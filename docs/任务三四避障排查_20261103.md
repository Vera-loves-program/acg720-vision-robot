# 任务三、四避障排查（2026-11-03）

> 本文为首轮排查证据。后续源码已补齐任务三的一米绕障和任务四显式转向保护，详见[最新修订状态](任务三四避障修订_20261103.md)。尚未完成 Gowin 布线验收或上板测试。

现场反馈：导航模式下，周围没有障碍仍显示 BLOCKED，底盘不动，或反复启停。

## 已复现并修正：碰撞保护的坐标转换错误

位置：`src/rplidar_c1.v`，`lidar_body_guard` 的 `ROT_APPLY` 状态。

顺序 CORDIC 每轮需要经过 `ROTATE → ROT_SHIFT → ROT_APPLY`，用上一轮更新的向量计算当前轮的移位操作数。原代码只增加 `iteration`，未返回 `ROTATE`，因此第 1～11 轮一直复用第 0 轮的操作数，坐标投影错误。

按当前工程的安装常量（雷达前向 90°，偏移 X=33 mm、Y=-77 mm）运行**原始 HDL**：

| 输入/结果 | 数值 |
| --- | --- |
| 原始角度 | 52/64° = 0.8125° |
| 测距 | 50 mm |
| 正确车体坐标，约 | (34, -27) mm，属于车体内部，应作为 SELF 丢弃 |
| 原代码投影坐标 | (63, -138) mm |
| 原代码碰撞标志 | `front_stop=1`、`turn_stop=1` |

这条回波会被误当成车体外障碍；前方覆盖有效时，导航保护会置状态 7（BLOCKED）并输出零轮速。错误投影还会影响 SELF 过滤、雷达显示、导航前视障碍判断，以及送往建图模块的点选择。建图模块本身另做坐标变换，不能把本次结果说成其变换算法也存在相同错误。

修复：非末轮更新 `iteration` 后返回 `ROTATE`，末轮再进入除法归一化。车体尺寸、安装参数、避障距离、工程文件和时序约束均未调整。

这证明源码存在能产生现场同类症状的故障；尚未读取实车雷达流或核验车上位流，不能据此断言现场只有这一种原因。

## 任务三仍有功能缺口：独立页面没有自主绕行

`src/robot_ui_control.v` 中 `page==2 && subpage==3` 的“前进”发送 `command=1`，双轮速度为 5，使用航向保持。

`src/robot_mission_control.v` 仅为 `command=3` 的目标点导航保持自主任务；`command=1` 不会因 BLOCKED 启动路径规划。导航给出的 `recommended_side` 也没有在这条链路中转成绕行动作。

因此当前任务三独立页面实现的是检测、减速、停车、障碍清除后续行。图示任务三要求的“自主绕障”不能由这个页面单独完成。任务四的 GOTO 才连接“停车 → 新地图积分 → 规划 → 路点续走”链路。本次没有新增任务三绕行状态机，也没有更改既有任务控制语义。

## 其他与现场复核有关的行为

- 导航 GOTO 对准目标时走车体旋转包络保护；显式 `command=2` 的 ±90°/180°陀螺仪旋转属于既有例外，会绕过雷达避障。不能把显式旋转演示当作 GOTO 转向保护测试。
- 地图规划仅允许已知 FREE；UNKNOWN 也会阻止规划。界面的 `START BLOCKED`、`GOAL BLOCKED`、`START UNKNOWN` 和导航状态 7 的阻挡提示应区分，不能统一归因为雷达停车距离。
- 当前安装外参、车体尺寸是 `robot_ui_control.v` 的固定常量；是否符合这台实车仍需测量确认。本次没有凭症状修改标定。

新增 `tests/tb_lidar_body_guard.v`，在本机 Vivado XSim 2018.3 中执行实际 `lidar_body_guard`、`robot_navigation` 和 `unsigned_divmod` RTL。

覆盖四种安装零角、多种距离和各角度，连续空地扫描夹杂车体回波、真实障碍的减速/停车/接触判定、侧向旋转保护、过期、处理溢出和恢复。导航测试没有接电机，也未闭环模拟真实运动、完整建图、BFS 绕行和终点到达。

运行方式：

```powershell
python tools/check_obstacle_hdl.py --xsim-bin C:/Xilinx/Vivado/2018.3/bin
```

同时通过现有离线检查：`check_lidar_body_guard`、`check_rplidar_protocol`、`check_navigation_tracking`、`check_robot_navigation_math`、`check_mission_lifecycle`、`check_realtime_route`、`check_mapping_recovery`、`check_lidar_grid_math`、`check_lidar_path_math`、`check_robot_integration`。这些历史脚本主要使用独立模型与源码约束，原代码也能通过其中相关检查，不能代替新增的实际 RTL 仿真。
