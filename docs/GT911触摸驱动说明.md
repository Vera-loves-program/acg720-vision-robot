# GT911 触摸输入与交互意图

本次新增 `src/gt911_touch.v` 和 `src/touch_gestures.v`。它们准备触摸坐标、双击选点、双指缩放和拍照请求；目标识别、跟踪算法、运动控制与照片写盘不在这两个模块中。

## 接线与当前验证范围

主任务已对照 ACG720-138&60K 通用板原理图第 1 页确认如下映射，新的触摸工程使用这张表。旧 `lcd1024_v2` 中 SDA 的 W21 约束是错误的；W21 在当前网口工程用于 `rgmii_txd[2]`，不能重复分配。

| 触摸信号 | 屏幕 FPC 脚 | FPGA 封装脚 |
|---|---:|---|
| TP_RST | 35 | Y21 |
| TP_SDA | 36 | **T20** |
| TP_SCL | 38 | T21 |
| TP_INT | 39 | P20 |

这里 TP_RST 是触摸控制器复位，与 FPC40 的 LCD RESET 区分。FPC37 不参与 GT911 I²C。SCL/SDA 采用输出低电平或高阻的开漏方式，需要模块上的 3.3 V 上拉；INT 选址后释放为输入，不启用内部上拉、下拉。

实体触摸尚未上板验证。模块代码已做静态检查，未运行 FPGA 编译或仿真。不能据此宣称多点触摸或跟踪已经成功。

## GT911 初始化和采样

驱动以 50 MHz 时钟运行，初始化不依赖 DDR 校准或网口就绪。RESET 保持低 20 ms，INT 选址建立 2 ms，RESET 拉高后保持选址电平 10 ms，再按 Linux 驱动做 INT 低电平同步 50 ms、释放后等待 50 ms。默认选择 7 位地址 `0x5D`，失败后完整复位并尝试 `0x14`。

读取 `0x8140..0x8149` 的产品 ID、固件区信息和坐标分辨率；只有产品前三字节为 ASCII `911` 且 X/Y 分辨率各为 2..4096 时，才允许进入坐标准备状态。随后仅向 `0x8040` 写命令 0，使控制器进入普通坐标报告模式。**旧代码称 `0x8040=2` 为软复位，但 Goodix 编程指南把命令 2 定义为 raw/diff 数据模式，本版不再写它。**

I²C 时钟约 50 kHz，SCL/SDA 都读取同步后的真实电平，支持时钟延展、从机 NACK、末字节主机 NACK 和 20 ms 事务超时。失败不会被伪造为 ACK，也不会阻塞摄像头显示。驱动约每 5 ms 开始一次状态查询，加上事务耗时后，实际触摸报告频率低于 200 Hz。

普通坐标状态位位于 `0x814E`。只有 bit7 为 1 时才读取坐标；读完且清状态的写事务成功后，才发布一帧坐标，包含最多两个接触点、ID 和归一化后的 LCD 坐标。多于两指时只使用前两个记录；大面积触摸、proximity 和无效坐标通过 `snapshot_cancel` 明确取消未完成手势，不当作正常抬手触发点击。I²C 故障取消当前手势并重新初始化。

标准 8 字节记录以 `0x814F` 的 ID 开头，其后为 X/Y 小端坐标。本版默认与 Linux `goodix.c` 的布局一致。部分 HotKnot 固件手册使用预留记录后移的布局，只有确认固件属于该类时才可把参数 `POINT_BASE` 调为 `0x8157`；本版不盲目猜测两种布局。

坐标不假定原生已经是 1024×600：使用控制器报告的实际分辨率，以逐周期除法换算成 X=0..1023、Y=0..599。`SWAP_XY`、`INVERT_X`、`INVERT_Y` 参数供确认方向后调整，不写屏幕固有配置区。

## 状态和故障码

`ack_seen` 表示曾有真实设备地址 ACK；`identified` 表示当前初始化识别到 GT911；`ready` 表示 ID、分辨率和普通报告命令通过。就绪不是触摸手势已经验证的含义。

| error_code | 含义 |
|---:|---|
| 0 | 当前事务正常 |
| 1 | 总线起始时不空闲，超时 |
| 2 | 事务或时钟延展超时 |
| 3 | 写设备地址未应答 |
| 4 | 寄存器地址或写数据未应答 |
| 5 | 内部状态异常 |
| 6 | 产品 ID 不符合 GT911 |
| 7 | 重复 START 后读地址未应答 |
| 8 | 控制器坐标分辨率无效 |
| 9 | 触摸数量、状态或坐标无效，已丢弃该帧 |

## 手势和 UI 区域

`touch_gestures` 运行在同一个 50 MHz 时钟域，输入是坐标快照。一次点击在手指释放时提交；按住不连续触发，持续超过 250 ms、移动超过 16 像素或出现多指时，不按单击处理。

| 区域 | LCD 范围，右/下端不包含 | 行为 |
|---|---|---|
| 视觉调试 | X=832..1007，Y=112..151 | 切换视觉调试状态 |
| 清除 | X=832..1007，Y=392..431 | 清除选点，恢复 1× 显示意图 |
| 拍照请求 | X=832..1007，Y=440..487 | 翻转 capture_toggle，请电脑端响应 |
| 摄像头区域 | X=16..815，Y=56..535 | 调试开启后可双击选点、双指缩放 |

双击需要两次短点击相隔不超过 350 ms、位置相差不超过 32 像素。输出的是相机原始 800×480 画面内的选点坐标，UI 应明确显示“已选点 / 待跟踪”，不假定该位置已被识别为人物。

双指缩放使用接触点 ID 检查和曼哈顿距离比较，距离变化需超过 25% 且 32 像素，输出 1×/2× 的显示意图及 `zoom_toggle`。本次保持已工作的 LCD DDR 顺序读取和 800×480 画面；电脑接收端可响应意图做真实显示缩放，LCD 侧先显示状态。图片采集始终保存收到的原始 FPGA 处理帧，不应把仅供观看的放大图当成训练样本。

`selection_toggle`、`zoom_toggle`、`capture_toggle`、`clear_toggle` 和相应稳定数据由顶层用握手或稳定数据邮箱跨时钟，不能直接拿单周期脉冲跨到 LCD 时钟。`debug_toggle_pulse`、`clear_pulse`、`zoom_reset_pulse` 可接经过同步的上位机控制；最后一个仅重置缩放，不清除选点。拍照是请求，必须由真正写盘的一端返回结果，不能只改变状态标签就显示“保存成功”。
