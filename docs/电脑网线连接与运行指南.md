## 1. 网线怎么接

用普通 Cat5e（超五类）或 Cat6（六类）网线，两端都有 RJ45 插头：

```text
OV5640 → ACG720 FPGA 开发板
                 │ RJ45 网口
                 │ 普通网线
                 │ RJ45 网口
              你的电脑
```

1. FPGA 保持供电，LCD 应继续显示摄像头画面。
2. 网线一端插入 FPGA 板上 RJ45，另一端插电脑有线口，插到卡扣扣住。
3. 保持电脑 Wi-Fi 联网，下载软件走 Wi-Fi，有线口与 FPGA 通信。
4. 当前 FPGA 代码使用千兆通路，电脑链路应为 **1 Gbps**。这条直连线不提供 Internet，“未识别网络 / 无 Internet”本身可以是正常现象。

不需要路由器。烧录器仍负责烧录，网线负责图像数据。

## 2. 核对 Windows 有线地址

### 2.1 打开普通 PowerShell

如果现在看到 `Vera@...$`，先在 **WSL** 输入：

```bash
exit
```

回到 `PS ...>` 就是 PowerShell。如果窗口关闭，按 Windows 键搜索 `Windows PowerShell`，直接打开。

在 **普通 Windows PowerShell** 输入：

```powershell
Get-NetAdapter -Physical | Format-Table Name,Status,LinkSpeed
Get-NetIPAddress -InterfaceAlias "以太网" -AddressFamily IPv4 | Format-Table IPAddress,PrefixLength
```

`以太网` 应为 Up、1 Gbps；IPv4 应为 `192.168.10.3`、PrefixLength 为 `24`。你目前已经符合，可以直接进入第 3 节。

### 2.2 只有地址不对时才修改

1. 按 **Win + R**，输入 `ncpa.cpl`，回车。
2. 找到 **以太网**。不要改 WLAN、Radmin VPN 或 `vEthernet (WSL...)`。
3. 右键 → 属性 → 选中“Internet 协议版本 4（TCP/IPv4）” → 属性。
4. 选择“使用下面的 IP 地址”，填写下表。
5. 点击确定，关闭窗口，再执行 2.1 的核对命令。

| 项目 | 填入 |
| --- | --- |
| IP 地址 | `192.168.10.3` |
| 子网掩码 | `255.255.255.0` |
| 默认网关 | 留空 |
| 首选/备用 DNS | 留空 |

FPGA 的 `192.168.10.2` 已写在代码里。不要把 `192.168.10.3` 手动加到 WSL 虚拟网卡上。

## 3. 将 WSL 从 NAT 改为镜像网络

FPGA 将视频发到电脑有线地址 `192.168.10.3:6102`，而你当前 NAT 模式的 WSL 是另一个 `172.28...` 地址。只启动 WSL 接收程序，并不会自动转发这条入站 UDP 流。

我们使用镜像网络接入局域网。模式条件与方法见 [微软 WSL 网络文档](https://learn.microsoft.com/en-us/windows/wsl/networking)。你的 Windows 构建号为 26200、WSL 2.7.13，可按此路线配置。

### 3.1 编辑配置

在 **普通 Windows PowerShell** 输入：

```powershell
notepad "$env:USERPROFILE\.wslconfig"
```

这会定位到 Windows 用户目录，不是在 `system32` 建文件。如果记事本提示是否创建文件，选择“是”。空文件完整填入：

```ini
[wsl2]
networkingMode=mirrored
firewall=true
dnsTunneling=true
```

已有内容时保留原内容，在原来的 `[wsl2]` 部分修改/增加这三项，不要重复两个 `[wsl2]`；尤其要改掉原 `networkingMode=nat`。

按 **Ctrl + S** 保存，关闭记事本。如果出现“另存为”，目录选 `C:\Users\Vera`，文件名 `.wslconfig`，保存类型选“所有文件”，不要保存成 `.wslconfig.txt`。

在 **PowerShell** 核对：

```powershell
Get-Content "$env:USERPROFILE\.wslconfig"
```

应看到 `networkingMode=mirrored`。文件位置及字段说明见 [微软 WSL 配置文档](https://learn.microsoft.com/en-us/windows/wsl/wsl-config)。

### 3.2 重启 WSL 使配置生效

先保存 WSL/VS Code 未保存的工作，停止正在运行的 WSL 程序。shutdown 会停止所有 WSL 发行版，不会删除文件。

在 **普通 Windows PowerShell** 输入：

```powershell
wsl --shutdown
wsl -d Ubuntu-22.04
```

第二条明确进入你已有 Python 的 Ubuntu-22.04，避免误进另一套名为 Ubuntu 的系统。提示符变成 `Vera@...$` 后，在 **WSL** 输入：

```bash
wslinfo --networking-mode
```

正确结果应是 `mirrored`。若仍是 `nat`，先不要运行接收器，检查文件位置、是否多了 `.txt`、是否保存并执行了 shutdown。若提示找不到 wslinfo，保留错误，不要安装一个同名 Linux 包。

## 4. 放行 Windows 与 WSL 的 UDP 6102

本节是 Windows 网络配置，**不能在 WSL 的 `$` 提示符后执行**。

### 4.1 打开管理员 PowerShell

1. 保留刚才的 WSL 窗口。
2. 按 Windows 键，搜索 `Windows PowerShell`。
3. 右键 → **以管理员身份运行**。
4. 用户账户控制询问是否允许时点“是”。新窗口标题应有“管理员”。

它开在 `C:\Windows\system32` 很常见。本节只运行下面的网络命令，不在这里创建 Python 环境。

### 4.2 添加两条入站规则

在 **管理员 Windows PowerShell** 执行下面两个完整代码块。每个 if 块整体复制；已有同名规则时跳过创建。

Windows 防火墙：

```powershell
if (-not (Get-NetFirewallRule -Name "ACG720-FPGA-UDP6102" -ErrorAction SilentlyContinue)) {
    New-NetFirewallRule -Name "ACG720-FPGA-UDP6102" -DisplayName "ACG720 FPGA Video UDP6102" -Direction Inbound -Action Allow -Protocol UDP -LocalPort 6102 -RemoteAddress 192.168.10.2 -Profile Any
}
```

WSL Hyper-V 防火墙：

```powershell
if (-not (Get-NetFirewallHyperVRule -Name "ACG720Video6102" -ErrorAction SilentlyContinue)) {
    New-NetFirewallHyperVRule -Name "ACG720Video6102" -DisplayName "ACG720 WSL Video UDP6102" -Direction Inbound -Action Allow -VMCreatorId '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' -Protocol UDP -LocalPorts 6102 -RemoteAddresses 192.168.10.2
}
```

规则放行 FPGA 源地址发到 UDP 6102 的数据。WSL 标识与 Hyper-V 规则方法来自 [微软 WSL 网络文档](https://learn.microsoft.com/en-us/windows/wsl/networking)，参数见 [Hyper-V 防火墙规则文档](https://learn.microsoft.com/en-us/powershell/module/netsecurity/new-netfirewallhypervrule)。

创建成功可能显示属性列表；已存在时可以没有新输出。继续检查：

```powershell
Get-NetFirewallRule -Name "ACG720-FPGA-UDP6102" | Format-List DisplayName,Enabled,Direction,Action
Get-NetFirewallHyperVRule -Name "ACG720Video6102" | Format-List Name,Direction,Action,LocalPorts,RemoteAddresses
```

应看到 Inbound、Allow，Hyper-V 的 LocalPorts 包含 6102。如果“拒绝访问”，重新打开管理员 PowerShell；如果命令不存在，保存完整错误。完成后可关闭管理员窗口，回到 WSL。无需关闭整个防火墙。

## 5. 在 WSL 进入项目，先运行收包器

### 5.1 进入正确目录

确认看到 `Vera@...$`；若只有 PowerShell，先执行 `wsl -d Ubuntu-22.04`。

在 **WSL** 逐条运行：

```bash
cd /mnt/d/GOWIN_PROJECTS/acg720_vision_robot
pwd
ls pc/udp_probe.py pc/udp_video_viewer.py pc/requirements.txt
python3 --version
```

pwd 必须显示 `/mnt/d/GOWIN_PROJECTS/acg720_vision_robot`，ls 应列出三个文件，Python 应为 3.10.12 或其他可用的 3.10 以上版本。

Windows 的 `D:\...` 在 WSL 写成 `/mnt/d/...`，使用正斜杠。如果 cd 报错，先处理目录问题，不要继续在 system32 运行。

### 5.2 测试 10 秒入站视频包

先关闭其他 probe/视频接收程序，每次只有一个程序占用 UDP 6102。这个工具只使用 Python 自带库，不需要 OpenCV。

在 **WSL 项目目录**运行：

```bash
python3 pc/udp_probe.py --bind 0.0.0.0 --seconds 10
```

`0.0.0.0` 表示监听 WSL 所有本地 IPv4 接口，不是要把网卡地址改成它。FPGA 目标仍是 `192.168.10.3`。

程序先显示 Listening，等待约 10 秒后输出统计、自动退出。第一次从帧中间开始接收时，开头的部分行可以被丢弃。重点看：

| 输出 | 正常判据 |
| --- | --- |
| `Packets received` | 大于 0 |
| `Sources` | 包含 `192.168.10.2` |
| `UDP payload lengths` | 图像包长 **802** 字节 |
| `Complete frames` | 大于 0 |
| `PASS: complete video frames reached this computer.` | 已有完整视频帧到达 WSL |

PARTIAL 表示收到视频行但没拼成完整帧；NO VIDEO 表示未识别到有效视频流。保存完整输出，按第 9 节排查。不要靠反复安装 OpenCV 解决零收包：probe 不依赖它。

## 6. 补齐 WSL 视频环境，使用阿里源

你的 Python 已安装，但项目虚拟环境缺 pip。本节补齐系统组件和该环境；保持 Wi-Fi 能上网。下面全在 **WSL** 执行。

### 6.1 安装 Ubuntu 系统组件

先完整复制下段，包括最后的 EOF。它只创建临时源，不覆盖现有系统源：

```bash
cat > /tmp/acg720-aliyun-jammy.list <<'EOF'
deb https://mirrors.aliyun.com/ubuntu/ jammy main restricted universe multiverse
deb https://mirrors.aliyun.com/ubuntu/ jammy-updates main restricted universe multiverse
deb https://mirrors.aliyun.com/ubuntu/ jammy-security main restricted universe multiverse
deb https://mirrors.aliyun.com/ubuntu/ jammy-backports main restricted universe multiverse
EOF
```

接着逐条执行：

```bash
sudo apt-get -o Dir::Etc::sourcelist=/tmp/acg720-aliyun-jammy.list -o Dir::Etc::sourceparts=- update
sudo apt-get -o Dir::Etc::sourcelist=/tmp/acg720-aliyun-jammy.list -o Dir::Etc::sourceparts=- install python3-venv python3-pip libgl1 libglib2.0-0
```

sudo 提示密码时输入 **Ubuntu 用户 Vera 的密码**并回车，输入时看不到字符或星号是正常现象。询问 `Do you want to continue? [Y/n]` 时输入 y 回车。

已确认系统是 Ubuntu 22.04，因此使用 jammy；镜像说明见 [阿里 Ubuntu 镜像](https://developer.aliyun.com/mirror/ubuntu)。apt 报错时先保存完整错误，不要假定组件已经安装成功。

### 6.2 完成 Linux 虚拟环境

在 **WSL** 逐条运行：

```bash
cd /mnt/d/GOWIN_PROJECTS/acg720_vision_robot
mkdir -p ~/.venvs
python3 -m venv ~/.venvs/acg720-vision
~/.venvs/acg720-vision/bin/python -m pip --version
```

`~` 表示 `/home/Vera`。环境实际在 `/home/Vera/.venvs/acg720-vision`，不是 Windows 的 `.venv\Scripts`。

该目录此前是不完整环境；安装 python3-venv 后再执行 venv 命令，用于补齐它。最后一行应显示 pip 版本，路径位于该环境下。若仍是 `No module named pip` 或 ensurepip 失败，停止并保存错误。

### 6.3 安装 OpenCV 与 NumPy

在 **WSL 项目目录**执行，等待安装完成：

```bash
~/.venvs/acg720-vision/bin/python -m pip install -i https://mirrors.aliyun.com/pypi/simple/ -r pc/requirements.txt
```

再检查：

```bash
~/.venvs/acg720-vision/bin/python -c "import cv2, numpy; print('Dependencies OK'); print('OpenCV:', cv2.__version__); print('NumPy:', numpy.__version__)"
```

看到 Dependencies OK 和两个版本号才表示可用。阿里 Ubuntu 源提供系统组件，阿里 PyPI 源提供 Python 包，是两套安装来源。

本指南直接调用环境内 Python，不要求 activate，也不需要 sudo pip install。以后用同一个解释器安装和运行，避免装在一个环境、运行在另一个环境；方法见 [Python 虚拟环境安装指南](https://packaging.python.org/en/latest/guides/installing-using-pip-and-virtual-environments/)。

## 7. 在 WSL 打开视频窗口

### 7.1 核对图形环境

在 **WSL** 执行：

```bash
echo "$DISPLAY"
echo "$WAYLAND_DISPLAY"
ls -d /mnt/wslg
```

你电脑检查时分别有 `:0`、`wayland-0` 和 `/mnt/wslg`。它们是图形环境的迹象，不等于已验证 OpenCV 窗口。WSLg 条件见 [微软 Linux GUI 文档](https://learn.microsoft.com/en-us/windows/wsl/tutorials/gui-apps)。

### 7.2 启动

确认 probe 已退出，在 **WSL** 执行：

```bash
cd /mnt/d/GOWIN_PROJECTS/acg720_vision_robot
~/.venvs/acg720-vision/bin/python pc/udp_video_viewer.py --bind 0.0.0.0
```

Windows 桌面应弹出 `VERA Vision Lab - FPGA UDP Viewer`。未收到完整帧时显示 WAITING，完整帧到达后显示画面和统计。

网络传输是 **400×240 RGB565**，窗口将它放大显示；LCD 是 800×480，所以电脑细节不同是当前降采样设计的结果。

若 probe 的行头统计主要为 little，退出视频程序后用：

```bash
~/.venvs/acg720-vision/bin/python pc/udp_video_viewer.py --bind 0.0.0.0 --row-byte-order little --byte-order little
```

仅像素字节顺序/颜色异常、行头正常时才单独试 `--byte-order little`。完全零收包时改变字节序没有作用。

退出：点击视频窗口按 Q 或 Esc；也可回到运行程序的终端按 Ctrl + C。

## 8. 测试电脑 → FPGA 的控制

点击视频窗口获取键盘焦点，切到英文输入后按键：

| 键 | 观察 FPGA LCD |
| --- | --- |
| D | 中央出现/消失橙色十字线，最好辨认 |
| F | GAUSS ON/OFF 切换，帧边界生效 |
| E | STOP LATCH 与红色状态条 |
| R | 清除停止状态 |
| Q / Esc | 退出电脑窗口 |

终端的 Sent opcode 日志只表示电脑执行发送；LCD 的变化才说明 FPGA 收到并执行。当前没有命令应答协议。

S4 也能切换滤波，电脑 F 状态不会自动跟随 S4，混用时以 LCD 为准。E 目前仅锁存状态，尚未连接电机制动。

控制目的为 `192.168.10.255:5001`，不同于视频接收端口 6102。若视频正常、控制无效，在另一个 **WSL** 终端执行：

```bash
ip route get 192.168.10.255
```

应走具有 `192.168.10.3` 源地址的有线接口；若走 VPN/其他接口，保留输出，不要先猜测并删除路由。

## 9. 出错时怎么定位

### 9.1 命令与环境错误

| 现象 | 下一步 |
| --- | --- |
| 仍在 `/mnt/c/Windows/system32` | WSL 执行第 5 节 cd 命令进入项目 |
| py / python / Scripts 路径找不到 | WSL 用 python3；环境解释器用 `~/.venvs/acg720-vision/bin/python` |
| system32/.venv 权限错误 | 按第 6 节在 Linux 用户目录建环境，不要 sudo 强行在系统目录建 |
| No module named pip / ensurepip 错误 | 完成 6.1，再重新执行 6.2 |
| No module named cv2/numpy | 同一个虚拟环境解释器安装和运行 |
| 找不到 requirements.txt | pwd 核对项目，ls 确认 pc/requirements.txt 存在 |
| Address already in use | 6102 被占用，关闭另一侧或另一个接收程序 |
| pip 代理连接失败、拒绝连接、DNS 错误 | 保存错误；这是下载联网问题，不代表 FPGA 链路坏了 |

### 9.2 probe 零收包

按顺序检查：

1. LCD 摄像头正常，D5/PHY 状态完成初始化。D5 不等于网线已协商成功。
2. Windows 以太网 Up、1 Gbps、192.168.10.3/24。
3. WSL 网络模式 **mirrored**。
4. 两条防火墙规则 Inbound/Allow。
5. 只有一个接收器，在 WSL 使用 `--bind 0.0.0.0`。

曾启用 Ubuntu UFW 时，在 **WSL** 查看：

```bash
sudo ufw status
```

仅 Status 为 active 时添加：

```bash
sudo ufw allow from 192.168.10.2 to any port 6102 proto udp
```

UFW 不存在或 inactive 时无需为本项目启用它。

仍无包时可用 [Wireshark 官方软件](https://www.wireshark.org/)捕获 **Windows 的以太网接口**。首次安装保留 Npcap 组件，打开后双击以太网，在“显示过滤器”填入下列内容并回车：

```text
udp.dstport == 6102
```

观察源 IP 192.168.10.2、目的 IP 192.168.10.3 的包：

- Wireshark 有包而 WSL 没有：查镜像模式、防火墙、监听进程。
- Wireshark 也没有：查 FPGA 发送、PHY、网线；LCD 正常不能单独证明网口正常。
- 802 字节包到达但完整帧为 0：保存行号/字节序/坏包统计，再查格式、丢包、FIFO。

当前 FPGA 未实现 ARP/ICMP 应答，**ping 失败不能判定视频链路失败**。Test-NetConnection 的 Port 检查是 TCP，也不能验证这里的 UDP。

### 9.3 probe PASS，但图形窗口失败

先保留终端完整错误，问题已转到图形环境：

- 缺 libGL.so.1 / libgthread-2.0.so.0：核对 6.1 的 libgl1、libglib2.0-0 是否成功安装。
- DISPLAY 为空、无法连接显示或 Qt/xcb 插件错误：检查是否进入 Ubuntu-22.04、/mnt/wslg 是否存在，提供完整错误。不要照搬旧教程把 DISPLAY 改成 NAT 网关 IP。
- 若需更新 WSL，在管理员 PowerShell 用 `wsl --update`，保存工作后 shutdown，再进入。当前已安装较新 WSL，不要求先重复更新。

### 9.4 遇到问题时提供这五项

1. Windows 2.1 节的网卡与 IP 输出。
2. WSL 的 `wslinfo --networking-mode`。
3. WSL 的 pwd、python3 --version。
4. probe 10 秒后的完整输出。
5. 视频程序若报错，提供完整错误文字。

## 10. 以后每次开机怎么运行

地址、镜像网络、防火墙和环境完成后，无需每次重新安装。

**普通 Windows PowerShell：**

```powershell
wsl -d Ubuntu-22.04
```

**进入 WSL 后：**

```bash
cd /mnt/d/GOWIN_PROJECTS/acg720_vision_robot
~/.venvs/acg720-vision/bin/python pc/udp_video_viewer.py --bind 0.0.0.0
```

只检查收包时，退出视频程序再用：

```bash
python3 pc/udp_probe.py --bind 0.0.0.0 --seconds 10
```

以后同一个有线口接路由器上网时，在第 2 节界面把 IPv4 和 DNS 改回自动获得；重新直连 FPGA 时设回 192.168.10.3/24。

## 11. 可选：VS Code 中运行

先完成直接终端测试，再引入 VS Code。在 WSL 项目目录执行 `code .`，确认左下角连接到 `WSL: Ubuntu-22.04`，从“终端 → 新建终端”打开 Linux 终端，使用第 10 节命令。

若 code 找不到或未连接 WSL，可在 Windows VS Code 的扩展面板安装微软 **WSL** 扩展，通过左下角远程连接菜单连接 Ubuntu-22.04，再打开 `/mnt/d/GOWIN_PROJECTS/acg720_vision_robot`。方法见 [微软 VS Code WSL 文档](https://code.visualstudio.com/docs/remote/wsl)。

PowerShell 与 WSL 终端外观相近，最终以提示符和 pwd 实际路径为准。
