# ACG720 摄像头画面传到电脑：从插网线到显示画面

当前工程：`D:\GOWIN_PROJECTS\acg720_vision_robot\vision_robot_netfix.gprj`。

你已再次验证旧工程摄像头正常，新工程曾出现 DDR 未就绪。先按 [网口集成检查与 R2 修正版](网口集成检查与R2修正版.md) 编译、烧录并确认摄像头恢复，再测试 FPGA 网口发送和电脑接收；LCD 显示成功还不能证明网络已通。本指南先使用 Windows 原生 Python，后面附有 WSL 路线，两种环境运行的是同一份接收程序。

## 1. 字体问题已经修正

照片中的文字上下颠倒，原因是我写错了字库行位序。每个字形由五个字节表示五列，每列的 bit 0 是最上面的像素；原代码却从 bit 7 向下取像素，还跳过了最下面一行。

`src\lcd1024_vision_ui.v` 已改为：

```verilog
font[32-(glyph_x*8)+glyph_y]
```

在 Gowin 中打开上述工程，重新运行 Synthesize 和 Place & Route，并在 Programmer 选择本次生成的 `impl\pnr\vision_robot_netfix.fs` 再烧录。字体方向修正已由用户确认，R2 的 DDR 与流水线修正仍待上板验证；本版标题为 `VERA NET FIX R2`，右栏为 `SYSTEM`、`PIPELINE`、`CONTROLS` 等。

R2 沿用原来的 802 字节视频 UDP 格式，电脑接收程序无需随本轮修复更改。

## 2. 网线怎么接

准备一根普通的 **Cat5e（超五类）或 Cat6（六类）网线**，两头都是带塑料卡扣的 RJ45 水晶头。不要购买电话线。

```text
OV5640 → FPGA 开发板上的 RJ45 网口
                      │
                 普通网线一根
                      │
                电脑上的 RJ45 网口
```

一端插入 ACG720 开发板网口，另一端插入电脑网口，插到卡扣扣住即可。两端可以互换，不用旋转接线、不用拆开水晶头，也不用手工制作交叉网线。板上 RTL8211E/EG PHY 支持自动交叉检测与纠正，见 [Realtek 原厂数据手册](https://datasheet.lcsc.com/lcsc/1810010421_Realtek-Semicon-RTL8211E-VB-CG_C90735.pdf)。

FPGA 仍需要原来的电源，烧录仍使用原来的下载器。网线负责传数据。本次直连不需要路由器，也不需要外网；电脑可以继续用 Wi-Fi 上网。拔线时按住卡扣再拔。

目前发送逻辑使用固定 125 MHz 的 GMII/RGMII 千兆数据通路，没有实现 10/100 Mbps 速率切换。因此请优先确认电脑与开发板协商到 **1.0 Gbps / 1000 Mbps**。只有 100 Mbps 的网口或交换机不适合测试这个版本。

## 3. 设置电脑的有线网卡 IPv4

这两个地址已经写在 FPGA 代码中，电脑要使用配套地址：

| 项目 | 值 |
| --- | --- |
| FPGA | `192.168.10.2` |
| 电脑有线网口 | `192.168.10.3` |
| 子网掩码 | `255.255.255.0` |
| 默认网关 | 留空 |
| DNS | 留空 |
| 接收视频端口 | UDP `6102` |

按下面操作：

1. 按键盘 **Win + R**，输入 `ncpa.cpl`，按回车。
2. 找到 **以太网 / Ethernet**。如果有多个有线网卡，可以拔插刚才的网线，看哪个条目的“网络电缆被拔出”状态随之变化。不要修改 Wi-Fi，也不要修改 `vEthernet (WSL)`。
3. 右键这个有线网卡 → **属性**。
4. 选中 **Internet 协议版本 4 (TCP/IPv4)** → **属性**。
5. 选择“使用下面的 IP 地址”，填入上表的 IP 和子网掩码；网关、DNS 留空。
6. 点击确定，关闭属性窗口。
7. 再双击该有线网卡，查看“速度”：本版本测试目标是 **1.0 Gbps**。

Windows 的手动 IPv4 设置也可从设置应用的以太网页面完成，见 [微软官方说明](https://support.microsoft.com/en-us/windows/experience/connectivity-networking/essential-network-settings-and-tasks-in-windows)。这里使用 `ncpa.cpl` 是为了明确找到有线网卡并保留空网关。

开发板没有运行 DHCP 服务器，所以保持“自动获得 IP”时电脑可能获得 `169.254.x.x`，无法按这个工程配置接收图像。“无 Internet / 未识别网络”本身是正常的：这条线连接的是 FPGA，不是上网路由器。

## 4. 打开正确的电脑终端

本节的命令全部在 **Windows PowerShell** 中运行。你可以：

1. 打开 VS Code → 文件 → 打开文件夹 → 选择 `D:\GOWIN_PROJECTS\acg720_vision_robot`。
2. 菜单“终端”→“新建终端”，在终端右上角下拉菜单选择 **PowerShell**。
3. 或者直接打开 Windows 开始菜单中的 PowerShell。

先输入：

```powershell
Set-Location D:\GOWIN_PROJECTS\acg720_vision_robot
ipconfig
```

在输出的“以太网适配器”下面确认 `IPv4 地址` 是 `192.168.10.3`，子网掩码是 `255.255.255.0`。

还可以输入：

```powershell
Get-NetAdapter -Physical | Format-Table Name, Status, LinkSpeed
```

找到刚才的有线网卡：`Status` 应为 `Up`，`LinkSpeed` 应为 `1 Gbps`。网口灯通常也会有反应，但不同硬件灯色含义不同，以网卡状态和收包结果为准。

**不要以 `ping 192.168.10.2` 失败判断 FPGA 坏了。** 当前代码实现了视频 UDP 和控制 UDP，没有实现 ARP 应答或 ICMP ping 应答；即使视频能收到，ping 也可能失败。`Test-NetConnection -Port 6102` 测的是 TCP，也不适用这个 UDP 视频端口。

## 5. Windows 安装 Python 和依赖

先试：

```powershell
py -3 --version
```

如果出现 `Python 3.10` 或更高版本，可以继续。如果找不到 `py`，再试 `python --version`。如果两者都找不到，或 `python` 只打开商店，请先从 [Python 官方 Windows 下载页](https://www.python.org/downloads/windows/)安装 64 位 Python，例如 3.13 的稳定版；已有可用的 3.10 以上版本时不用重复安装。经典安装器中可以勾选 `Add python.exe to PATH`。安装后重新打开 PowerShell。

在项目目录运行以下命令，每条单独执行：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -i https://mirrors.aliyun.com/pypi/simple/ -r .\pc\requirements.txt
.\.venv\Scripts\python.exe -c "import cv2, numpy; print('Dependencies OK')"
```

若你只能使用 `python`，把**第一条**的 `py -3` 换成 `python`，其余命令原样执行。

看到 `Dependencies OK` 表示依赖安装完成。下载依赖时电脑需要能上网，通常保持 Wi-Fi 连接即可。这里直接调用虚拟环境内的 Python，无需执行 `Activate.ps1`，因此也无需为此修改 PowerShell 执行策略。虚拟环境做法见 [Python 官方安装指南](https://packaging.python.org/en/latest/guides/installing-using-pip-and-virtual-environments/)。

## 6. 为视频接收放行防火墙

通过开始菜单搜索 PowerShell，右键 **以管理员身份运行**，执行下面的窄范围入站规则：

```powershell
New-NetFirewallRule -DisplayName "ACG720 FPGA Video UDP6102" -Direction Inbound -Action Allow -Protocol UDP -LocalPort 6102 -RemoteAddress 192.168.10.2 -Profile Any
```

这条规则仅允许源地址 `192.168.10.2` 发送到电脑的 UDP 6102；不需要关闭整个防火墙。创建一次即可。普通接收程序不要求管理员权限，可以回到之前的普通 PowerShell 运行。

以后不再使用时，可在管理员 PowerShell 删除该规则：

```powershell
Remove-NetFirewallRule -DisplayName "ACG720 FPGA Video UDP6102"
```

## 7. 先用检查工具确认收到了视频包

在普通 PowerShell、项目目录中运行：

```powershell
.\.venv\Scripts\python.exe .\pc\udp_probe.py --bind 192.168.10.3 --seconds 10
```

先关闭其他接收窗口，每次只运行一个接收程序。这个检查工具只使用 Python 自带库，不依赖 OpenCV。等待约 10 秒，正常输出类似：

```text
Packets received: 72000
Sources: {'192.168.10.2': 72000}
UDP payload lengths: {802: 72000}
Valid video rows: 72000; bad packets: 0; other sources: 0
Complete frames: 300; incomplete frames: 0
Row header byte order votes: {'big': 71700}
PASS: complete video frames reached this computer.
```

上面的数量只是举例，实际数量取决于摄像头帧率和测试时间。重点看：源地址是 `192.168.10.2`，UDP 载荷长度是 **802**，`Complete frames` 大于 0。

- `PASS`：FPGA 的视频数据已到达电脑，可以打开视频窗口。
- `PARTIAL`：已收到视频行，但这次检查没拼出完整帧，后续需要检查丢包或包顺序。
- `Packets received: 0`：没有收到包，按第 10 节排查。
- `BIND FAILED`：电脑 IP 没设对，或另一个程序占用了 6102。

若输出中主要是 `little` 行头字节序，工具会提示在视频程序中使用两个 `little` 选项；这能处理宽度转换 FIFO 输出字节顺序与预期不同的情况。

## 8. 打开电脑上的视频窗口

收包检查结束后运行：

```powershell
.\.venv\Scripts\python.exe .\pc\udp_video_viewer.py --bind 192.168.10.3
```

你应该看到 `VERA Vision Lab - FPGA UDP Viewer` 窗口。网络实际传输 **400×240 RGB565**，电脑把它放大到 800×480 显示。LCD 继续显示 800×480 摄像头原尺寸画面。因此电脑端精细程度会比 LCD 低一些，这是目前 FPGA 隔行隔列取样的结果。

如果检查工具提示行头是小端：

```powershell
.\.venv\Scripts\python.exe .\pc\udp_video_viewer.py --bind 192.168.10.3 --row-byte-order little --byte-order little
```

如果行头正常、只出现像素颜色异常，可以仅尝试 `--byte-order little`。不要通过改变字节序去解决完全没有收包的问题。

为了减少以后输入命令的次数，我还提供了 `pc\run_windows.cmd`：

- 在资源管理器双击它，可创建本项目虚拟环境、在缺少依赖时安装依赖，然后打开视频窗口。
- 在 PowerShell 中执行 `.\pc\run_windows.cmd probe`，可运行 10 秒收包检查。
- 它需要 Windows 已安装 Python，不会自动改电脑 IP 或防火墙。

## 9. 测试电脑 → FPGA 的反向通信

**先点击视频窗口，使它获得键盘焦点**。按下面的键，观察开发板的 LCD：

| 按键 | 应看到的结果 |
| --- | --- |
| `D` | LCD 摄像头画面中央出现/消失橙色十字线，这是最好辨认的反向控制测试 |
| `F` | LCD 右栏 `GAUSS ON/OFF` 改变，高斯滤波在摄像头帧边界切换 |
| `E` | LCD 右栏出现 `STOP LATCH` 状态和红色状态条 |
| `R` | 清除上述停止状态 |
| `Q` 或 Esc | 退出电脑视频窗口 |

控制包发送到 `192.168.10.255:5001`。如果 `D` 能改变 LCD，说明电脑到 FPGA 的命令也生效。终端的 `Sent opcode=...` 只表示电脑发送了命令；目前没有命令应答协议，应以 LCD 的变化确认执行。

S4 也能切换高斯滤波。电脑的 F 状态目前不会自动跟随 S4 按键，混用时以 LCD 状态为准。`E` 现在仅锁存界面/协议状态，项目尚未接入电机，因此它还不具备实际电机制动功能。

## 10. 不成功时按现象排查

| 现象 | 先做什么 |
| --- | --- |
| 网卡显示网线已拔出 / `Disconnected` | 检查插紧、开发板供电，换一根完整 Cat5e/Cat6 线，确认插的是开发板 RJ45 |
| 链路只有 100 Mbps | 查看电脑网卡是否千兆；保持速度设置“自动协商”；换一根八芯线；当前 FPGA 数据通路按千兆设计 |
| `WinError 10049` | 电脑有线网卡还没有 `192.168.10.3`，检查 `ipconfig`，不要把该 IP 配到 Wi-Fi 或 WSL 虚拟网卡 |
| `WinError 10048` | 关闭另一个 probe/视频程序；每次只开一个接收器 |
| 1 Gbps、IP 正确，但 10 秒内零收包 | 核对防火墙规则；查看 FPGA D5/`PHY INIT`；确认烧录的是新网络工程；记录网卡状态和检查工具输出 |
| D5 亮，但零收包 | D5 只表示 PHY 寄存器初始化流程完成，不等于已经协商成功或发出正确以太网帧 |
| 有 802 字节包，完整帧为 0 | 看行头 `big/little` 统计；若已收到正确行号却仍不能完整拼帧，需要进一步查丢包、FIFO 或包格式 |
| `No module named cv2/numpy` | 使用 `.venv\Scripts\python.exe` 运行，并用同一个解释器安装 `pc\requirements.txt` |
| 视频窗口停在 WAITING | 先退出视频程序，再运行 probe 区分无包、错误包、残帧；Wi-Fi 与有线口都在 `192.168.10.x` 时还要检查地址/路由冲突 |
| 收到画面，但 D 键不改变 LCD | 确认点击了视频窗口、终端出现发送日志；检查广播发往正确有线网卡；当前 FPGA RX 链路还需要实板验证 |

如果 Python 零收包，但链路和 IP 都对，可以使用 [Wireshark 官方软件](https://www.wireshark.org/)捕获**有线网卡**，显示过滤器为：

```text
udp.dstport == 6102
```

能在 Wireshark 看到源 IP `192.168.10.2`、目的 IP `192.168.10.3` 的 UDP 包而 Python 看不到，重点查防火墙和绑定地址；如果完全没有这些包，重点查 FPGA 发送通路、PHY 和网线。此时无需反复改变 LCD 的引脚或时序。

## 11. 如果你希望在 WSL 中运行

先完成前面的插线和 **Windows 有线网卡 IPv4 设置**。WSL 与 Windows 原生 Python 可以任选其一，先关掉另一侧的接收程序。

WSL2 默认 NAT 网络通常不能直接收到 FPGA 发给 Windows 有线 IP 的入站 UDP；本指南使用 Windows 11 22H2 及以上提供的镜像网络。微软官方说明见 [WSL 网络文档](https://learn.microsoft.com/en-us/windows/wsl/networking)。如果系统版本或 WSL 不支持镜像网络，先使用前面的 Windows 路线。

在 **Windows PowerShell** 查看：

```powershell
wsl --version
wsl -l -v
winver
```

确认使用的是 WSL2。用下面命令打开配置文件：

```powershell
notepad "$env:USERPROFILE\.wslconfig"
```

若已有配置，请保留原内容，在已有的 `[wsl2]` 节下增加或修改这一项，不要重复建立同名节：

```ini
[wsl2]
networkingMode=mirrored
```

保存后，先保存 WSL/VS Code 中的工作，再在 Windows PowerShell 执行以下命令。它会停止正在运行的 WSL 实例：

```powershell
wsl --shutdown
wsl
```

在 **管理员 Windows PowerShell** 中为 WSL 的 UDP 视频端口单独放行：

```powershell
New-NetFirewallHyperVRule -Name "ACG720Video6102" -DisplayName "ACG720 WSL Video UDP6102" -Direction Inbound -VMCreatorId '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' -Protocol UDP -LocalPorts 6102
```

这是微软文档中 Hyper-V 入站规则方法的 UDP 6102 版本，不需要将所有入站流量统一放行。前面的 Windows 源地址限定规则也保留。

下面的命令开始在 **WSL 的 Linux 终端** 运行，不能贴到 PowerShell：

```bash
cd /mnt/d/GOWIN_PROJECTS/acg720_vision_robot
python3 --version
python3 pc/udp_probe.py --bind 0.0.0.0 --seconds 10
```

已有 Python3 时可以先直接运行 probe，因为它不需要任何第三方包。显示 `PASS` 后再准备视频依赖。以 Ubuntu 为例：

```bash
sudo apt update
sudo apt install python3-venv libgl1 libglib2.0-0
python3 -m venv ~/.venvs/acg720-vision
~/.venvs/acg720-vision/bin/python -m pip install -i https://mirrors.aliyun.com/pypi/simple/ -r pc/requirements.txt
~/.venvs/acg720-vision/bin/python pc/udp_video_viewer.py --bind 0.0.0.0
```

WSL 的虚拟环境使用 Linux 路径，**不要复用 Windows 的 `.venv`**。若 `python3 --version` 小于 3.10，需要使用更新的解释器。图像窗口需要 WSLg 等图形支持；如果 probe 能收完整帧但窗口报图形错误，先用 Windows 接收程序即可，FPGA 端无需为运行环境换代码。

## 12. 测完后恢复普通有线上网

如果以后这同一个网口要插路由器上网，回到 `ncpa.cpl` → 有线网卡 → IPv4 属性，将 IP 和 DNS 恢复为“自动获得”，否则当前静态地址可能不适合你的路由器网络。

建议你第一次测试时按这个顺序记录结果：**网卡 1 Gbps → IPv4 为 192.168.10.3 → probe 的收包与完整帧统计 → 电脑画面 → D 键是否能改变 LCD。** 这五项能明确区分接线、电脑配置、FPGA 发送以及反向控制的问题。
