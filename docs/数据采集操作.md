# 用 FPGA 摄像头采集训练照片

本脚本保存的是香橙派／电脑**实际收到的完整图像**，不是 LCD 截图，也不是电脑预览窗口的截图。网络图像为 **400×240、RGB565**，保存为无损 RGB PNG。预览时放大到 800×480，文字和状态栏都不会进入 PNG；脚本不另加滤波、裁剪或数字缩放。

当前 LCD 的摄像头窗口为 800×480，UDP 图像为 400×240。给队友标注的是后者，日后在香橙派做识别也应使用相同的输入约定。PNG 的“无损”指保存不再引入 JPEG 压缩，不能恢复 RGB565 已经量化掉的颜色或网络下采样丢失的细节。

## 1. 先关闭其他接收程序

关闭 `udp_video_viewer.py` 和 `udp_probe.py`，再运行拍照脚本。它们都监听 UDP 6102，同一时间只运行一个接收程序。

FPGA 保持现在已经验证成功的摄像头工程。不要仅为运行脚本重新烧录。如果电脑接收，用电脑的网口 `192.168.10.3`；如果香橙派接收，用香橙派的网口 `192.168.10.3`。两个接收端不能同时占用这个地址。

## 2. 在电脑 WSL 打开拍照窗口

以下命令全部在 **WSL Ubuntu 终端**运行，不在 Windows PowerShell 中运行：

```bash
cd /mnt/d/GOWIN_PROJECTS/acg720_vision_robot
python3 --version
```

已只读确认你电脑 WSL 的现有环境位于 `/home/Vera/.venvs/acg720-vision`，里面有 OpenCV 和 NumPy，使用它即可：

```bash
/home/Vera/.venvs/acg720-vision/bin/python pc/capture_dataset.py --bind 192.168.10.3
```

如果之前使用的是系统 `python3`，则运行：

```bash
python3 pc/capture_dataset.py --bind 192.168.10.3
```

不要输入 `.venv\Scripts\python.exe`，那是 Windows 虚拟环境的路径。无需为拍照重新安装已经正常工作的环境。

如果提示缺少 `cv2` 或 `numpy`，在现有虚拟环境内安装：

```bash
/home/Vera/.venvs/acg720-vision/bin/python -m pip install -i https://mirrors.aliyun.com/pypi/simple/ -r pc/requirements.txt
```

如果之前视频工具需要 `--row-byte-order little --byte-order little` 才能显示正确颜色，拍照工具也加上同样的参数。不要靠预览看起来“差不多”来混用两种字节顺序。

## 3. 按键与连拍

先单击拍照窗口，让它获得键盘焦点。

| 按键 | 功能 |
|---|---|
| `1` | 选择当前拍摄组 `vera` |
| `2` | 选择当前拍摄组 `dog_plush` |
| `3` | 选择当前拍摄组 `earphone_cable` |
| 空格或 `C` | 开始一次 5 秒连拍 |
| `Q` 或 Esc | 退出 |

连拍默认**最多每秒保存 10 张**，5 秒最多约 50 张。实际数量受 FPGA 帧率、丢包、磁盘速度影响。脚本只保存新收到的完整帧；不会为了凑数量重复保存一张图像。连拍期间不能改变拍摄组，也不会叠加第二个连拍。

如果之后烧录支持 `VUI1` 状态遥测的 R3 触摸界面工程，LCD 的 `CAPTURE` 按钮也可触发这个脚本的一次连拍。首次接收到状态时只建立计数器基线，不会把之前按过的拍照按钮当成新事件。旧工程没有这项遥测时，键盘连拍照常工作。LCD 拍照请求本身不保存文件，需要电脑／香橙派上运行此接收脚本。

窗口出现 `CAPTURING` 后，缓慢改变姿势、距离或物体朝向；不要快速晃动导致全部模糊。终端显示 `BURST DONE: ... images saved` 表示本次结束。拍摄组只是文件归类，**不是自动生成的 YOLO 检测框或身份标签**。

修改默认拍摄组名称，例如想用通用 `person` 类：

```bash
/home/Vera/.venvs/acg720-vision/bin/python pc/capture_dataset.py --labels person dog_plush earphone_cable
```

## 4. 明确记录 FPGA 处理版本

不要让“滤波已经开启”只是凭印象。先在 LCD 检查当前滤波状态，再给本次数据指定记录，例如：

```bash
/home/Vera/.venvs/acg720-vision/bin/python pc/capture_dataset.py \
  --bind 192.168.10.3 \
  --session room_daylight_gauss_off_01 \
  --fpga-profile rgb565-400x240-gauss-off-v1 \
  --filter off \
  --pipeline-note "LCD confirmed GAUSS OFF; FPGA RGB565 and 2x subsampling"
```

`--filter off` **只记录人工确认结果，不发送关闭滤波命令**。如果尚未确认，用 `--filter unknown`，不要写成已确认。`--fpga-profile` 是由你指定的配置标记，不是脚本读取的 FPGA 软件版本。

R3 会额外报告最近观测到的实际滤波开关。脚本将它放在每张图片元数据的 `fpga_ui_recent_observation` 中，同时保留人工填写的值。状态遥测与视频帧没有共同帧 ID，因此这个观测**不能保证对应某一张照片**，切换滤波后应等待图像稳定再开始下一组拍摄。旧工程或暂时没有遥测时，该字段为空。

不同滤波状态、不同摄像头寄存器配置，分开新建 session。之后处理流程改变，可以补采、重新训练或用独立验证集比较；不需要永久禁止修改 FPGA。但不要把不同来源悄悄混成同一份数据。

当前网络数据已经下采样。把保存的 400×240 图片再滤波，不能完全复现“在 FPGA 的 800×480 图像上滤波之后下采样”的过程。因此比较 FPGA 滤波开关效果时，应分别实际采集、保留清晰的版本标记。

## 5. 约 150 张如何拍得更有用

“三次 5 秒连拍最多得到约 150 张”只是文件数量，不代表 150 个独立场景。连续帧通常非常相似。建议实际采集时降为每秒最多 3 张，在多种条件下分别连拍：

```bash
/home/Vera/.venvs/acg720-vision/bin/python pc/capture_dataset.py --fps 3 --filter unknown
```

每组做约 10 次不同条件的 5 秒连拍，可能得到约 150 张；数量不够再补采。条件可以覆盖：

- 不同距离：近、中、远；先保证耳机线在 400×240 图像里仍可分辨。
- 不同方向、姿势、摆放方式；玩偶正面、侧面、背面，线材展开、盘起和少量遮挡。
- 不同背景、位置、光照；白天、台灯、稍暗环境，避免只有同一个桌面背景。
- 单独出现、多个目标同框，以及目标不存在的负样本。

不要给人物采集组只拍脸，却期望训练后能从远距离整个人识别身份。普通 `person` 检测与“这个人是 Vera”是不同任务；人物身份通常需要额外的人脸／外观特征比对。耳机线细、形状多变，远距离在 400×240 输入下可能没有足够像素，先用实际画面确认可见范围。

需要拍背景负样本，可单独运行：

```bash
/home/Vera/.venvs/acg720-vision/bin/python pc/capture_dataset.py --class background
```

## 6. 文件在哪里，怎样发给队友

默认输出在工程的 `dataset/captures/`：

```text
dataset/captures/20261003_180000_ab12cd/
├── session.json
├── metadata.jsonl
├── vera/
│   └── burst001_000001.png
├── dog_plush/
└── earphone_cable/
```

每次启动生成新的 session；指定的 `--session` 已存在时脚本拒绝覆盖。`session.json` 记录配置，`metadata.jsonl` 记录每张图的接收时间、来源、尺寸、连拍组、人工处理标记及丢包统计。请连同 PNG 一起保留这些文件。

电脑 WSL 运行时，Windows 里可直接打开：

```text
D:\GOWIN_PROJECTS\acg720_vision_robot\dataset\captures
```

发给队友前先人工剔除严重模糊、错误字节顺序、目标过小或不适用的图。标注时对**每张图上实际出现的目标**画框，多个目标同框时分别标注。文件夹名称不能替代逐个目标的标注。背景负样本确认没有目标后保留为空标注，不是删除这张图。

训练集、验证集、测试集应按**不同拍摄时段／背景／完整连拍组**划分，避免把同一连拍的相邻帧随机分到训练和测试两边。原始采集数据不要提交普通 Git 仓库；用压缩包、网盘或队内共享存储传递。

## 7. 香橙派或无显示窗口时，直接拍一次

在香橙派工程目录，使用它自己的 Linux Python 环境。无需复制电脑的虚拟环境。

```bash
python3 pc/capture_dataset.py \
  --bind 192.168.10.3 \
  --burst --duration 5 --fps 3 \
  --class dog_plush \
  --session dog_side_light_01 \
  --fpga-profile unconfirmed --filter unknown
```

`--burst` 无窗口运行：命令开始后马上拍一次，然后退出；**只需要 Python 标准库，不依赖 OpenCV 或 NumPy**。GUI 模式仍需要原有图像查看程序使用的依赖。若要提前摆好姿势，可在同一终端输入：

```bash
sleep 3
python3 pc/capture_dataset.py --burst --class vera --fps 3
```

## 8. 发生问题时

| 现象 | 检查 |
|---|---|
| `Cannot listen ... Address already in use` | 关闭视频查看器、收包测试和其他采集脚本 |
| 无图、保存 0 张 | 先退出脚本，再运行此前已验证成功的 `udp_probe.py`；检查地址、防火墙和完整帧统计 |
| 图片颜色异常或行号错误 | 使用之前正常视频查看器同样的两个字节顺序参数 |
| 没有桌面或窗口打不开 | 改用 `--burst`，或回到有桌面显示的终端 |
| 完整帧少、`incomplete_frames` 高 | 查看丢包、链路与CPU负载；降低保存 `--fps`；脚本拒绝拿缺行图片作训练数据 |
| `Cannot create new session` | 更换 `--session` 或可写 `--output`；已存在的 session 不覆盖 |

协议只有行号，没有摄像头帧 ID。脚本严格要求来自 FPGA 的连续 `0..239` 行，丢行、乱序或超时会丢弃整个待组装帧。这个策略减少错拼图片，但不能给原有协议补出不存在的传感器时间戳或帧 ID。

已进行主机端协议、连拍节奏、PNG 颜色与大小、元数据和本机 UDP 收包回归检查；没有运行 FPGA 编译或仿真。上板实际采集质量仍以你查看保存的 PNG 为准。
