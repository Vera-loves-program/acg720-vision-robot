# FPGA 摄像头拍照：WSL 逐步操作指南

按 Vera 当前电脑的环境操作：Windows 没有 Python，Python 和 OpenCV 已装在 WSL 的 `/home/Vera/.venvs/acg720-vision`。**不用安装 Windows Python，不用重新烧录 FPGA，也不用重新配置已经收通的网口。**

## 1. 这次为什么窗口没有图像

窗口的 `complete 0 / incomplete 294` 不表示完全没有网络数据。你第一次运行留下的记录显示：收到 **503660 个包**，只有 **2099 行合法**，其余 **501561 个包被判为格式错误**。几乎每 240 个包只有一个合法，符合“行号字节顺序读反，只能识别行号 0”的特征。

例如，行号 1 发成 `01 00`，应按小端读成 1；旧脚本默认按大端读成 256，而图像只有 `0..239` 行，于是拒绝这一行。旧收包测试能自动判断行号，新拍照脚本却固定大端，这是脚本的兼容性遗漏。

现在拍照脚本和视频查看器均默认自动判断行号顺序。当前 FPGA 视频通道的行号和 RGB565 像素经过同一条 16 位数据通道，像素默认使用检测出的同一顺序；仍可分别手动覆盖。下面直接使用自动模式。

`QFontDatabase ... Cannot find font directory` 是 OpenCV 的 Qt 字体目录警告。你的窗口已经能打开，它不是这次所有帧被拒绝的原因；新拍照脚本会优先使用 WSL 已安装的系统字体目录。

## 2. 先退出正在运行的窗口

1. 单击当前拍照窗口，再按键盘 `Q`，或者点窗口右上角的关闭按钮。
2. 回到 WSL 终端，等待重新出现 `Vera@...$` 提示符。若窗口关闭后终端仍不返回，在该终端按 `Ctrl+C`。
3. 关闭其他正在运行的 `udp_video_viewer.py`、`udp_probe.py` 或拍照脚本。**同一时间只运行一个接收程序**，它们都使用 UDP 6102。
4. 保持 FPGA 正常供电、摄像头接好、网线连接 FPGA 与电脑；LCD 应仍有正常摄像头画面。

脚本运行期间不能在同一终端继续输入新命令；先退出脚本，看到 `$` 提示符，再输入下一条。

## 3. 进入 WSL 和工程目录

如果已经看到 `Vera@...$`，就在 WSL 内，跳过下面的 `wsl` 命令。

如果看到 Windows 的 `PS ...>`，输入以下命令，按回车：

```powershell
wsl
```

进入后应看到 `Vera@...$`。从这里开始，所有 Python 命令都在 **WSL 终端**执行。

接着复制下面这一行，粘贴到 WSL，按回车：

```bash
cd /mnt/d/GOWIN_PROJECTS/acg720_vision_robot
```

成功时通常没有输出，提示符末尾应变为 `/mnt/d/GOWIN_PROJECTS/acg720_vision_robot$`。

只复制代码框里的命令，不复制 `PS ...>`、`Vera@...$` 等提示符。不要用 `.venv\Scripts\python.exe`，那是 Windows 环境路径。

## 4. 打开修好的拍照程序

在刚才的 WSL 终端输入这一条完整命令，按回车：

```bash
/home/Vera/.venvs/acg720-vision/bin/python pc/capture_dataset.py --bind 192.168.10.3 --fps 3
```

程序打开拍照窗口，终端会显示类似以下内容。这里的省略号是输出示意，不是让你输入的命令：

```text
Listening on 192.168.10.3:6102, source 192.168.10.2
Saving clean 400x240 PNG to .../dataset/captures/本次会话目录
FORMAT: row=little, pixels=little
RX: packets=... valid_rows=... complete=... incomplete=... bad=... row=little order_conflicts=0
```

`FORMAT` 等收到可判断顺序的行号后才出现。按现有记录推断，你的版本应检测为 `little`；其他固件若检测为 `big`，且画面与颜色正常，也可以继续。

**确认以下三点后才拍照：**

1. 窗口上方出现实时摄像头画面，替换 `WAITING FOR COMPLETE FPGA FRAME`。
2. 窗口底部 `complete` 数字持续增加。
3. 画面颜色合理，例如白纸接近白色，红色物品不会变成奇怪的颜色。

`RX` 日志每约 3 秒输出一次，数字是本次启动以来的累计值。`incomplete` 偶尔增加表示有帧缺行、乱序或超时，被丢弃；只要 `complete` 增加，仍能采集完整帧。若看到 `NOT READY`，先等待新完整画面，不要反复按空格。

## 5. 第一次拍你自己

1. 固定摄像头，让你出现在画面中。想检测整个人，就不要只采脸部特写。
2. **用鼠标单击拍照窗口的画面区域**，让键盘输入交给窗口，并切到英文输入。按键不是输入到终端里。
3. 按数字 `1`。窗口底部应显示 `CLASS: vera | IDLE`。
4. 按一次**空格键**，然后松开。窗口应显示 `CAPTURING`、已保存数量和剩余秒数。
5. 接下来 5 秒里缓慢改变姿势或头部角度。可以请队友按空格，或先摆好姿势再按。
6. 结束后终端应显示类似：

```text
SAVED vera 1: burst001_000001.png
SAVED vera 2: burst001_000002.png
...
BURST DONE: 15 images saved for vera
```

7. 窗口恢复 `IDLE` 后，改变距离、背景或灯光，再按一次空格拍下一组。

`--fps 3` 表示每秒**最多**保存 3 张新完整帧，一次 5 秒最多约 15 张；实际可能少一些，不会复制旧画面凑数。**启动程序本身不会自动拍照，必须按空格或 C。** 连拍期间不能换组或开始另一组，等 `BURST DONE` 后再操作。

## 6. 拍玩偶和耳机线

在同一个拍照窗口中操作，无需退出：

| 拍什么 | 按键 | 窗口显示 | 开始拍摄 |
| --- | --- | --- | --- |
| 你自己 | 数字 `1` | `CLASS: vera` | 空格，一次 5 秒 |
| 小狗玩偶 | 数字 `2` | `CLASS: dog_plush` | 空格，一次 5 秒 |
| 耳机线 | 数字 `3` | `CLASS: earphone_cable` | 空格，一次 5 秒 |

玩偶依次拍正面、侧面、背面和稍有遮挡的样子；耳机线拍展开、盘起、不同桌面背景。先确认耳机线在保存的 **400×240** 图像里仍能辨认，预览放大不代表原图细节增加。

每类先做约 **10 次不同条件的连拍**，可能得到约 150 张，不足再补。不要在同一姿势下连续拍十组：不同背景、距离、方向和光照更有用。

三个名称只是保存文件夹，不会自动生成 YOLO 框。队友需要对每张图上实际出现的目标分别标注；多个目标同框时也分别标注。人物检测与识别具体人物身份需要分别设计。

## 7. 结束后找到照片

**步骤 1：**单击拍照窗口，按 `Q`。终端显示本次总数与目录：

```text
Session saved ... images: /mnt/d/GOWIN_PROJECTS/acg720_vision_robot/dataset/captures/本次会话目录
```

**步骤 2：**在 Windows 按 `Win+E` 打开文件资源管理器。

**步骤 3：**单击上方地址栏，粘贴下面路径，按回车：

```text
D:\GOWIN_PROJECTS\acg720_vision_robot\dataset\captures
```

**步骤 4：**找到刚才终端输出的会话目录，名称以拍摄日期、时间开头。每次启动程序都会新建目录；之前保存 0 张的旧目录不会自动补上图片。

**步骤 5：**进入会话目录，再进入对应目标文件夹：

```text
本次会话目录/
├── session.json             设置记录，不是图片
├── metadata.jsonl           每张照片及收包记录，不是图片
├── vera/                    你的 PNG
├── dog_plush/               玩偶的 PNG
└── earphone_cable/          耳机线的 PNG
```

只有该类实际保存过照片，才创建对应文件夹。双击 `.png` 在 Windows 图片查看器中打开。

保存的是 FPGA 发来的完整 **400×240 RGB565 图像转换成的 RGB PNG**，不含电脑窗口文字、状态栏或放大效果。PNG 不再引入 JPEG 压缩，但不能恢复量化或下采样丢失的细节。

检查几张照片的颜色、清晰度和目标大小，再将会话目录打包发给队友，保留两个记录文件。按不同拍摄时段或整组连拍划分训练／验证／测试，避免相邻重复帧同时进入训练与测试集。采集照片不提交 GitHub 源码仓库。

## 8. 还是无图时，单独检查收包

**先退出拍照窗口，等终端出现 `$`，再运行下面命令。不要同时运行拍照和收包检查。**

```bash
/home/Vera/.venvs/acg720-vision/bin/python pc/udp_probe.py --bind 192.168.10.3 --seconds 10
```

等待 10 秒结束。正常应有：包数大于零；`UDP payload lengths` 包含 802；`Complete frames` 大于零；最后出现 `PASS: complete video frames reached this computer.`。

把实际输出发给我，尤其是 `Packets received`、`UDP payload lengths`、`Complete frames`、`Row header byte order votes`。拍照脚本的新 `FORMAT` 与 `RX` 日志也有用。

| 结果 | 含义与处理 |
| --- | --- |
| `packets=0` | 才是完全没有收包：查 FPGA 供电、LCD 画面、网线、地址及此前的防火墙配置 |
| 包多，`bad` 多，`order_conflicts` 增加 | 强制行号顺序相反；去掉两个字节顺序参数，使用默认自动模式 |
| `bad=0`，但 `complete=0`、残帧增加 | 检查缺行、乱序或超时；降低保存 fps 不能直接解决网络丢行 |
| 完整帧增加，颜色异常 | 行号正确而像素顺序可能不同；保留自动行号，只覆盖 `--byte-order big` 或 `little` 对照已知颜色 |
| `Address already in use` | 先退出另一个查看器／采集程序 |
| `Cannot assign requested address` | WSL 无法绑定该地址；按网线指南核对有线网卡与镜像网络 |
| 有画面但保存 0 张 | 单击画面取得焦点，再按空格；观察 `CAPTURING` 和 `SAVED` |

如果临时使用旧版脚本，可按当前记录推断试明确小端参数；新版通常不需要：

```bash
/home/Vera/.venvs/acg720-vision/bin/python pc/capture_dataset.py --bind 192.168.10.3 --fps 3 --row-byte-order little --byte-order little
```

WSL 登录显示的 `eth1: 10.9.140.88` 不足以判断 FPGA 链路失败；此前日志已经证明有包到达。不要仅因它与 `192.168.10.3` 不同就改动已验证的配置。

## 9. 可选：不开窗口直接拍一次

先退出其他接收器。命令启动就开始计时，拍一次 5 秒后退出，无需空格，只依赖 Python 标准库。提前摆好目标，或请队友按回车。

```bash
/home/Vera/.venvs/acg720-vision/bin/python pc/capture_dataset.py --bind 192.168.10.3 --burst --duration 5 --fps 3 --class vera
```

拍玩偶将最后的 `vera` 换为 `dog_plush`，拍耳机线换为 `earphone_cable`。看到 `SAVED` 和最终总数才表示有照片；没有完整帧时不会保存残图。

## 10. 正式采集时记录 FPGA 处理状态

基本操作跑通后，为每次采集标明滤波状态和处理版本。例如，先在 LCD 确认 `GAUSS OFF`，再运行：

```bash
/home/Vera/.venvs/acg720-vision/bin/python pc/capture_dataset.py --bind 192.168.10.3 --fps 3 --fpga-profile rgb565-400x240-gauss-off-v1 --filter off
```

`--filter off` **只记录人工确认状态，不发送关闭滤波命令**。未确认时保持默认 `unknown`；不同状态分别启动新会话，等画面稳定再拍。

R3 若发送 `VUI1`，脚本另外保留最近 UI／滤波状态；它与视频没有共同帧 ID，不能保证对应某张照片。旧 R2 没有遥测也可键盘拍照。R3 的 LCD `CAPTURE` 可请求连拍，但电脑仍需运行本脚本，照片由电脑保存。

处理流程不必永久冻结，可以补采和重新训练，但不能混用不同条件而不记录。比较高斯开关应实际分别采集；对下采样 PNG 再滤波，不能完全复现 FPGA 原尺寸滤波后下采样。

协议只有行号，没有摄像头帧 ID。接收器仍要求指定来源的连续 `0..239` 行，缺行、乱序、重复或超时会丢弃待拼帧；自动判断字节顺序没有放宽完整性要求。
