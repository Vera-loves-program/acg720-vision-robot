## 实际修改与依据

功能 RTL 仅改两份：

- `src/robot_mission_control.v`：原实现要求地图积分完成的单周期脉冲，恰好与消费者全部就绪条件同时出现。若每次完成时 `map_capture_ready` 短暂为低，任务会丢失完成事件；即使建图 RAM 持续更新，也可能一直等待。现在使用建图模块保持的“已积分扫描 ID”，配合原有时间新鲜度、扫描代差和就绪条件消费完成结果。停车后仍要求合格完整扫描；过期、旧 ID、重复 ID 不触发重试。接触仍停车，清障后以新的合格地图重规划同一目标；人工 STOP 取消任务，物理故障不自动清除。
- `src/lidar_path_planner.v`：BFS 等长路线按车体前、左、右、后访问，随捕获航向旋转。左侧阻塞或 UNKNOWN 时仍可走已知空闲右侧，不是强制左转。

最终同一份 HDL 测试换回原任务控制器会复现 `fresh completed observation was lost`，修改后通过。这是可复现的软件错误，尚无现场诊断证明它是实车不续走的唯一原因。

雷达解析、body guard、导航控制、建图、UI、网络、尺寸、CST/SDC/PLL/IP 与队友基线逐字节一致。没有合入旧分支的严格方向覆盖门限，没有把 UNKNOWN 刷成 FREE，也没有修改测距比例或删除近障/传感器失效停车。

最终坐标判据仍为 X/Y 各5mm；这是估计位姿的软件完成条件，不保证实车绝对精度。题4基础速度仍为30 counts/10ms。512mm视觉目标接近距离未改，它与坐标到达误差不同。

## 简短实车验收

1. 记录位流文件名、SHA、Pi版本、电池电压。Programmer手动选择本次新目录的FS；SRAM Program断电丢失，不能仅凭LCD样式判断版本。代理没有自动烧录。
2. 题4静止设原点/+X，先以(1000,0)在空场跑一次，记录起点、终点、实测误差与LCD状态。坐标以两驱动轮中点测量。
3. 保留原目标，在路线前方放置扫描平面可见且有充足绕行空间的障碍。预期停车后继续扫描/积分；地图有已知空闲通道时重规划，等长优先左侧。首次绕行测试不要把障碍直接贴车体放置。
4. 接触或地图无安全路线时保持任务，移走障碍。预期新射线清除占据后继续原目标，无需再按GO。记录移走时间、LCD文字、是否继续、等待时间；肉眼空旷不等于UNKNOWN已经观测。
5. 等待时按STOP，再移走障碍，必须保持停止。传感器失效和物理故障也要单独实测。

若仍不走，保留现场再采诊断，区分传感器、接触、起点未知、起点占据与无路；不要先清图/改原点。仅照片不能确定拒绝细格或新鲜度。
