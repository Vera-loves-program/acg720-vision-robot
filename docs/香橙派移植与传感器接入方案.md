# 香橙派移植与传感器接入方案

日期：2026-10-03。当前已由用户验证：FPGA LCD 摄像头显示正常，电脑 WSL 能收到 FPGA 视频图像。香橙派、传感器和电机尚未在本工程中验证。

更新：用户已提供香橙派截图，系统为 Orange Pi 1.2.2 Jammy / Ubuntu 22.04.5，NetworkManager 1.36.6；有线 eth0，Wi-Fi wlan0。具体解压、电脑改为 .4、香橙派配置 .3、依赖及收图步骤，请使用新的 [香橙派独立操作指南](香橙派解压配置IP与收图指南.md)，不必再参考 WSL 文档。原先的 ZIP 为早期脚本快照，现提供 `acg720-orangepi-client-v2-20261003.zip`，包含全部辅助模块及自动字节顺序判断。

本轮先确定方案；第一步只查看香橙派环境和收集模块资料。本文后面的安装、接线和电机步骤是后续路线，不表示已经执行。

用户补充：香橙派系统未知；手边有电源，是否可限流及规格待确认；没有万用表；电机带霍尔编码器；IMU 为六轴。当前先完成系统查看和资料审查，连接 FPGA 前建议借/准备万用表核对供电，并依据手册确定信号电平。

## 1. 当前最合适的分工

```text
OV5640 → FPGA 高斯滤波、采集、LCD、UDP → 香橙派图像接收与目标识别
             ↑ 激光/超声波/IMU/编码器
             ↓ 本地避障、PWM、速度闭环、故障停车 → 电机驱动器 → 电机

香橙派 → 目标位置、导航意图、任务命令 → FPGA 本地控制状态机
```

FPGA 与软核承担基础实时感知和运动控制；香橙派承担视觉模型与高层任务。这样香橙派发出“目标在左侧”“前往某个路点”等意图，FPGA 根据本地传感器、速度反馈和限速条件决定实际输出。

任务 1～3 优先完成，再做任务 4～6。传感器读数、超时判断、编码器计数和电机使能不能依赖香橙派图像程序一直正常运行。

## 2. 香橙派只看见 VS Code，不代表其他软件不存在

桌面/任务栏的快捷方式不是软件清单。先不重装系统或清理以前的环境，打开现有 VS Code，选择“终端 → 新建终端”（Terminal → New Terminal）。也可在系统应用菜单找 Terminal/终端。

下面命令在 **香橙派自己的终端** 输入，不是在电脑 PowerShell，也不需要执行 wsl。全部是查看命令：

```bash
cat /etc/os-release
uname -m
uname -r
python3 --version
command -v python3 pip3 git apt pacman nmcli
python3 -m pip --version
ip -br addr
ls ~
```

把输出发回来，可以确认：系统类型/版本、CPU 架构、内核、Python、包管理器、网络接口和主目录。缺某个命令并不意味着系统坏了。

如果是 Ubuntu/Debian，还可以查看相关系统包；某包提示未安装也可以：

```bash
dpkg-query -W python3 python3-venv python3-opencv python3-numpy git
```

不要先安装一大套 YOLO/RKNN。视频接收只需要 Python、NumPy、OpenCV；NPU 部署应在系统、驱动与运行库版本明确后再安排。

## 3. 接收程序怎么移植

### 3.1 复制哪些文件

现有 pc/udp_probe.py 使用 Python 标准库检查视频包；pc/udp_video_viewer.py 用 NumPy 和 OpenCV 拼帧、显示并发送控制命令。源码没有依赖 Windows 专用接口，因此可作为香橙派原生 Linux 接收端使用；最终还要在板上实际验证依赖与图形窗口。

已经准备了一个小移植包，只有以下文件和本文，不包含 FPGA 构建产物：

```text
acg720_vision_client/
  pc/udp_probe.py
  pc/udp_video_viewer.py
  pc/requirements.txt
  香橙派移植与传感器接入方案.md
```

用 U 盘把 zip 从电脑复制到香橙派。用香橙派文件管理器解压，把 acg720_vision_client 文件夹放到“主目录/Home”中，后续路径就是 ~/acg720_vision_client。

只复制源文件，不能把电脑/WSL 的虚拟环境复制过去：电脑是 x86，香橙派通常是 ARM，环境内的解释器和 OpenCV 等二进制包需要在目标系统重新准备。

### 3.2 网络拓扑

先让香橙派替换电脑，作为唯一视频接收端：

```text
FPGA RJ45 ── 普通网线 ── 香橙派 RJ45
                           │ HDMI
                         显示屏
                     鼠标、键盘接香橙派
```

FPGA 目标 IP 已固定，所以香橙派有线口设置为：

| 项目 | 值 |
| --- | --- |
| FPGA | 192.168.10.2 |
| 香橙派有线 IPv4 | 192.168.10.3 |
| 子网掩码/前缀 | 255.255.255.0 / 24 |
| 网关、DNS | 留空 |
| 接收端口 | UDP 6102 |

电脑原来也用了 .3，测试时将电脑从这条测试有线网络断开。不能在同一网段同时放两个 .3。香橙派可以继续通过 Wi-Fi 下载软件。

通过桌面网络图标编辑“有线连接”，把 IPv4 方法改为“手动”，添加上述地址，保存并重新连接。不同系统界面不同；若没有该页面，先发第 2 节输出，再选适合该系统的配置方法，不猜接口名或连接名。

在香橙派终端核对：

```bash
ip -br addr
```

有线接口应具有 192.168.10.3/24，链路应为 1 Gbps。香橙派是原生 Linux，省去了电脑 WSL 的镜像网络和 Hyper-V 防火墙步骤。

### 3.3 先测试标准库收包器

确认 Python 可用、文件已放到主目录后：

```bash
cd ~/acg720_vision_client
pwd
ls pc
python3 pc/udp_probe.py --bind 0.0.0.0 --seconds 10
```

希望看到源地址 192.168.10.2、802 字节载荷、Complete frames 大于 0 和 PASS。一次只开一个收包器/视频程序。

若目标 Python 低于此前采用的 3.10 环境，先提供版本，我们确认兼容方式；不要为了跟上命令直接替换系统 Python。

如果系统启用了 UFW，按实际状态放行来自 192.168.10.2 的 UDP 6102；并不是所有香橙派镜像都安装/启用 UFW。ping 失败依然不能判断此链路失败，当前 FPGA 未实现 ICMP/ARP 应答。

### 3.4 再准备图像显示环境

先确认系统。对于适合的 Ubuntu/Debian 桌面系统，可优先使用发行版提供的 python3-opencv、python3-numpy、python3-venv，避免不必要的 ARM 源码编译。安装来源应对应实际系统和 ARM 架构：Ubuntu ARM 使用 ubuntu-ports 类镜像，不能盲目复制电脑 x86 的 ubuntu 源。下载 Python 包时可以继续使用阿里 PyPI。

安装方式参考 [OpenCV 官方 Ubuntu 指南](https://docs.opencv.org/4.x/d2/de6/tutorial_py_setup_in_ubuntu.html)。具体 apt/镜像命令待第 2 节系统信息确认后给出，避免对未知系统执行错误的软件源配置。

如果最终采用系统 OpenCV，项目环境可用 --system-site-packages 访问系统的 OpenCV/NumPy。以下是该方案依赖安装完成后的命令，当前不要求立即执行：

```bash
python3 -m venv --system-site-packages ~/.venvs/acg720-vision
~/.venvs/acg720-vision/bin/python -c "import cv2, numpy; print(cv2.__version__, numpy.__version__)"
cd ~/acg720_vision_client
~/.venvs/acg720-vision/bin/python pc/udp_video_viewer.py --bind 0.0.0.0
```

从香橙派显示屏上的终端启动，OpenCV 窗口应在同一桌面弹出。先验证画面，再点击窗口按 D，观察 FPGA LCD 十字线是否改变；这验证香橙派 → FPGA 的控制。

目前 E 仍只是状态锁存，不能据此认为电机已经有急停功能。

### 3.5 以后再加入视觉识别

首先迁移已经成功的接收和显示功能，随后让拼好的帧进入推理模块。采集接口保持 UDP，识别无需再开一个摄像头采集进程。

RKNN 部署还涉及模型转换、板上运行库、内核 NPU 驱动与版本匹配。可以在电脑训练/转换模型，再在板上运行推理；具体方案参考 [Rockchip RKNN 工具仓库](https://github.com/airockchip/rknn-toolkit2) 和 [官方模型示例](https://github.com/airockchip/rknn_model_zoo)。当前视频接收不是 NPU 推理，不需要先完成这些安装。

现有网络图像 400×240 足以先验证流程，是否满足实际检测距离和目标大小，要用实际画面测试。训练/量化校准的数据应尽量包含同一摄像头、滤波与缩放处理后的图像，减小部署图像和训练图像之间的差异。

## 4. 没有转接 PCB，现在能做什么

可以先做低功耗传感器的单模块验证，确认接口后，短杜邦线可以用于台架调试。不是所有模块都能直接接 FPGA：安全性首先取决于供电、逻辑电平、接口制式、引脚定义和回流路径，而不是是否有 PCB。

接线表要等手册确认，当前不提供具体 FPGA 管脚号：已有 LCD、摄像头、DDR、网口占用了很多管脚，需结合 ACG720 连接器原理图和现有 CST 分配空闲 IO。

| 模块 | 手册需要确认 | FPGA 后续负责 |
| --- | --- | --- |
| 激光测距 | 供电、TTL UART/RS232/RS485/I2C 等具体接口、输出电平、协议、量程/频率 | 通信、帧解析/校验、距离、有效位、时间戳、超时 |
| 超声波 | 型号、供电、Trig/Echo 或串口接口、输出电平、触发和超时要求 | 触发、回波计时/串口解析、距离、超时和无回波标志 |
| 陀螺仪/IMU | 芯片型号、是否含加速度计、I2C/SPI/UART、电平、地址、寄存器、量程 | 初始化、采集、校准、滤波和姿态处理；适合部分可由 FPGA 软核完成 |

关键电气检查：

- 模块供电 5 V 不等于信号输出 3.3 V。超声波 Echo、UART TX 和模块上的 I2C 上拉都要逐项确认。
- 对将使用的 3.3 V FPGA IO，未确认兼容前不能接入 5 V 输出。必要时设计对应电平转换；不能假定串联一个电阻就解决所有输入过压。
- RS232/RS485 不是 TTL UART，需要对应收发器。
- I2C 是开漏总线，上拉电压和阻值由整条总线决定；带板载上拉的模块要检查上拉接到哪里。
- 非隔离台架通常需逻辑共地。电机的大电流回路不能借道 FPGA 接口地线或细杜邦线。
- 先断电连线，检查 VCC/GND、引脚与供电，再通电；万用表有助于检查供电和短路，但不能单独证明所有瞬态信号都满足电平要求。

已确认模块是六轴 IMU，可规划加速度、角速度采集及俯仰/横滚姿态估计，具体寄存器、量程、校准和滤波参数仍待型号确认。六轴不提供磁航向参考；仅积分陀螺仪所得航向会漂移，也不能把加速度积分当成长期准确的位置。后续导航要结合编码器及必要的外部参考。

## 5. 建议的验证顺序和验收结果

| 阶段 | 工作 | 先验收什么 |
| --- | --- | --- |
| A | 香橙派接收图像 | probe PASS、画面持续显示；D 命令能改变 LCD |
| B | 手册审查和临时接线图 | 每个信号的供电、电平、方向、接口、连接器脚号明确 |
| C | 最容易安全接入的单个传感器 | ID/应答或帧校验正确；原始值、单位、有效位与超时可观察 |
| D | 其他传感器逐个验证 | 测距随已知距离变化；IMU 静止/转动读数合理；失败可识别 |
| E | 在保持视频工作的工程中整合 | LCD/电脑看到读数，拔掉传感器后显示失效而不是沿用旧数据 |
| F | 电机与供电方案审查 | 电压、堵转电流、驱动容量、编码器、电平、硬件急停、连接器明确 |
| G | 固定台架电机测试 | 限流供电、车轮悬空、低速方向/PWM、禁能、编码器计数正确 |
| H | 速度闭环和低速避障 | 编码器反馈、限速、故障停车、停车距离实际测试 |
| I | 视觉与任务扩展 | 识别结果通过高层命令送 FPGA，基础安全控制仍在 FPGA |

C 的顺序依据实际手册决定。例如如果激光模块是明确的 3.3 V TTL 串口，它可能更容易先验证；若是 RS485 或需要额外电源，则先验证其他合适模块。

超声波没有应答/ID 寄存器时，不虚构“初始化成功”；验收应看触发时序、回波计时、距离变化和无回波超时。通信应答也不等于量测可靠。

集成时保留现有 802 字节图像协议，传感器遥测可设计独立消息/端口，包含类型、序号、时间戳、值、单位、有效位与错误码。不能直接把传感器值塞到原图像包里破坏接收器。

## 6. 电机部分，先查选型与反馈

现在可以继续准备传感器，不需要马上给电机接 VM。要先确认电机额定电压、启动/堵转电流与供电方案，不能只根据驱动模块标题判断能带动电机。

TB6612 有独立的逻辑 VCC 和电机 VM。原厂资料给出了电源范围、输入阈值、温度/散热与脉冲电流条件；商品常写的 3.2 A 峰值不是长期连续电流。若逻辑 VCC=5 V，原厂 VIH 最低为 0.7×VCC=3.5 V，FPGA 的 3.3 V 高电平不能保证满足；模块是否允许逻辑 VCC=3.3 V 还要查模块原理图。依据是 [东芝 TB6612FNG 数据手册](https://toshiba.semicon-storage.com/info/docget.jsp?did=10660)。

题目明确写了“支持编码器反馈闭环控制”。用户已确认电机带霍尔编码器，具备继续设计反馈采集的条件。下一步确认它是 A/B 两路还是单路、线序、供电、输出形式/电平、每转脉冲数和减速比，且区分电机轴与车轮轴的脉冲定义；不能仅凭“霍尔编码器”假定一定可直接接 FPGA 或采用四倍频。

后续电机方案要有合适的供电、低阻大电流连接、去耦、启动默认禁能和硬件急停路径。FPGA 提供控制信号，不能从 FPGA 的 3.3 V/5 V 插针直接承担电机供电。禁能、滑行与短路制动也需要区别设计。

## 7. 转接板什么时候画

先锁定模块型号与供电，再做临时接线表和单模块验证，之后画 PCB，可减少返工。原理图里至少规划：

- FPGA 可用连接器与引脚编号，区分电源和逻辑信号。
- 传感器/编码器电平转换、I2C 上拉和必要的输入保护。
- 电机电源与逻辑电源、回流路径、去耦和合适的接插件。
- 硬件急停、STBY/使能默认状态、测试点、模块接线标注。

不必等正式 PCB 做好才验证 3.3 V 低电流传感器，但临时连线同样必须有已经核对的接线图。

## 8. 现在需要提供的资料

1. 香橙派第 2 节命令输出；未知系统前不盲目换源、重装或升级系统 Python。
2. 激光、超声波、陀螺仪/IMU 的确切型号、商家模块手册/链接、正反面和插针标注照片。芯片手册不能替代模块板上稳压/上拉/收发器的资料。
3. TB6612 模块正反面、引脚标注、模块原理图或购买链接。
4. 电机型号、额定电压、启动/堵转电流和已确认的霍尔编码器资料；机械结构轮数、是否差速、轮径。
5. 手边电源的电压/电流能力、是否可限流。当前没有万用表，正式台架接线前建议借/准备一个；现有转接连接器及 ACG720 板卡版本照片可用于核对可用接口。

拿到资料后先交付一张具体接线表：模块脚 → 供电/地/电平转换 → ACG720 连接器脚 → FPGA 管脚与 IO 电压；再确定驱动、采样时序、故障标志和验收项目。确认这张表后才开始传感器驱动和接线测试。
