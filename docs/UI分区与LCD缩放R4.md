# UI 分区与 LCD 缩放 R4

这次直接修改已有 `vision_robot_ui.gprj`，入口不变，屏幕标题改为 **VISION ROBOT R4**。保留正常工作的摄像头、DDR3、网口和高斯滤波主链路。

## 这次修正什么

上一版的双指操作只改变主机缩放请求，LCD 没有执行像素放大。现在加入 LCD 本地的 1× / 2× 显示：2×把原始 800×480 中央的 400×240 区域放大到整个摄像头窗口。摄像头窗口仍是 800×480，位置仍为 X=16..815、Y=56..535。

右侧改为独立白色卡片和蓝色按钮。原先穿过 `TOUCH` 文字的分隔线已经去掉；所有文字都限制在所属区域内，字体节距从 16 px 减为 12 px。预览使用源码中的字形和实际卡片位置，不再沿用与固件不一致的旧示意图。

参考界面已经找到：[EDispense_Vision/ui/solder_ui.py](https://github.com/ZexinLiang/EDispense_Vision/blob/master/ui/solder_ui.py)。它是 Python/PyQt5 程序；你最初给的 Embedded 仓库主要是 STM32 固件。这里参考浅灰背景、白色卡片和蓝色按钮，自行绘制 FPGA 界面，没有复制点锡机控制逻辑或字体文件。具体区别见 [点锡机界面参考审查](点锡机界面参考审查.md)。FPGA 当前采用位图文字，和 Python 界面的字体、圆角、动画效果仍有区别。

## 屏幕分区

以下坐标右端、下端不包含。各卡片之间留空，不让文字跨区绘制。

| 区域 | X 范围 | Y 范围 | 内容 |
|---|---|---|---|
| 顶栏 | 0..1024 | 0..44 | 版本标题、FPGA UI 标识 |
| 摄像头 | 16..816 | 56..536 | 实时画面、调试十字线、选点框 |
| 初始化状态 | 828..1012 | 52..108 | CAM WAIT / PLL WAIT / DDR WAIT / CAM DDR OK |
| 视觉调试按钮 | 832..1008 | 112..152 | VIS DEBUG / DEBUG ON |
| 触摸状态 | 828..1012 | 160..224 | TOUCH OK、FINGERS 0/1/2 |
| 图像与网口 | 828..1012 | 232..296 | GAUSS ON/OFF、PHY INIT/WAIT |
| 选点与视图 | 828..1012 | 304..384 | ROI、TRACK OFF、VIEW 1X/2X |
| 重置视图按钮 | 832..1008 | 392..432 | 恢复 1× 并清除选点 |
| 拍照按钮 | 832..1008 | 440..488 | 发出五秒连拍请求 |
| 电机状态 | 828..1012 | 496..536 | NO MOTOR / STOP FLAG |
| 底栏 | 0..1024 | 547..600 | 画面尺寸、网络尺寸、滤波状态、操作提示 |

`PHY INIT` 只表示 PHY 初始化完成，不表示香橙派已经在线或收图。`TRACK OFF` 表示暂未连接跟踪算法；选点框仍是人为指定的候选区域。`STOP FLAG` 仍是状态位，电机部分尚未接入。

1. 在 Gowin 中打开本地 `D:\GOWIN_PROJECTS\acg720_vision_robot\vision_robot_ui.gprj`，确认顶层为 `vision_robot_ui_top`。
2. 文件列表现在应包含新增的 `src/lcd_camera_zoom.v`。如果原工程窗口一直开着，先关闭工程再打开，让它重新读文件列表。
3. 保存后，由你重新执行 Synthesize 和 Place & Route。不要只看旧的绿色完成标记，要确认本次任务实际重新运行、生成文件时间更新。

本次没有运行 FPGA 编译、仿真或上板测试。排版预览已经绘制并检查；实际布局布线、资源及时序以你这次编译报告为准。

## 双指放大怎样操作

1. 等待 `CAM DDR OK`，画面正常出现；触摸栏应显示 `TOUCH OK`。
2. **不必先打开 DEBUG**。把两根手指都放在摄像头画面内，例如间隔 100～150 个屏幕像素。
3. 手指保持接触，向外展开。间距增加至少约 25%，并增加至少 24 px 时，切换到 2×。
4. 应同时看到 `FINGERS 2`、`VIEW 2X`，屏幕中间的物体变大，四周内容被裁去。
5. 保持双指接触后向内收拢，间距减少约 20% 且至少 24 px，恢复 1×。也可以抬手后重新放两指再收拢。
6. 点击 `RESET VIEW` 也可以立即请求恢复 1×，同时取消选点。

这一版是 1× / 2× 两档、以画面中心放大；暂不包含任意倍率、跟随手指中心放大或拖动平移。像素使用最近邻复制，不会增加摄像头细节。

`FINGERS` 显示最近一次有效触摸快照。三指及以上、重复 ID 或异常坐标报告会取消手势，避免误操作。

## 双击选点怎样操作

1. 单击 `VIS DEBUG`，看到 `DEBUG ON`。
2. 在画面中短点两次，两次间隔不超过约 450 ms，位置尽量一致。
3. 显示 `ROI SET` 和橙色候选框。2× 状态下也会换算回原始 800×480 图像坐标。
4. 放大或缩小时，选点仍对应原图同一位置。若选点落在中央裁剪区域外，放大时不绘制它的框，显示 `ROI OUT`。
5. 这一步只是选择目标，还不会自动识别人或让电机移动。

## 拍照和香橙派接收

LCD 缩放只改变观看方式，不改变发给香橙派的完整 400×240 RGB565 图像，也不改变采集脚本保存的照片。高斯滤波仍由 S4 切换，采集时按已确认的滤波约定操作。

`CAPTURE 5S` 只发出请求。香橙派或电脑必须正在运行 `capture_dataset.py`，才会真正保存照片；查看器本身不写照片。两者不能同时占用 UDP 6102。

新版 `udp_video_viewer.py` 收到 LCD 缩放状态后，也按中央区域显示 1×/2×，避免原先有选点时主机绕选点放大、LCD 绕中心放大的差异。网络遥测的倍率取自 LCD 帧边界锁存的实际状态，而非刚发出的请求；该状态仍不表示照片保存或目标跟踪成功。原客户端仍可收图；要同步观看区域，可以更新客户端脚本或使用此次提供的 R4 客户端 ZIP。网络协议没有改变。

R4 客户端包名为 `acg720-orangepi-client-r4-20261003.zip`，解压后的根目录仍是 `acg720_vision_client_v2`，环境和 IP 设置沿用已经完成的配置。先退出接收窗口；备份旧目录后把新包解压到 Home，再从原目录启动查看器即可。也可以只复制更新后的 `pc/udp_video_viewer.py` 到原包同名位置。此包不包含 FPGA 工程，不能拿它在 Gowin 里编译。

## 如果没有按预期显示

| 现象 | 优先检查 |
|---|---|
| 两指放下仍是 FINGERS 0 或 1 | 看 TOUCH 是否 OK；把两指完全放在画面内部，间距稍大，避免一个手指在侧栏 |
| FINGERS 2，始终 VIEW 1X | 保持接触向外展开，达到约 25% 且 24 px 的变化；不是两指点一下就放大 |
| VIEW 2X，图像确实变大 | 缩放已生效，四周裁去是中央裁剪的正常结果 |
| 显示 ZOOM WAIT、画面黑或 D7 亮 | 本帧行缓存没有及时拿到正确数据；先点 RESET VIEW 恢复原读取方式，记录 1× 是否正常以及编译时序结果 |
| UI 仍是旧标题或旧颜色 | 检查是否重新编译本工程、烧录本次生成的 FS 文件 |
| CAPTURE 按了没有照片 | 检查主机运行的是拍照程序而非查看器，并查看主机终端的 BURST / SAVED 输出 |

行缓存预取以当前 DDR 适配器和 45 MHz LCD 时钟为基础。缓存不足时会报告等待，不用旧行冒充新画面；下一帧重试。实际双指反馈和预取余量需要此次上板验证。

## 后续界面扩展

等测距、IMU 和电机接口确定后，可以增加独立页面：传感器页面显示距离/姿态，运动页面显示编码器与速度，视觉页面显示目标类别/置信度/丢失状态。普通页面只保留关键状态，详细信息放调试页，不继续往当前侧栏塞文字。

FPGA 继续负责采集、滤波、显示和实时状态；香橙派运行检测或跟踪后回传结果。这样 UI 上可以明确展示哪些处理来自 FPGA，哪些来自识别模型，避免把“打开调试”误写成“已经识别成功”。
