## 0. 产品方向：陪伴学习助手

产品方向是“能在平地跟随、在桌边陪伴学习的小车”。先服务学生，也可用于成人听力练习。物品存放/搬运功能暂不作为主线；云台留到下一阶段，不为目前的演示增加机械负担。

第一版先做摄像头人脸/玩偶检测、双击选目标与取消、学习/休息计时、可关闭的离座提醒。联网拍题答疑、语音讲解、SD 卡听力播放放在后续阶段。这里是方案，不表示这些功能已经完成。

| 功能 | 分工 | 目前状态与实现边界 |
| --- | --- | --- |
| 实时画面与触摸 | FPGA 相机采集、图像流水线、DDR/LCD；GT911 提供触点 | R4 已上板；此前 R5 已改缩放源码，等待用户编译和上板 |
| 人脸/玩偶框与选中目标 | 香橙派运行 YuNet＋YOLOv5n，再做检测关联和跟踪 | 模型接入、真正跟踪、框回传 LCD 均待编写；目前橙色 ROI 只是选点请求 |
| 跟随与避障 | 香橙派提供目标位置；FPGA 独立读取编码器、测距并控制速度，最终受急停/超时约束 | 扩展板与引脚分配先完成，再逐个传感器、架空电机测试 |
| 学习计时 | FPGA 做稳定计时与本地提示；香橙派管理学习计划、记录和语音 | 待实现。没有网络也应能暂停、结束，不随意开动小车 |

| 拍题与讲解 | 香橙派 OCR/联网问答/语音；FPGA 提供清晰快照和显示通路 | 400×240 预览不能保证读清整页题目；需额外设计较高分辨率快照传输 |

学习助手的大部分语义和知识功能都在香橙派或云端；不能说换成这个用途以后，FPGA 就自动比 STM32 更有优势。FPGA 的研究重点仍是像素流与多任务同时运行时的固定延迟、独立控制和故障情况下的行为。用下面第 2 节的实测来说明作用，再决定哪些额外外设值得加入。

### 此前 R5 缩放设计与下一步显示交互

R5 沿用同一个 `vision_robot_ui.gprj`。正常模式下，双指拉开/收拢围绕两指中点缩放，两指一起移动可平移；ZOOM IN MODE 下，双击画面指定原图中心；2026-10-06按用户要求移除LCD的`+`/`−`及其他多余按钮，倍率继续用双指手势调整，见第21节。视觉调试的双击选目标只在缩放选点模式关闭时生效。倍率范围先为 1～4×，以 Q8 逆比例提供 193 个细分步长，不是只切换 1×/2×，也不是无限倍率或光学变焦。

为了不牺牲 RGB565 颜色和源图采样品质，显示使用两个完整 800 像素行缓存，调整 DDR 的读取起始行，并在每个 LCD 帧边界锁存裁剪位置与步长。摄像头写入、DDR PHY/PLL、网络全画面保持原链路。数字放大不会创造新细节；网络图像仍是 400×240。R5 尚未编译、仿真或上板，现有位流不是自动更新后的 R5。

以后香橙派返回 `dog`/`human` 框时，必须携带类别、源图坐标、时效与跟踪状态；FPGA 使用与画面相同的裁剪变换叠加框。要真正显示讲解的中文文字，还需要字库或香橙派渲染后的图层传输，现有英文点阵 UI 不会自动做到。

### 摄像头对焦暂按手动 V5 处理

用户已确认模组版本 V5。配套目录的版本说明文件名指出“V5 的自动对焦和补光灯没有硬件支持”，但同目录用户手册介绍仍写支持自动对焦，资料存在冲突。当前按用户实际可手动旋拧的镜头使用，暂不加入自动对焦驱动，也不仅凭 OV5640 芯片支持就断言该模组带电动镜头。

软件自动对焦需要镜头执行机构，例如 VCM；OV5640 的自动对焦方案还涉及固件和控制命令。[OV5640 应用说明](https://www.arducam.com/downloads/modules/OV5640/OV5640_Software_app_note_parallel.pdf) 写明了这条控制链路。现阶段先在实际人物/玩偶的常用距离调清楚并固定镜头。如果以后换带电动调焦的 DVP 模组，先确认供电、接口和控制方法，再做驱动。

拧动螺纹镜头主要调整对焦距离；数字放大改变显示裁剪。二者不能互相替代。FPGA 以后可对选区计算清晰度作为手动调焦提示或电动对焦反馈，但不能让没有执行机构的镜头自行移动。

## 1. 先说清楚：为什么使用 FPGA

如果目标只是“摄像头识别人，香橙派算结果，下位机驱动两台电机”，香橙派直接连接摄像头和屏幕、配合 STM32，完全是合理方案。不能把绕经 FPGA 的显示、网口转发或多接几个传感器本身当成优势。STM32 也有硬件 PWM、编码器计数和定时器，见 [ST 定时器文档](https://wiki.st.com/stm32mpu/wiki/TIM_internal_peripheral)。

比赛要求以 FPGA 为主体，这决定了我们要研究 FPGA 能承担什么，并不证明它一定是这类消费产品的成本最优解。要区分“适合研究和比赛”“系统中确有作用”和“市场上最划算”。闹钟、音箱和更多接口可以增加实用性，不能代替性能证据。

在学习助手用途下，建议把 FPGA 技术主线定为：**图像流水处理与独立移动控制，香橙派增加目标识别和学习交互。**简单颜色定位可作为独立演示或调试模块，不作为人脸/玩偶神经网络的替代。先做出可测量的硬件处理路径，再评价是否值得采用。

| 候选能力 | FPGA 具体做什么 | 实际用途与限制 |
| --- | --- | --- |
| 简单目标定位 | 对摄像头像素做颜色分割，统计目标区域、面积、中心位置 | 可跟随颜色标记、定位红色目标；不能把“红色区域”称作“识别了水瓶”，也不能保证在杂乱背景中正确选中目标 |
| 独立跟随闭环 | 目标水平偏差产生转向意图，前方测距限制速度，两路编码器反馈轮速 | 在不依赖香橙派视觉推理的模式下运行；目标丢失、数据过期时停止，而不是盲走 |
| 并行执行 | 像素处理、编码器计数、各传感器接口、PWM、LCD、网络各自运行 | 是否在视频/网络满负载时仍保持控制周期，需要实测；不是 MCU 不能并行，也不是零延迟 |
| 图像与传感器时间对应 | 给帧、距离、轮速打统一时间戳，记录数据有效性 | 帮助判断目标画面和障碍物距离是不是同一时刻附近的数据；传感器内部测量周期仍由模块决定 |
| 输出仲裁 | 识别结果不能直接绕过急停、测距异常和速度上限驱动电机 | 与独立硬件禁能结合，提高失联时行为的可预测性；这也是 MCU 可做的功能，不单独作为 FPGA 独有优势 |

现有高斯滤波是实际像素流水线，可以继续复用。但为了检测效果而不断叠加滤波不一定有益：用于 AI 的彩色图像和用于硬件颜色定位/调试的分支应明确区分，并记录处理配置。颜色阈值应在实拍光照下标定。

800×480、30 帧/秒的 RGB565 有效图像数据为 23.04 MB/s；400×240、30 帧/秒为 5.76 MB/s，未计空白和协议开销。这是计算示例，不是当前所有链路的实测吞吐。逐像素流水线是 FPGA 值得研究的部分，数值不能证明它已经超过香橙派或某款 STM32。

## 2. 如何证明价值，避免自欺欺人

先给出测试条件和结果，再写性能结论。建议记录以下项目：

| 测试 | 要记录什么 | 能说明什么 |
| --- | --- | --- |
| 颜色定位路径 | 从曝光/帧到坐标输出的时序、帧率、错误选中情况 | FPGA 是否真正承担定位计算。逐帧面积/中心统计通常要等帧结束，不能声称微秒级完整识别 |
| 控制周期 | 例如以 1 kHz 作为初始设计目标，记录轮速控制更新间隔和抖动 | 固定周期控制是否实现；1 kHz 不保证机械系统有相同响应速度，参数需实测调节 |
| 并发负载 | 视频+网口打开/关闭时的编码器丢计数、控制周期、轮速误差 | 这些硬件模块运行是否受到图像负载影响 |
| 停止行为 | 有效障碍事件/指令超时到 PWM 与使能变化，以及车轮实际停下的时间 | 数字输出停止与机械刹停是两种指标；传感器采样周期、惯性、驱动状态都影响后者 |
| 对照方案 | 同摄像头、同算法、同分辨率、同功耗/成本统计方法 | 若要宣称优于香橙派或 STM32，必须有可比实测；只展示本方案不够 |

目前没有上述对照数据，所以只可描述设计和已实现的功能。即使测试后发现 MCU 同样能胜任，也应如实报告。项目仍可以展示硬件流水线、资源开销和可预测控制，但不夸大性价比。

## 3. 40＋4＋8＋16 不是 68 个数字 GPIO

依据官方《ACG720-138&60K通用原理图》第 1、3、7、8、11、12、15 页，以及《高云 ACG720-138&60K通用管脚分配表.xlsx》Sheet1 GPIO0 的 A219:F254。接插件总脚数包含电源、地、模拟信号和未连接脚。

| 接口 | 实际信号 | 扩展板处理 |
| --- | --- | --- |
| P7，40 针 | 36 个 GPIO、5V、3V3、两个 GND | 作为主要数字接口，36 根信号全部保留直通/测试点 |
| P3，4 针 | 两路 DAC 模拟输出、两个 AGND | 单独标为模拟输出，不接数字传感器或电机 |
| P5，16 针 | 八路 ADC 模拟输入、八个 AGND | 每路按“模拟输入＋AGND”分组；需要分压/放大/保护的前端另画 |
| P8，8 针 | USER0/1/2、5V、3V3、两个 GND、一根未标功能脚 | 可预留连接器，不将未知脚计入本期可用 IO |
| P6，8 针 | GPIO Bank 的 VCCIO 电压选择跳帽 | 保留选择功能，不当传感器接插件 |

P8 按原理图为：1=5V，2=GND，3=USER0，4=USER2，5=USER1，6=未标功能，7=3V3，8=GND。USER2 可见 H20；USER0/1 的 FPGA 端映射尚未可靠核实，本期不使用。第 6 脚不是可随意分配的 IO。

**纠正旧说明：本版官方资料中，P7 GPIO0 在 BANK2，HDMI 在 BANK7，球位没有重叠。此前“GPIO0 与 HDMI 共用”的说法没有依据，应撤回。**同时使用时仍要计算时钟、逻辑资源和视频带宽，但不存在已发现的这两组球位冲突。

GPIO0 的电压不是固定 3.3V：BANK2 的 VCCO_2 接 VCCIO，P6 可选 3.3/2.5/1.8/1.5V。按图 P6 的 7—8 跳帽选择 3.3V；实物 Pin1 方向、板卡修订和跳帽位置还需确认，并用万用表核对 TP5。软件设置 LVCMOS33 不会把错误的硬件供电自动变成 3.3V。

## 4. P7 候选分配：传感器共用 I²C，BQ 两路独立

**球位映射已经核对，功能分配仍是电路方案，没有写入 CST 或 RTL，也没有实物接线验证。**主工程 `vision_robot_ui.gprj` 指向 `src/lcd_interaction.cst`。本轮从官方 XLSX 的 Sheet1!A219:F254 读出 36 个互不重复的 GPIO 球位，与当前 CST 的 115 个已用球位比较，交集为 0；并目视检查原理图第 2、3、11、12 页。LCD、GT911、摄像头、DDR 和网口约束保留。

此前资料未证明 SHUT 引出，所以先用四条独立 TOF 总线避开同地址问题；这是保守的设计选择，不是 FPGA 必须如此。2026-10-05 用户给出 TOF 的 VIN/GND/SDA/SCL/INT/SHUT 和 IMU 的 VCC/GND/SDA/SCL/INT/SA0，现将候选简化为**传感器一条共用 I²C＋BQ A/B 各一条，共三组逻辑总线**。

四个 TOF 上电均为 0x29，需要分别控制 SHUT，逐个改为七位 0x30/0x31/0x32/0x33；IMU 按 SA0 状态选择 0x6A 或 0x6B，与它们不冲突。总线一次服务一个事务，测量可在器件内部进行，不因共享就要求四个测距过程都串行等待。线长、等效上拉、总线占用和故障恢复仍需实测；共享线路被某块拖低时，IMU/TOF 都会受影响，必须超时、数据失效和停车处理。

| 功能 | 当前候选占用的 GPIO 数 |
| --- | ---: |
| IMU＋四个 TOF 共用 SCL/SDA | 2 |
| 四路 TOF 独立 SHUT 控制 | 4 |
| IMU INT | 1 |
| BQ A、BQ B 各一组 SCL/SDA | 4 |
| 超声波 TRIG/ECHO | 2 |
| TB6612 四路方向、两路 PWM、MOTOR_REQ | 7 |
| 两台电机编码器 A/B | 4 |
| SAFE_OK 反馈、外部看门狗心跳 | 2 |
| 调试/HC-06 复用 UART TX/RX | 2 |
| 基础合计 | **28，剩余 8** |
| 两路舵机控制预留 | **再占 2，共 30，剩余 6（P7 13/14/33/34/36/37）** |

目前云台接口仅预留，不接功率负载。两路舵机占 2 根，或者两个 STEP/DIR/EN 步进轴占 6 根，二选一；选择两步进轴后基础共 34 根、剩 13/14 两根。TOF 的四路 INT 暂留连接器/本地测试点、不占 FPGA；以后若四路中断全接入，需要再占 4 根并重算云台/备用。P7 13/14 保留改回独立 IMU 总线的可能；共享接法与独立接法通过装配选项二选一，不同时焊通不同控制器输出。不为用满引脚提前选定云台。

TB6612 没有可假定的 FAULT 引脚。SAFE_OK 来自扩展板硬件门控/锁存电路；BQ 的 ALERT 本期仅留本地测试点，未分配 FPGA 脚，不能再照旧表占用 P7 38/39。未来限位或 ALERT 需要使用备用脚并重算。完整信号直通到标号测试点，预留断开电阻/焊桥供迭代，同一根 IO 的两个连接器不是两个 IO。

HC-06 按用户已用过的 5V 供电、115200 波特率安排，不擅自改成默认波特率或重发 AT 配置。5V 来自受保护的逻辑支路，近模块预留去耦；供电电压不等于 UART 电平，核对实际底板 TX 输出及 RX 门限，再装配 3.3V 直通/输入缓冲。蓝牙天线朝板边，按模块要求留净空、避开电机/电源和金属遮挡。J_BT/J_DBG 候选针号是扩展板定义，模块侧按实物丝印转接。

BQ采样区域保留各自BAT−低电流参考地，SDA/SCL由系统侧上拉后条件直连，不再使用隔离器。独立采样组件的4Pin中SYS_GND只接PACK−，不能接BAT−。电池/负载另走额定电流合适的动力端子，BAT− 采样地不经过这个 4Pin 接到 SYS_GND。BQ 的 NTC 每块留 2Pin，ALERT、REGIN、REG25、BAT、SRP/SRN 留本地测点。

每路模块电源预留可断开的供电焊桥/受控负载开关及本地去耦，便于排查单模块，避免模块断电后仍被 SDA/SCL/INT 反向供电。确认模块稳压器、上拉和供电后，选择带掉电保护的适配器；0Ω 直通仅在电平已确认时装配。P7 的板载 5V/3V3 与扩展板自己的稳压输出不能直接并联，用单一供电源或经过验证的电源选择电路。

## 6. 开关、LED、按键和 LCD 怎么发挥作用

不要做“每个开关对应一种随意效果”的功能拼盘，围绕测试、模式和故障解释来用。这些板载资源使用自身的固定连接，不需要占用 P7 的新传感器信号。

| 板载资源 | 建议用途 |
| --- | --- |
| SW0 | 允许运动开关，关闭则禁止运动；不是替代硬件急停 |
| SW1 | FPGA 简单视觉模式 / 香橙派识别模式；切换后重新确认启动 |
| SW2～SW3 | 调试预览选择：原图、灰度、高斯、边缘。AI 发送分支配置需单独记录，不能随意跟着预览改变 |
| SW4 | 图像标记/传感器数值叠加 |
| SW5 | 台架低速限制模式 |
| SW6 | 事件/时序记录开关 |
| SW7 | 定时提醒开关；不设置“关闭安全保护”的开关 |
| S0 | 保留当前全局复位功能 |
| S4 | 保留当前高斯切换功能；之后若改变，应更新 UI、说明和数据配置 |
| S1～S3 | 后续开始/暂停、菜单确认、取消/提醒消音，长短按去抖；具体映射待界面确定 |
| D0～D7 | 后续显示心跳、相机、DDR、通信数据有效、测距有效、轮速控制、目标有效、停止/故障 |

上述是规划，当前 R4 的 LED 诊断含义仍以源码为准，不能假设已经改好。当前 PHY 初始化完成不等于网络已连通，目标被双击也不等于跟踪算法已经接入。

LCD 保持四块不重叠区域：摄像头/目标标记；四角和前方距离；左右目标与实测轮速；模式、数据年龄、停止原因。增加一页“硬件处理调试”，显示原图/分割结果、目标像素数、坐标和流水线状态，比只写“已高斯滤波”更便于验证。

## 7. 闹钟、音箱、SD 和两路 HDMI

### 7.1 闹钟可以做，而且已有适合的硬件

官方原理图第 9 页有两组四位数码管，即**八位数字**，不是只能显示两位。通过两个 74HC595 驱动，FPGA 信号为 SEG7_DIO=M18、SEG7_RCLK=C2、SEG7_SCLK=F4。

同页有 BM8563T RTC 和 CR1220 电池位。教程第 34 章名为《基于I2C接口的PCF8563数字时钟显示》，可以参考读时间、校时、显示逻辑，但实际芯片/寄存器先核对。RTC 的 INT/CLKOUT 没有接 FPGA，时间和报警状态需要轮询；掉电保持取决于实际电池。RTC、EEPROM 和音频配置共用板载 I²C（M13/M16），后续驱动不能各自同时占用总线。

板载无源蜂鸣器 BEEP=N19，已有晶体管驱动。最小功能可以是“时钟/番茄钟＋数码管＋蜂鸣提醒”，无需先买扬声器。官方第 13、19/20、34 章分别提供数码管、蜂鸣器、时钟参考。此功能可先独立验证再整合，其中RTC时钟与数码管已在2026-10-06写入同一主工程源码，待用户编译/上板，见第20节；番茄钟和蜂鸣提醒仍未实现。声音提醒时小车默认停着，不设计无人确认就追着睡觉的人移动。

### 7.2 会移动的小音箱可做，但需要声音输出设备

原理图第 14 页是 ES8388：蓝色 IN 为线路输入，绿色 OUT 为模拟音频输出，没有独立扬声器功放。MIC1 是两针接口，不代表已经有麦克风。

你已买的 **2828、4Ω/2W 裸扬声器可以先保留**，做提示音不需要急着换。接法是“ES8388 绿色 OUT → 功放模块输入 → 扬声器”，不能直接接 GPIO，也不建议直接挂在板卡音频输出上。可选带音量调节的 PAM8403 模块；它在 5V、4Ω、10% 失真条件下可输出 3W，所以不能对 2W 喇叭满音量长期播放，需要限制音量/输出功率。功放供电单独核算。PAM8403 是桥接输出，喇叭接同一声道的 `L+ / L-` 或 `R+ / R-`，两端都不能接 GND，也不能把左右声道输出并联。参考 [PAM8403 原厂手册](https://www.diodes.com/datasheet/download/PAM8403.pdf)。

最实用的声音内容是倒计时结束、靠近障碍、目标丢失和低电量提醒。语音合成/语义识别可由香橙派承担，FPGA 做定时播放、音量/混音或简单音频处理，但这些需要音频传输和 ES8388 配置。复杂语义任务不能因为加了音频口就自动成为 FPGA 功能。

### 7.3 SD 是 microSD/TF，需要驱动和文件系统

第 15 页 J8 是 microSD 插座。未来可放提示音、字体、配置和日志；插卡本身不会自动支持 MP3 或录像。先考虑 PCM/WAV 提示音，比在 FPGA 上新增 MP3 解码省工。日志第一版直接发到香橙派存储，后续再实现 SD 写入。

用户提出板上速度曲线回放，现按第 18 节先做 RAM 短时记录，再做 SD 长日志。可先使用板载 J8，无需为了此功能新增扩展板卡座；SD 驱动/文件系统尚未实现。

### 7.4 HDMI 保留为大屏调试输出，不是通用传感器接口

本地当前工程未使用 HDMI；后续可先把它作为显示器、投影仪或采集卡的视频输出。接口有 ESD、电源开关和 DDC 适配。[高云官方板卡说明](https://www.gowinsemi.com.cn/university/board/17)称双路支持输入/输出；没有独立 HDMI 接收芯片不能据此断言 FPGA 不能接收。具体接收仍需匹配 FPGA 收发实现、时钟、约束及接口电路，本次没有验证或实现。本项目不用改屏，也不通过 HDMI 插座接激光、电机等普通模块。

软件可复用已有像素生成逻辑，但仍要加 TMDS、时钟、串化和正确约束。以后比赛展示时可在借来的大屏上显示处理对比和传感器调试页。两口都空着没有问题，不需要为了“用满板子”购买两块屏。

### 7.5 ADC 可以服务电池和电机状态，而非硬加示波器

第 15 页 ADC128S102 的模拟供电为 3.3V，因此按图正常输入为 0～3.3V；八通道是轮询复用转换，不是八路同时采样。若以后加入电池电压分压、电流传感器/采样放大和必要保护，可检测低电量、过载与堵转征兆。需要模拟前端和实测阈值，不能直接接电池或电机端。第一版先预留模拟接口，待运动稳定再决定是否值得实现。

1. 现在：审核并冻结电路、接插件和引脚；再开始画板或写驱动，保留已通过的图像链路。
2. 硬件验证：逐个传感器、独立急停、架空电机/编码器，之后才做低速闭环；先证明不会误启动。

## 11. 已收到的传感器资料：接口和初始化怎么安排

### 11.1 TOF200C：四个 VL53L0X 的地址管理

本地资料为 `TOF200C资料/vl53l0x.pdf`、`TOF200C尺寸图.pdf` 和 STM32/Arduino 例程。STM32 例程里的 USART 9600 是向电脑打印测距日志，不是传感器通信。芯片通过 I²C 访问，上电七位地址为 **0x29**。手册里的 **0x52/0x53** 是已加读写位的总线字节，不能再把 0x52 当七位地址左移一次。

本地 `VL53L0X_general/readme.txt` 明确写 SCL→PA3、SDA→PA2、XSHUT→PA5；`vl53l0x.h/.c` 定义 PA5 并执行复位/改地址。尺寸图目视仅见六个 2.54mm 孔，未标功能；2026-10-05 用户补充模块六针为 VIN/GND/SDA/SCL/INT/SHUT，故不再把“有无 SHUT 引出”列为缺口。候选按 SHUT 对应 VL53L0X 的 XSHUT 控制设计，实际连接和电平待核实。示例使用推挽 GPIO 的写法不能照搬到 FPGA I²C。

本期候选改为四个 TOF 和 IMU 共用传感器总线。四个 SHUT 分别控制，在初始化完成前关断所有 TOF，再逐个启动改地址。预留逐模块供电断开/复位能力；共享 SDA 卡死时先禁止运动，把受影响设备的数据判无效，再按有超时的恢复流程处理，不能继续信任旧距离。若最终 SHUT 控制不可用，可另选总线开关或重新分路，不能直接让四个 0x29 同时在共线上应答。

共享启动过程为（控制电平和上电默认态须在电路冻结前确认）：

1. 电平适配电路先保证四个 XSHUT 都处于低电平。
2. 只释放第一块，等芯片启动，再按 ST 初始化流程把七位地址改为 0x30。
3. 依次释放其余模块，改为 0x31、0x32、0x33，每次确认应答。
4. 完成校准/测量设置后，读取距离、状态和数据年龄；失败时显示无效，不能保留旧距离当成最新结果。
5. 传感器掉电/复位后地址恢复默认，需要重新执行分配。遇到总线异常，应先禁用移动，再恢复传感器。

上述共享方案使用 SCL/SDA 两根线、四根 SHUT，共六根 IO；IMU 加到同一 SDA/SCL 不再新增总线引脚，只有 INT 另占一根。地址管理依据 [ST 多 VL53L0X 应用说明 AN4846](https://www.st.com/resource/en/application_note/an4846-using-multiple-vl53l0x-in-a-single-design-stmicroelectronics.pdf)。先以 100kHz 调通，再看线长和上升时间是否适合 400kHz。四块都带上拉时电阻会并联，例如四个 4.7kΩ 合起来是 1.175kΩ；再接 IMU 还可能多一组，必须核对所有模块电路、总线电容及允许的灌电流。

用户提供针脚名称仍不说明 VIN 允许电压或模块稳压/电平转换。裸 VL53L0X 供电和 IO 规格不能直接代替整模块规格。SHUT 应通过符合模块 IO 电压的电路控制；适配电路必须在 FPGA 尚未配置、复位或逻辑断电时默认把四块关断，完成地址分配后才启用正常采集；不能只靠 RTL 拉低，也不能假设一个下拉必定压过模块上拉。供电及默认控制方式确认后再定器件，不能只加一个未知电压的上拉就接入。

测量不是只读一个寄存器就结束：还要移植 ST 初始化、校准、测量预算、状态读取等流程。文档正文默认预算为 33ms，不同模式会不同；第一轮明确设定预算，并实测四块的有效更新率。标称“2m”有反射率/环境条件，不能作为黑色物体、强光等情况下的可靠保证。四角视场交叉时还要检查光学互扰，必要时错开启动测量。

### 11.2 新版 HC-SR04（CS100A）：先考虑 3.3V 供电

本地文件为《72366 HC-SR04 最新版 超声波测距模块 宽电压3-5.5V 工业级 传感器.pdf》。它支持 **3～5.5V**，不能直接套老版 HC-SR04 的必须 5V 接法。第 3 页按图示方向的四针是 VCC、Trig、Echo、GND。

本期拟采用 3.3V 模块电源；先核对实物版本和 Echo 实际电压，再接 FPGA。手册没有给出 Trig 的高低门限、Echo 的高低电平保证值，因此不能把“3.3V 供电”写成未测量的直连保证。

时序先设计为 Trig 高 20µs，捕获 Echo 上升/下降沿，按往返时间计算距离。两次触发间隔采用 **至少 70ms**，等回波结束或超时后才进入下一次。无回波时可能输出约 66ms 的脉冲，要判无效，不能把它换算成约 11m 的有效距离。温度会影响声速，第一轮用手册 340m/s 换算并注明条件。

如果最终用 5V 供电，Echo 要经过合适的分压或 5V 容忍缓冲；例如按规格选用 3.3V 供电的 [SN74LVC1G17 施密特输入缓冲](https://www.ti.com/lit/ds/symlink/sn74lvc1g17.pdf)，核对输入门限和掉电行为。Trig 也要满足模块门限。**不要给 3.3V Echo 无条件使用 5V→3.3V 分压器**，否则高电平可能被压得过低。

### 11.3 LSM6DSV16X：例程中的 SPI 属于 OLED

你确认的正确例程是 `Examples/lsm6dsv16x-oled-hardware-spi`。已核对 main、syscfg 和驱动：IMU 使用 **I²C**，SPI 是 OLED 的接口，不是 IMU 的接口。TI MSPM0 的 PB2/PB3/PB9 不适用于 FPGA，当前共享方案使用 P7 1/2 的 SCL/SDA、15 的 INT；13/14 保留为可选独立总线。

| 例程设置 | 核对结果与移植方式 |
| --- | --- |
| 地址/器件 ID | 七位地址 0x6A；WHO_AM_I 寄存器 0x0F，应读到 0x70 |
| 接口 | I²C，原例程配置 1MHz；第一轮 FPGA 调试可从 100/400kHz 开始 |
| 量程 | 加速度 ±4g、陀螺仪 ±2000dps，可作为初始配置参考 |
| 更新率 | 加速度/陀螺仪 60Hz；不是 FPGA 轮速控制必须同步降为 60Hz |
| 姿态相关 | 启用芯片内置 SFLP 60Hz，FIFO 连续模式；例程解析四元数后转欧拉角 |
| 中断 | INT2 为加速度数据就绪脉冲，读数据/FIFO 的条件仍按例程与手册处理 |

裸芯片 VDD 为 1.71～3.6V，VDDIO 为 1.08～3.6V，见 [ST LSM6DSV16X 原厂手册](https://www.st.com/resource/en/datasheet/lsm6dsv16x.pdf)。I²C 模式要求 CS、地址选择脚正确设置；0x6A/0x6B 取决于地址选择。确认模块稳压器、上拉和焊接配置前不能直接把供电针接 5V。

用户给出模块仅一个 INT 和一个 SA0：SA0 为地址选择，不是另一条数据线；按模块电平固定为低/高，分别选择 0x6A/0x6B，不悬空。CS 未引出，仍需核对模块自身的 I²C 模式配置。例程使用 INT2，不足以证明模块上丝印 INT 一定对应 INT2；若实际连 INT1，后续软件中断路由应相应调整，而不是凭文件夹名接线。

先交付“读 ID、配置、读取六轴原始值、状态与时间戳”，然后验证 FIFO/SFLP。C 例程中的浮点四元数/欧拉角计算不能原样变成 Verilog；姿态显示可选择软核计算、专门定点实现或香橙派计算，按实际资源和工期决定，不预先承诺已经完成。

内置 SFLP 的融合由 IMU 完成，不归功于 FPGA；六轴无磁力计，yaw 是相对航向、会漂移。移植时补上 I²C 返回值、初始化/复位超时、失败状态，不照搬无超时等待。保留原始 16 位六轴数据或 32 位 mg/mdps，避免原例程转成整数 °/s 后丢失小角速度精度。总线恢复也采用开漏释放/拉低，不能用推挽 SCL 顶住模块。

### 11.4 为什么传感器可以共用，两个 BQ 暂时分开

把 I²C 理解成“大家共用的一条小路”，地址是门牌；地址不同只是能区分谁应答，不保证线长、电压、速度和故障行为合适。

共线是常规接法，STM32 和 FPGA 都能采用。每个模块接口都标 SDA/SCL，只表示它使用 I²C，不意味着必须配一条独立总线。扩展板可把各口的 SDA 接到 SENSOR_SDA、SCL 接到 SENSOR_SCL，配置合适的上拉/电平适配后由一个主控按地址访问；不要让多个控制状态机同时驱动这一组线。分别测量和轮流传输是两回事；共享总线要做调度，但无需为了读取一块的测量结果而停止其他芯片内部测量。

| 设备 | 首版选择 | 能否共享及理由 |
| --- | --- | --- |
| 四个 TOF200C | 共用传感器总线，SHUT 分别控制，改为 0x30～0x33 | 用户确认 SHUT 引出后采用常规逐个改地址；上电全为 0x29，不能未经初始化就同时访问；复位后重新分配 |
| LSM6DSV16X | 接到同一传感器总线，SA0 固定，地址 0x6A/0x6B，INT 独立 | 与 TOF 新地址不冲突；共享降低接口数量。以后总线负载/故障影响不合适时，可利用预留 13/14 再分开，不把分开当成必须 |
| BQ A / B | 各一条，均0x55，原生I²C条件直连 | 固定地址不能改成 0x40/0x41。若以后共用主总线，必须加通道选择，MUX不能替代地差预算，也不允许短接BAT−/PACK− |
| CS100A、两路霍尔 A/B | TRIG/ECHO、四路脉冲输入 | **都不是 I²C**，不能接 SCL/SDA；按边沿/脉宽采集 |

初始总线频率先用 100kHz，共线 IMU/TOF 采用双方都支持的速度，波形验证后可整体升到 400kHz，不能因为 IMU 示例为 1MHz 就把 VL53L0X 也带到 1MHz。BQ 手册第 8 页允许最高 400kHz，并要求 STOP 到下次 START 的总线空闲时间至少 66µs；有重复 START 的读事务按专门时序处理，不能把通用快速 I²C 控制器原样套用。[BQ I²C 时序与地址](https://www.ti.com/lit/ds/symlink/bq34z100-g1.pdf)

每条总线核对模块自带上拉，再选择系统上拉；两侧电平转换/隔离时各自计算。上拉太小会让器件拉低时电流过大，太大让信号上升太慢。可用 `Rmin=(Vpullup−VOLmax)/IOL`、`Rmax≈tr/(0.8473×Cbus)` 检查边界，最终看波形；这两个公式仍需要器件和电容数据，不能凭固定“4.7k”通用装配。传感器电源来自主支路，I²C 上拉不承担模块供电。

首版不新增 SPI IMU 驱动；六轴 IMU 的姿态融合仍来自 IMU/后续计算，不表示 FPGA 已有绝对航向。为防触摸/相机总线被外设拖死，扩展总线不直接拼到原板 GT911、摄像头或板载 RTC 的现有总线上。

### 12.3 保护、去耦与回灌：每种器件承担明确任务

| 电路功能 | 拟采用的处理 | 不能代替的功能 |
| --- | --- | --- |
| 接线短路/线缆过载 | 近每块电池正极放总保险，分支保护；按线径、额定/峰值电流、直流分断能力和 I²t 选型 | 普通保险/PTC 通常太慢，不能保证 TB6612 不被短时峰值损坏 |
| 反接 | 带方向防呆的连接器＋经过核算的 MOSFET/反接保护电路 | 单 MOSFET 体二极管不保证反向电流阻断，保护不能只看正接压降 |
| 电机过流 | VM 支路增加快速限流/过流锁存，高侧开关默认关闭，故障同时撤销 STBY | TB6612 热关断不是可设定限流；BQ 的慢速电流数据不能担当逐 PWM 周期保护 |
| 板卡输出过压 | 5V/9V 模块优先选有 OVP/限流/温保者，必要时外加受控断开 | 降压器故障可能让输入到输出，额定“5V”本身不等于故障时保护 |
| 供电局部瞬变 | 核对 TB6612 模块上 VM/VCC 各自 10µF＋100nF，靠近芯片；扩展板 VM 口预留额外储能位置 | 大电容不能修正过流、电平错误或接地旁路 |
| 减速/反转回灌 | 核对电池/BMS接收能力、开关反向路径，必要时主动制动能量支路；TVS 仅在窗口和能量合格后使用 | 普通 buck、保险丝、反接保护都不自动吸收回灌 |

快速过流电路可用“高侧电流检测＋比较器＋故障锁存＋高侧关断”，或选适合的 eFuse/控制器；是**TB6612 外部保护，不更换驱动**。VM 总电流只是两通道合计，而且 H 桥短刹/PWM 续流时电流可能在桥内循环，不能把 VM 测量宣称为两相独立限流。若要求逐路保护，需要两路输出电流检测（或适合 PWM 共模的霍尔/放大器）及相应关断链，不能在现成模块已共接 PGND 时随意塞两个低侧电阻。阈值、延迟、启动容许时间按实际模块热条件和电机波形选，留出正常启动空间，同时满足驱动峰值时间限制；未定这些参数前不做持续堵转实验。

电容初始可预留 100～470µF 的 VM 储能封装，数值是调试起点而非定案。按纹波、温度、ESR、直流偏压衰减、耐压、浪涌充电和保护开关能力选型。原厂 VM/VCC 的局部参考电容见 [TB6612 手册第 7 页](https://toshiba.semicon-storage.com/info/docget.jsp?did=10660)。降压模块的输入/输出电容必须符合其手册的稳定性要求，不能换成“越大越好”。

对 TB6612，TVS 应同时满足正常最高电压不误导通、实际浪涌电流下的钳位电压加走线尖峰低于器件耐压并有余量，还要核算脉冲能量和重复发热。12.6V 正常电压与 15V 绝对最大之间窗口很窄，**本轮未选出可保证满足窗口的 TVS**。禁止仅按“12V TVS”文字选料；必要时调整 VM 供电/制动能量策略，再核算。急停开断或 BMS 断开后电池可能无法吸收能量，负载侧电容和钳位仍须存在，不能靠上游电池兜底。

电机 M+/M− 绞合，编码器线与地配对，避开像素排线和 I²C；电刷抑制用小陶瓷/RC 吸收位置按测量选择，不在可反转的两端随意并单向续流二极管或大电解。FPGA 输出预留发送端串联阻尼电阻，输入可选掉电保护/5V 容忍的施密特缓冲，器件门限核对后定；串联电阻不是电平转换。

### 12.4 默认禁止启动与独立急停

规划两个层次：FPGA 负责命令时效、传感器有效性、速度限制和编码器控制；**板外硬件电路直接决定是否给驱动许可**。硬件急停不等网络、LCD 或 FPGA 时钟执行代码；目前均未实现，也不声称达到某个安全等级。

```text
PERMIT = MOTOR_REQ AND ARM_LATCH AND NC_LOOP_OK
         AND POWER_OK AND WATCHDOG_OK AND NOT OC_FAULT
VM_ENABLE = PERMIT
STBY_HW = PERMIT AND VM_SETTLED
```

这是一条原理图逻辑要求，不是已经写好的代码。常闭急停许可回路断开（按急停、插头拔掉、断线）直接异步清除 ARM_LATCH、拉低 STBY；比较器过流、欠压/看门狗超时同样清除锁存。VM 高侧开关使能也受硬件锁存约束，默认关断，不靠 FPGA 输出维持安全默认态。门控/锁存选有确定上电状态的器件，配置电源监控与外部电阻。

POWER_OK 检查逻辑电源和开关前的动力电源；VM_SETTLED 来自开关后的电源良好检测/规定稳定等待。先开 VM、确认稳定后才释放 STBY，故障时两路许可立即撤销；不能用尚未开启的 VM 作为 POWER_OK 唯一来源形成启动死锁。稳定等待及关断顺序待选开关/模块后核对，不能只连接一个与门就宣称完成电源时序。

| 状态 | 硬件必须出现的结果 |
| --- | --- |
| FPGA 未配置、复位、插头脱落、逻辑电源未稳定 | MOTOR_REQ、PWMA/B、方向经外部下拉；STBY=0，VM 开关关闭 |
| 控制更新停止/FPGA 时钟停止 | 外部看门狗超时，锁存禁止；心跳只能由完成有效控制周期的状态机更新，不能另起永远翻转的计数器假装系统健康 |
| 急停、过流、欠压 | 不等 I²C/网络，硬件先撤销 STBY 并关断许可；输出高阻滑行，实际停车距离需测 |
| 急停释放、网络恢复、电压回升 | 锁存仍禁止；不能恢复旧 PWM 或旧运动命令 |
| 重新启动 | 故障消除，命令新鲜，FPGA 确认零输出；人工 ARM 边沿仅在 MOTOR_REQ=0 且硬件健康时允许，随后新的启动请求才放行 |

ARM 用扩展板本地按钮/许可电路，不必增加 P7。P7 27 读取 SAFE_OK，40 送控制心跳。外部看门狗并不能保证检测任意 FPGA 内部错误，但能覆盖控制停止/无心跳；常闭回路加锁存也不能检测所有短接故障，应按测试边界表述。

STBY=0 是高阻待机，**不是主动刹车，也不保证车轮立刻停**。PWM=0 且 STBY=1 的某些状态是短刹；不能把这两者混写成同一种停止。正常减速可用斜坡/经核实的短刹，失控急停优先撤销许可。VM 开断时序、回灌、惯性、坡面运动须核算和实测；若需要机械保持，另加机械机构。

必须检查成品模块是否把 STBY 固定拉高；若固定高，未经适配不能宣称硬件禁能有效。急停触点只承受许可回路小电流；切 VM 用额定 DC 电流合格的功率开关，不让细信号开关承受电机电流。逻辑 A 电源在急停时保留，以便显示原因和香橙派正常关机。

## 13. 两颗 BQ34Z100-G1的采样与接地依据（最新引脚说明见第23节）

### 13.1 功能和电池参数

**本节保存BQ34Z100-G1的BAT−侧参考接地依据；2026-10-07用户重新确认该芯片，14脚说明与接地适用条件见第23节。此前将隔离作为首版前提过于保守，现已取消ISO1640，修正依据见第26节；第13.2的采样分域继续保留。**此前INA226不是当前自动采用方案；本次INA3221建议来自用户明确允许重新推荐，并与专用SOC电量计区分。BQ 是电量计，用电压、电流、温度和电池模型估计 SOC；不是充电器、BMS、均衡器或电机快速保护。不能直接沿用 INA226 模块针序/电路。

每块电池独立一个 BQ 和一只分流，分别记录 A（计算/显示）和 B（动力），不能用一个芯片把两块独立电池当同一个包。3S 的串联不把容量变成 8400mAh；2800mAh 是现有标签值，实际有效容量和截止条件需验证。BQ 测的是整个包，不能由总电压推断每一节都没有过放，原电池 BMS 仍要保留。

### 13.2 低侧分流与共地：BAT− 和 PACK− 不能混用

每路拓扑如下。这里的 BAT− 指接入该电量计的电池包输出负极；若包内有 BMS，不擅自拆包接电芯负极或绕开 BMS。

```text
电池包正极 ─ 总保险/反接保护 ─ PACK+ ─ 分支保护 ─ 全部负载正端
                                                     负载负端
                                                         │
电池包负极 = BAT− ── [本路 R_SENSE] ── PACK− ───────────────┘
                     │              │
                 Kelvin SRP     Kelvin SRN
                     │              │
                     └── 对称输入滤波 ── BQ

BQ 的低电流 VSS/采样参考 → 本路 BAT− 的 Kelvin 取点
系统 SYS_GND             → 本路 PACK−
```

**A 的 PACK− 与 B 的 PACK− 在计划的系统电源分配处连接为 SYS_GND；A/B 的 BAT− 不另接系统地，也不互相直接连接。**FPGA、香橙派、TB6612、编码器和普通传感器全部使用 SYS_GND。电机高电流沿 B 的本地粗回路到 PACK−_B、经 R_B 回 BAT−_B，不通过 P7 地脚或 FPGA 板卡。控制参考地连接可靠，不能让唯一共地路径是杜邦线、USB 外壳或网线屏蔽层。

采样地属于另外的功能域：本参考采用TI的BAT−侧方案，BQ低电流地在分流的 BAT− Kelvin 点单点连接，SRP 靠 BAT−、SRN 靠 PACK−；这不等于把整车模拟地随意切开。每个地符号明确命名 `BQ_A_GND/BQ_B_GND` 与 `SYS_GND`，不可全部命名 GND 后被 PCB 自动短接。依据 [BQ 数据手册第 3、54～56 页](https://www.ti.com/lit/ds/symlink/bq34z100-g1.pdf)及 [EVM 第 5 页接线、第 20 页原理图](https://www.ti.com/lit/ug/sluu904/sluu904.pdf)。

若把 BQ 模块 GND（BAT− 侧）用普通四针线接 FPGA GND（PACK− 侧），它会提供分流的并联通路，使电流测错，甚至让细信号线承受电池电流。USB 转串口、EV2400、台式电源负端、示波器接地夹、充电器和金属机壳也可能造成同样旁路。**两条独立 I²C 只解决同地址；不自动解决地旁路。**

### 13.3 通信和供电域：原生I²C条件直连，本路LDO保留

BQ34Z100-G1原生支持I²C，本版取消ISO1640。A/B分别由P7候选7/8和38/39连接各自SCL/SDA，两组各自上拉至SYS_3V3。FPGA只拉低或释放，读回SCL处理拉伸；BQ配置No LED，避免通信脚被改作LED输出。不额外连接BQ_GND与SYS_GND，两地通过本路分流获得参考。该P7预算不代表已写CST/驱动。

本版以两端最坏充放电及瞬态的`|ΔGND|≤50mV`为候选地差目标，含分流及回流铜箔压降；另叠加输出低电平及信号走线压降核对双方VIL/VOL和引脚允许范围，具体见24.2。该目标不是已验证电流额度，电机尖峰与采样滤波不会自动消除通信地差。达不到预算时须重新选择分流/回流或审查适合接口，不凭有无隔离芯片判断整机抗扰已通过。

BQ前级稳压仍由本路电池正端（经保护）及BAT−供电，REGIN用本路TPS70933输出，REG25自用并去耦。SYS_3V3只用于总线上拉；不得将本地LDO输出并联到系统3.3V，也不得用一根系统地线短接分流。BQ、LDO和固定分压的BAT侧自耗不经过分流，仍需核算待机误差。现在没有隔离器电池侧的持续mA级负载。

两颗七位地址均固定0x55，写/读地址字节0xAA/0xAB；独立总线仍占四根GPIO，本期不用MUX。若以后用MUX，逐次只选一颗，其通道选择不能替代地差预算或防止地旁路。上拉只用可掉电SYS_3V3，任意缺电池/热插拔状态尚待验证。

### 13.4 分压、分流和模拟前端

| 电路 | 本期要求 |
| --- | --- |
| REGIN | 正常工作输入 2.7～4.5V，3S 需前级稳压；12.6V 禁止直接接 REGIN；REGIN 近端 100nF，REG25 按引脚/应用图用 1µF 核对，不按布局概述中的不同值随意换 |
| BAT 电压采样 | 采用 TI 多串电池外部分压/转换，并配置 VOLTSEL、串数和 Voltage Divider；BAT 测量 ADC 域为 0.05～1V，不能因引脚绝对最大 5.5V 就把 BAT 接 3.3V 或 12.6V |
| VEN | TI 分压开关控制输出，按参考图设计；不是自由 FPGA GPIO，不为省事随意短接 |
| R_SENSE | 每块单独低侧分流；`V=I×R`、`P=I²×R`，同时满足差分 ±125mV、热/瞬态、压降、零点分辨率和精度；优先低温漂四端采样电阻，不能仅照抄 EVM 的 10mΩ |
| SRP/SRN | 从电阻两端独立 Kelvin 细线引出，对称滤波放近 BQ；功率流不能穿过 Kelvin 小焊盘或细线 |

BAT 分压可用 `Vbat_pin=Vpack×Rlow/(Rhigh+Rlow)` 初算，但最终按 TI 转换电路、开关漏电、ADC 负载、最高正常/故障电压、容差及校准因子选值；不能只凭理想分压比例冻结。R_SENSE 举例：10mΩ、6A 时为 60mV、0.36W，只说明如何算，不是允许两台 TB6612 通道持续跑 6A；实际分流、电池和保护的裕量另外审核。

充电器接系统侧 PACK+/PACK− 才能让充电电流经过分流，且须是适合该 3S 电池/BMS 的充电器；若电池有独立充电口且接在上游，会漏计充电。当前端口拓扑未知，第一版先按断开外部调试地的方式审查充电回路；不能把 BQ 当充电控制器，也不能直接改电池包线。

### 13.5 SOC 配置和学习流程：焊好不等于电量准确

按 [BQ34Z100-G1 技术参考手册，附录 D](https://www.ti.com/lit/ug/sluubw5/sluubw5.pdf)规划：核对 3S/电池化学体系和容量参数、截止条件与硬件分压；校准电压、零电流偏置和电流增益；确认 NTC；根据电芯/日志选 ChemID；按 TI 的充放电与静置要求完成学习，再检查学习状态与独立放电测试，保存适用于该硬件的配置。

两块电池各自校准/学习，不能默认所有电池误差一样。学习用合适充电器、受控负载、仪表和明确截止条件，不用车轮堵转充当放电设备。EV2400/bqStudio 为计划中的调试工具，尚未确认持有；也没有完成 ChemID、学习或可发布的 SOC 精度数据。

BQ 的电流转换时间约 1 秒，适合电量统计，不是电机短路保护速度。SOC 尚未验收时显示“未校准/学习未完成”，可先验证 V/A/温度/状态是否合理；不凭包电压线性映射出一个看似精确的百分比。

### 13.6 低电提醒与香橙派正常关机（计划）

电池 B 低电：禁止运动并锁存原因，逻辑 A 保留供电。电池 A 低电：先停车，再由 FPGA→香橙派发送带版本/序号/原因的关机请求，香橙派停止采集、保存文件、执行系统正常关机。阈值依据 BMS、稳压器最低输入、压降和实测关机时间制定，包含持续时间/迟滞与足够余量，不等 BMS 已断电才通知。

```mermaid
flowchart TD
  SAMPLE[BQ 电压电流状态及数据年龄] --> LOW{低电持续成立或数据异常}
  LOW -->|否| SAMPLE
  LOW -->|是| STOP[撤销运动许可并锁存原因]
  STOP --> BAT{是逻辑 A 低电吗}
  BAT -->|仅动力 B 或传感异常| WARN[保留计算电源并提示处理]
  BAT -->|逻辑 A 低电| REQ[关机请求与确认重发]
  REQ --> SAVE[香橙派停止任务并保存]
  SAVE --> SHUT[系统正常关机]
  SHUT --> KEEP[保持电源等待人工确认后断开]
```

请求 ACK 仅表示收到，不等于 Linux 已关完；首版不自动切香橙派电源。未来自动切电须有可靠完成判据、功率开关和断线/超时策略。当前 32 字节 UI 状态包、视频协议、客户端和 RTL **没有实现低电关机**；后续新增独立消息，不随意改变已跑通的 802 字节图像行格式。逐渐低电可以提前处理，拔插头/保护突断不能靠通知保证关机完成。

## 14. 电感、电容、LC 和 TVS：用学生能理解的方式说明

电容像靠近用电点的小水箱，电压突然变化时能短时吸收/补充电荷；小陶瓷处理快变化，大储能电容处理较慢的电流需求。粗估 `ΔV≈I×Δt/C`：若要用 1000µF 给 2A 负载支撑 1ms，理想情况下仍会掉约 2V，还没算 ESR。因此“大电容”不能保证香橙派不断电。它有浪涌、纹波发热和耐压要求，也不能无穷吸收制动能量。

电感像抗拒流量突然改变的部件，电流变化越快，它产生的电压越大：`V=L×di/dt`，储能 `E=L×I²/2`。降压器靠开关、电感和反馈把高电压变成稳定低电压，不能把电感单独当“降压元件”。电机绕组和长线本身也有电感；开断电流却不给能量出路，正可能产生尖峰。

| 元件/组合 | 可以做什么 | 设计时必须注意 |
| --- | --- | --- |
| 去耦电容 | 缩小芯片附近高频供电回路 | 放置比单纯增加容量重要，长细线使它来不及供电；两端接正确参考地 |
| 串联电感 | 配合电容抑制某些频段噪声 | 额定电流、饱和、直流电阻、发热；大电流饱和后滤波能力变化，输入电流阶跃可能增大压降 |
| 磁珠 | 在一定频段提供损耗抑制高频噪声 | 它与理想电感不同，规格要看频率和偏置电流；不能作为保险或万能电机隔离 |
| LC 滤波 | 对一定频段形成低通，`f0=1/(2π√LC)` | 有谐振；低 ESR 电容可降低阻尼，和 buck 的控制环/输入负阻抗互相影响。按模块手册/阻抗和波形决定是否加阻尼，不先塞一组 LC |
| TVS | 对有界的瞬态过压进行钳位 | 不是稳压器，实际钳位高于标称；看工作/击穿/钳位电压、浪涌波形、重复能量和走线电感，不能长时间吞下制动功率 |

能量核算可用 `Ecap=½C×(Vhigh²−Vlow²)`：电容只允许很小的电压涨幅时能吸收的能量也很小。把 VM 正常电压、驱动允许峰值、负载惯性能量及电源是否可回吸放在一起计算，再选电容/钳位/制动支路。当前不确定电源和电机波形，LC/TVS 只保留可评估的位置，不视为已通过的保护。

## 15. PCB 放置与布线原则（供下一步原理图评审使用）

**目前没有完成的 PCB 文件，也没有 Gerber 或已选定板层/铜厚。**下面是布局约束，不能当生产图。优先四层用于连续系统参考地和布线；若成本要求两层，先验证地铜连续性和功率回路，不凭“两层够用”跳过检查。

| 区域 | 放置与走线 |
| --- | --- |
| 电池/动力区 | 电池端子、保险/反接、高侧开关、VM 大电容、TB6612 座、电机端子靠一侧，缩短大电流路径；宽线/铜皮、多过孔的载流能力按铜厚、温升和电流计算，不预先写死一个线宽 |
| 电机高频回路 | 去耦正端→VM→H 桥/电机→PGND→去耦负端尽量紧凑；PWM 续流也在本地区域闭合；再用粗分支回 PACK−_B 和分流，避免绕一圈经过 P7 |
| 降压区 | 靠输入/输出端子布置，开关“热回路”紧凑，SW 铜面积小，反馈远离电感/SW 和电机线；不能把多个功率模块挤在 IMU/BQ 边上 |
| 系统数字区 | P7、输入缓冲、总线适配、独立门控/看门狗靠近；SYS_GND 作为连续参考，信号尽量不跨地缝，换层旁放参考地过孔；ESD 回流在接口附近安排 |
| IMU 区 | 机械上靠车体稳定位置、离电机/减速箱振动和发热源；轴向丝印固定，局部去耦与短 I²C，避免安装孔、板弯及大电流热源影响；位置不是单纯“离所有东西越远越好” |
| 两个 BQ 采样区 | 各靠近本路分流，分流靠动力回路而 BQ 靠安静一侧；远离热源/开关节点。各自低电流地按 TI 在 BAT− Kelvin 点单点连接，系统 PACK− 铜不跨接到采样岛 |
| Kelvin/电压/NTC 模拟采样 | 电阻焊盘内侧直接取 SRP/SRN，对称并行短线，滤波贴近输入，避开 PWM、SW/时钟；电压分压与基准回到所属采样域，不从载流铜末端随便取地；NTC 线远离电机线 |
| 模块和云台接口 | 带方向/锁扣、供电丝印、可断开连接；大电流电源与控制分开。传感器总线分支尽量短，长线增加电容，避免把车角杜邦线随意串成环；舵机/步进和共享/独立 IMU 的选配方式标在丝印/装配表上 |

普通逻辑/IMU 的“模拟区和数字区”主要靠摆放和回路管理区分，**不为了抗干扰随意切 SYS_GND**。本版BQ的BAT−/PACK−分域用不同网名和受控铜皮保持，仅经分流连接；这不等于必须安装通信隔离器，不能用“整板必须一片地”又把分流短接。这两个原则不矛盾。[TI 电机布局指南第 3～7、19～22、30～34 页](https://edgeworker.ti.com/lit/pdf/slva959)

P5 原板 AGND 已有自己的连接方式，转接时按图保留，不把它拿来作电机功率地或 BQ BAT− 跳线。SDA/SCL按第24节短线连接及门限预算布线，避免共享电机回流和参考地骤变；供电、地铜、安装金属和仪器地不得形成绕过分流的通路，不靠随意切系统地抗扰。

制造前先审核封装、实物排针方向、孔径、连接器额定电流、安装高度、螺丝/支撑柱导电关系，以及 LCD/相机/网口插拔空间。原理图 ERC 和 PCB DRC 能找部分错误，不能替代接地拓扑、回灌和热设计人工检查。后续实际画板才执行这些检查，本轮没有跑过 ERC/DRC。

## 16. 借到万用表后的接线与通电检查

用户预计能借到表，借到之前保持纸面设计。万用表先验证静态电压/接线；它通常看不到微秒尖峰、PWM 电流和控制延迟，这些最终需要示波器/逻辑分析仪及合适测量方式，不能因为静态电压正常就宣布抗干扰合格。

| 阶段 | 必须检查/测量 | 未满足时的处理 |
| --- | --- | --- |
| 全部断电、电容放完 | P7/P6 Pin1 与相邻脚，DC 正负极；各电源无硬短路；模块针序可确认；各负载地到 PACK− 的连接及不存在额外 BAT− 旁路 | 表的蜂鸣档会对毫欧分流和并联铜线都响，**不能单凭蜂鸣证明无旁路**。分流边界/USB/仪器地逐线检查，必要时在装配前断开设计测试连接做通断核验 |
| 先只测降压器，不接主板/模块 | A/B 包端电压；9V/5V/3V3 输出与极性；换输入电压/受控负载时是否保持目标；测接收端电压而非只测模块端 | 未核对型号、输出/热能力和保护前不接香橙派或 FPGA；调压电位器设好后固定 |
| 单独给 ACG720 正确电源 | TP5/VCCIO 约 3.3V，P7 11 的 5V 与 29 的 3V3，基于原板功能核对 | P6 不匹配不接 GPIO；不修改已验证的视频约束去“适应”未知供电 |
| 单模块低风险测试 | V_TOF/V_IMU/V_US/V_ENC，空闲 SCL/SDA 上拉电压，Echo/霍尔可能输出的电压，模块掉电时有无倒灌 | 万用表不足以测门限或瞬态：核对器件规格，必要时示波器确认；不明 5V 输出不直接 FPGA |
| BQ 各路单独测试 | REGIN 在允许范围、REG25 约 2.5V、BAT 分压在测量域；已知电流下 SRP/SRN 极性与幅度、无电流偏置；BAT−/PACK−无分流旁路，检查最坏充放电地差、I²C高低电平和掉电状态 | 校准用准确电压/电流参考；共地仪器不得跨分流。表的电流档不能直接跨电池正负测电流 |
| 不接电机先查禁能 | FPGA 未配置/复位/急停断开/心跳停止时 STBY 低、VM 开关禁止；ARM 不会自动恢复旧请求 | 任何状态会误使能，先修电路，不能靠“上电后赶紧点停止” |
| 架空电机、限流电源、低占空比 | 单轮再双轮，编码器方向/计数，启动电流、温升、实际电平，急停/看门狗/失联行为 | 不做无监控持续堵转；逐步加负载，峰值/回灌看示波器，未验证不落地自动跟随 |

最少要测：两块包端电压、5V/9V 支路输出与板端压降、3V3/VCCIO、传感器/编码器供电与上拉、TB6612 VM/VCC/STBY、BQ REGIN/REG25/BAT 和已知电流下分流压降。记录测量条件和结果，不能把“计划测量”写成已测。

接示波器时先查探头地是否接大地，多路探头地通常内部相连；普通接地夹不能分别夹 BAT− 和 PACK−。根据拓扑用合适的差分/隔离测量设备，不随意断开仪器保护地。EV2400/USB 配置时也先审核是否形成分流旁路，必要时断开系统其他接地连接或采用经过确认的隔离方式。

## 18. HC-06、实时速度曲线、记录回放与局域网

### 18.1 LCD 曲线、DAC 电压和无线调参是三项独立功能

可以同时保留电脑 VOFA、板上曲线和无线启停，不必三选一。速度先从编码器得到数字量，送给 LCD/通信/记录；DAC 只是可选的另一种输出。变量统一写 `TARGET_SPEED` 和 `ACTUAL_SPEED`（实际速度），左右轮分别记录，不能只画一个总速度掩盖其中一轮的问题。

| 用途 | 数据怎样走 | 需要实现什么 |
| --- | --- | --- |
| 电脑 VOFA 实时调参 | 编码器→测速/PID→UART→HC-06→电脑蓝牙虚拟串口 | FPGA UART、遥测编码、命令解析/反馈和超时处理；用户的 STM32 经验可复用 |
| 板上 LCD 实时曲线 | 同一组目标/实测数字值→历史点缓存→LCD 绘图 | 坐标轴、比例、两色曲线、图层/页面；**不需要 DAC** |
| 示波器观察模拟波形 | 数字速度→比例/偏置映射→板载 DAC→示波器 | DAC 驱动与电压校准；输出不直接让 LCD 出现曲线 |
| 短时回放 | 数字采样记录→片内 RAM 环形缓存→同一个 LCD 绘图器 | 记录/冻结/浏览状态机、读写缓冲和时间轴 |
| 长时日志/回放 | 数字记录→FIFO→SD 或香橙派文件→回放 | 文件格式、存储驱动、错误/断电处理；有插槽不等于已完成 |

实时性分三层：编码器/PID 的更新周期、遥测/记录采样周期、屏幕刷新周期。LCD 可以实时滚动，不天然比 VOFA 慢；真正的延迟取决于测速窗口、缓存、绘图和传输。电脑蓝牙也会有缓冲/抖动。控制不应等待屏幕、无线链路或 SD；不得把一帧 LCD 更新周期当成 PID 运行周期。

```mermaid
flowchart LR
  E[两轮编码器] --> C[测速与固定周期控制]
  C --> M[PWM及硬件许可]
  C --> S[带序号和时间戳的采样快照]
  S --> L[RAM历史点与LCD曲线]
  S --> B[UART和HC-06到VOFA]
  S --> N[未来网络遥测到香橙派或电脑]
  S --> F[日志FIFO到SD或香橙派]
  S --> D[可选DAC到示波器]
  Q[触摸或远程请求] --> A[命令仲裁与时效检查]
  A --> C
  X[独立急停和故障门控] --> M
```

### 18.2 HC-06 先复用原调试接口，不增加 GPIO

| HC-06 引脚 | 扩展板/FPGA 连接 | 边界 |
| --- | --- | --- |
| VCC | 受保护的 5V_LOGIC | 按用户这块模块的 5V 输入安排，含在 A 支路功耗中；不接电机 VM |
| GND | SYS_GND / PACK− 系统侧 | 不接 BQ 的 BAT− 采样域 |
| RX | FPGA_TX，P7 28 / C19 | 从 FPGA 发数据；实际 UART 逻辑电平核对后接 |
| TX | FPGA_RX，P7 31 / F16 | FPGA 接收电脑命令；不因 VCC=5V 就认定 TX 为 5V，也不未经核实假定安全 |

按用户已使用的 **115200** 设计，8N1 为待核对的常用候选，不把它说成这块模块实测配置。四针即可做双向通信；电脑配对后选实际出现的虚拟 COM 口。HC-06 没引出连接状态脚也能使用，但用应用心跳和命令年龄判断失联，不能用“UART 写出了字节”证明电脑在线。[HC 串口蓝牙厂商手册第 8～10 页](https://www.hestore.eu/en/prod_getfile.php?id=8279)

原 J_DBG 保留，J_BT 复用同一 UART：通过两路选择跳帽/开关选蓝牙或 USB 串口。FPGA TX 向多个接收端发送通常可行，但 **HC-06 TX 和 USB 串口 TX 都是主动输出，不能直接并到同一个 FPGA RX**。如果将来确需两路独立同时操作，再占两根备用并定义控制权；本期不增加 UART GPIO，仍为基础 28 根＋两舵机预留＝30 根、六根备用。

VOFA 首版建议四通道 FireWater 文本：左目标、左实测、右目标、右实测。FPGA 内部采用有符号整数/定点速度即可，不必为了画曲线先实现浮点 PID。可把输出轴 rpm×100 的整数发出，例如：

```text
d:10000,9800,10000,10100
```

每行末尾必须是真正的换行字节；上述例子分别表示 100.00、98.00、100.00、101.00rpm，VOFA 若直接画整数则标注单位为 0.01rpm，或由电脑转换量纲。将来需要小数文本，再实现整数转十进制与小数点插入。此为候选遥测格式，尚无发送源码。[VOFA FireWater 官方协议](https://www.vofa.plus/docs/learning/dataengines/firewater/)

115200、8N1 每个字节占 10 位，发送方向理论上限 11520B/s；若按每条含四速度的消息不超过 64B、50 条/秒预算，则最多 3200B/s，留出状态/确认余量。这里是 UART 预算，不是蓝牙实测吞吐/延迟；丢帧、缓冲和重连还需测。JustFloat 可减少带宽，但要求正确的小端 IEEE-754 浮点表示，不能把定点整数的字节直接冒充 float；先不为此引入浮点运算链。[VOFA JustFloat 官方协议](https://www.vofa.plus/docs/learning/dataengines/justfloat/)

遥测上行与控制下行分别设计。下行候选包括 STOP、START、左右速度、PID 参数、心跳；界面按钮发送命令后，FPGA 应回报已接收/已应用或拒绝原因和参数版本，不能只看按钮变色。具体帧格式、校验、序号和应答方式待冻结；参数整体校验后在控制周期边界一次应用，第一版仅停车状态改 PID，避免一半新参数、一半旧参数。VOFA 内置控件可发命令，但按钮字节格式仍要与 FPGA 解析器配套。[VOFA 官方接口与控件说明](https://www.vofa.plus/docs/learning/)

### 18.3 LCD 怎样画目标与实测速度

先做独立“轮速调试”页，不把所有曲线挤进相机页：左/右轮可选择，显示目标/实测数值、两色曲线、PWM、误差、停止原因、参数版本和样本年龄。GT911 触摸提供暂停图像滚动、选轮、横轴时间范围、纵轴量程和查看历史点；这些是界面方案，尚未写 RTL。

每次记录目标与实测的同一份快照，然后把速度映射成像素纵坐标：`y = 底边 − (v−vmin)×图高/(vmax−vmin)`，越界截断并标识。横坐标按样本时间推进，连续点连线；缺样本时保留空档，不把断流画成平滑正常曲线。用固定量程/可选量程，避免纵轴每次自动改变让 PID 波动看起来忽大忽小。

无需存每一幅曲线截图，只存数字采样点。优先片内 RAM 双口缓存：写口追加样本，读口供显示；跨时钟用快照握手/异步 FIFO，不能直接跨域读正在变化的多位速度总线。显示在帧边界锁存窗口/读指针，避免一帧上半和下半使用不同历史窗口。

超过显示宽度的历史区间，每个像素列可用最小/最大包络保留尖峰；少量点直接连线。仅每 N 点取一个可能漏掉短时过冲；快速 PWM 电气纹波仍需要示波器，低速轮速曲线不能代替。

示例预算：1024 条×32B＝32KiB；100Hz 记录可保留 10.24 秒，50Hz 可保留 20.48 秒。32B 候选记录为序号 uint32、相对时间 ms uint32、四路速度 int32（rpm×100）、两轮 PWM int16、状态 uint16、保留 uint16。控制周期/测速窗口/记录率各自制定，不因为画图而提高无新测量的“实际速度”更新率；样本要带测速有效性/年龄。该 RAM 预算需结合用户以后编译资源报告确认，不称已分配。

记录率高于无线显示率时，先完整记录，再选择合适的遥测率；丢遥测不能阻塞记录，记录满时按选定策略覆盖或报告丢样本。序号、时间戳保留在原始日志，VOFA 按到包点数画图不一定代表真实采样时间，做过冲/响应时间测量时以原记录时间轴为准。

### 18.4 RAM 与 SD 回放：记录数据，不自动重演动作

RAM 是短期历史，断电丢失；SD 是长期文件。原有 DDR3 主要服务相机/LCD，不能仅凭“有内存”就把日志任意写到其空白地址。先用独立片内缓存；以后真的扩到 DDR，要划定日志地址范围、增加仲裁与带宽验证，不覆盖图像缓冲或改动 DDR 校准。

回放复用同一个曲线绘图器，只把数据源换成历史记录：提供 LIVE/REPLAY 大字标识、暂停、拖动时间位置、原速/快放及真实记录时间；回放按记录时间戳，不能只按 SD 读取速度。首版进入 REPLAY 时禁止运动，历史目标速度/START/心跳只用于显示，**绝不作为当前电机命令或有效传感器数据**。看历史不意味着控制电路在重放当时的 PWM。

长日志先由电脑/香橙派落盘，之后再做板载 J8 的 SD 写入。SD/FAT 有忙等待和不固定的写延迟：控制采样→FIFO→块写，存储满/卡拔出/写错误时显示原因、统计丢样本，不阻塞编码器/PID或独立急停。按实测最大忙时间核算 FIFO，平均吞吐够不代表永不堵塞。日志文件按块带长度/序号/校验，尾部被断电截断时应保留此前完整记录。

首版采用候选固定长二进制记录，另加文件头：格式版本、单位/缩放、轮径/减速比/编码器换算配置、控制/测速/记录周期、左右 PID 与参数版本、起始时间和停止原因；参数变化作为事件记录。电脑端以后可导出 CSV，不要求 FPGA 同时实现 CSV 格式化和复杂文件管理。用 FAT 文件便于电脑读取但要有文件系统；若先做原始扇区日志，不能把它称为电脑直接可读文件。现有工程尚无 SD 写入/FAT 驱动，本轮不执行存储或驱动实现。

### 18.5 DAC 用来给示波器输出两路“速度电压”

本轮重读/目视核对官方原理图第 15 页：U40 是 **TLV5618ACD，两通道 12 位 DAC**，P3 1=OUTA、2=AGND、3=OUTB、4=AGND，三根串行控制为 DIN/SCLK/CS。官方 XLSX 对应 60K 球位 P5/P4/P2，与当前 CST 的已用球位无交集；这些是原板固定线路，不占新增 P7 引脚，尚未添加顶层端口/CST/驱动。

可选“左轮目标→DAC A、左轮实测→DAC B”，再切换右轮；两个通道不能同时独立输出左右四条曲线。DAC 输出模拟电压，外接双通道示波器/采集器才能观察，LCD 或 VOFA 接数字数据更直接。原板 TLV5618A 外部参考标为 LM4040-2.0，输出关系 `Vout≈2×Vref×D/4096`；参考实际电压、有效输出范围和负载须测后确定，不当成通用 0～3.3V 输出。[TI TLV5618A 数据手册](https://www.ti.com/lit/ds/symlink/tlv5618a.pdf)

若要表示倒车负速度，需加电压偏置，例如把 −vmax～+vmax 映射为经核实范围内的 1～3V；DAC 不会直接输出负电压。映射应标明零速电压、单位、饱和与更新率，实际模拟电压只有映射意义，不能拿来替代 PWM 驱动电机。P3 AGND 按原板接地，用示波器时仍遵守第 16 节 BQ/仪器地约束，不把地夹跨到 BAT−。仅为板上速度显示无需接 DAC，本期它是可选调试接口。

### 18.6 FPGA 网口可以用，无线局域网由香橙派转接

VOFA 官方支持串口和 TCP/UDP，可以保留同一个电脑工具。ACG720 本项目的网络是有线以太网，不因为有网口就具有 Wi-Fi；无线方案可让香橙派充当桥接应用：[VOFA 官方接口说明](https://www.vofa.plus/docs/learning/)

```text
电脑 VOFA/控制界面 ←→ 蓝牙 ←→ HC-06 ←→ FPGA UART

电脑 VOFA/控制界面 ←→ Wi-Fi/电脑热点 ←→ 香橙派应用
                                             │
                                    eth0 有线 UDP
                                             │
                                      FPGA 192.168.10.2
```

无线 LAN 是后续方案，需要香橙派开机和接收/转发服务，不是当前已验证链路。已有 FPGA→192.168.10.3:6102 图像不改；未来低带宽速度遥测新增独立包类型/端口候选（如 6103，尚未占用/实现），不把它伪装成 802 字节图像行或复用 32 字节 VUI1 定义。发送仲裁需保证新增遥测不会造成视频 FIFO 溢出，接收端独立解码/转发。

实际源码已有 UDP 5001 接收和 `VRB1` 八字节 UI 命令，电脑查看器向 192.168.10.255 发送请求；目前它处理滤波/UI/停止意图等，**没有电机速度/PID 控制、可靠命令确认或运动权限协议，停止意图不等于电机已停**。跨 Wi-Fi 后要由香橙派应用转发到 FPGA 有线网段，不能假设热点广播自动穿过路由；原实现使用广播绕开 FPGA 侧 ARP，未来单播/路由方案另审。

若电脑直接用网线接 FPGA，也可规划速度 UDP→VOFA＋命令返回；这无需香橙派中继但要接网线。蓝牙/UDP 只是载体，界面显示和控制协议可以相同，不必把有线局域网、蓝牙和 LCD 都做成不同套速度定义。

### 18.7 多入口不能互相抢控制，STOP 和失联独立处理

先只启用一个控制来源（本地调试、HC-06 或香橙派网络之一），其他入口可看遥测。模式切换时先停车并撤销旧目标，重新人工确认；不能网络断了自动切到蓝牙旧命令。任一允许入口的有效 STOP 可以撤销运动许可，START/速度/调参仅由当前拥有控制权的入口提交，受硬件 ARM 和健康状态约束。远程 START 不能清除常闭急停、过流或硬件禁止锁存。

通信调参首版先停车修改 PID，核对符号、尺度、范围、上限/积分限幅和版本，再统一应用。通用命令帧设计含明确类型/长度、合法值检查、校验、会话/序号以及实际应用确认，拒绝半帧、旧会话重放和重复启动。心跳/控制租约按本地单调时间判断，不能仅有遥测发出就判远端健康；例如 100ms 心跳、300ms 超时仅为待测试候选，最终按车辆风险/链路延迟确定，重连不自动恢复运动。

记录通信超时停车、停止请求处理延迟、实际车轮停止距离及视频满负载时控制抖动。蓝牙/LAN 的停止按钮用于操作，不能作为物理急停替代；外部门控仍不依赖上位机、LCD、SD 或 Linux。没有实测之前不承诺蓝牙延迟或本地曲线一定比电脑快。

### 19.2 源码做了什么

| 文件 | 行为 |
| --- | --- |
| `src/sensor_i2c_master.v` | 100kHz、开漏、重复 START 和连续读取；检查 ACK，事务 20ms 超时；必要时最多九个恢复时钟后 STOP，不会一直占住其它任务 |

| `src/cs100a_demo.v` | 50µs TRIG、触发间隔至少100ms；从触发开始逐时钟捕获Echo边沿；等待上升沿最多70ms、高电平最多70ms；完整约66ms无目标脉冲判无效 |
| `src/sensor_demo_commands.v` | 115200、8N1 UART 接收，同步和中心采样、检查起始/停止位；接受 P/F/S/N |

| `tools/watch_sensor_demo.ps1` | Windows COM 口查看、发测试指令，把实际收到的数据追加到 `dataset/sensor_demo.csv` |

IMU 是 **LSM6DSV16X**，参考实际用过的本地 `D:\M0\mspm0-modules-main\Examples\lsm6dsv16x-oled-hardware-spi\Drivers\LSM6DSV16X`。文件夹名的 SPI 属于 OLED。用户提供的 [DELIVERY_CAR_M0](https://github.com/Vera-loves-program/DELIVERY_CAR_M0) 本次公开访问返回404，不能据此判断工程完整性；不等待该链接，使用已有本地例程及 ST 寄存器定义。

初始化先写 `FUNC_CFG_ACCESS(0x01)=0x04` 触发全局复位，等10ms再有界轮询bit2清零，与本地C例程的全局复位一致；依据 [ST LSM6DSV16X官方手册第56页](https://www.st.com/resource/en/datasheet/lsm6dsv16x.pdf)。随后设置加速度 ±4g、陀螺仪 ±2000°/s、两者60Hz；`CTRL3(0x12)=0x44` 开启 BDU/地址自增，`CTRL6(0x15)=0x04`，`CTRL8(0x17)=0x01`，`CTRL1/2(0x10/0x11)=0x05`，每项配置读回检查。这款芯片的 ODR 编码与旧 LSM6DS3 不同，不能混用。WHO_AM_I 寄存器 0x0F 应为 **0x70（十进制112）**。原始数据从0x22连续读12字节：先gyro三轴，再accel三轴，均为小端有符号16位；完整burst一起发布，不宣称六轴严格在同一瞬间采样。

换算：**角速度 = gyro_raw × 0.070 °/s；加速度 = accel_raw × 0.122 mg**。加速度包含重力，静置时一根大致竖直的轴接近 ±1000mg，三轴合成约1g，不应要求静止时加速度全为0。角速度静置应接近0但有零偏；旋转后变化才是陀螺仪响应。轴符号取决于实际安装方向。**本次没有计算 roll/pitch/yaw，也没有完成SFLP融合或标定**。

超声单位是 mm，换算使用客服手册340m/s：`distance_mm≈echo_us×0.17`，并四舍五入。程序有效区间20～4500mm，温度、目标材质和角度会影响结果；标称范围不能保证任何目标都测得到。遥测快慢指令改变的是发送频率，不改变超声10Hz触发，也不改变IMU60Hz输出；样本计数用来识别重复报告。

| 指令 | 行为 | 回传确认 |
| --- | --- | --- |

### 19.5 超声无回波：客服截图核对与修订

## 20. 板载八位数码管实时时钟（2026-10-06源码接入，待上板）

### 20.1 为什么前几次烧录数码管始终空白

此前 `vision_robot_ui.gprj` 没有数码管扫描模块、RTC读时模块及这五个信号的约束，程序没有驱动板载74HC595。因此数码管空白有明确的源码原因，不能据此推断数码管损坏或“FPGA不能显示时间”。本次沿用同一工程接入，不新增独立工程。

已对照开发板原理图第9页、60K管脚表和官方第13/34章源码：板上U8是**BM8563T**，BT1为**CR1220**纽扣电池，两个四位数码管组成八位，通过两颗74HC595移位寄存器驱动。板载I²C已有4.7k上拉到3.3V，和P7的IMU总线是两组物理信号，不能用P7针号代替下表球位。

| 信号 | 已核对的60K球位 | 用途 |
| --- | --- | --- |
| IIC_scl | M13 | 板载RTC/EEPROM/音频配置I²C时钟 |
| IIC_sda | M16 | 板载I²C数据 |
| SEG7_DIO | M18 | 74HC595串行数据 |
| SEG7_RCLK | C2 | 74HC595输出锁存 |
| SEG7_SCLK | F4 | 74HC595移位时钟 |

这些信号已加入主工程CST，不占用临时P7传感器针脚。只实例化一个主机控制板载I²C；当前没有同时运行EEPROM或音频配置驱动，后续加入时必须仲裁同一总线。

### 20.2 当前源码行为与电池保持条件

`src/bm8563_clock.v`复用现有开漏I²C引擎，以100kHz轮询7位地址0x51，从寄存器00起一次读9字节，检查CTRL1的STOP/TEST、秒寄存器VL和合法BCD日期。寄存器依据[上海贝岭BM8563官方数据手册](https://www.belling.com.cn/media/file_object/bel_product/BM8563/datasheet/BM8563_V1.1_cn.pdf)，不只根据教程文件名推断型号。

上电/按S0复位只读取RTC，**不自动把时间重置成源码编写时间，也不自动清VL冒充时间可靠**。手动校时才暂停RTC、写入日期时间、清秒寄存器VL并恢复正常计时，然后读回实际时间显示。校时中途有I²C错误，会尝试一次恢复计时，但保留失败状态，要求重新发送完整校时帧；不能把部分更新的日期显示成成功。

`src/seg7_clock_display.v`按厂商串联顺序发送16位，先段码后位选、最高位先发；段选低有效、位选高有效。每位扫描1ms，整屏约125Hz；使用50MHz时钟下的使能节拍，不另造逻辑时钟。启动先显示约1秒`88888888`，然后正常显示`HH-MM-SS`（24小时制）。

| 数码管现象 | 本版设计含义 |
| --- | --- |
| 开机短暂88888888 | 用于先检查显示链路；仍待实际烧录验证 |
| 12-34-56并继续走秒 | 成功读到RTC合法时间；是否与当前实际时间一致仍需校时/核对 |
| -------- | 初始化、校时中，或RTC低电/停钟/日期不合法，不展示伪造时间 |
| E0000021 | I²C NACK，RTC未应答 |
| E0000022 | I²C事务/拉伸超时 |
| E0000023 | 总线恢复后仍低 |
| E0000024 | 内部读长度错误 |

纽扣电池给RTC维持计时，**不会在主板断电后继续点亮数码管，也不能让FPGA本身继续运行**。电池及保持电路正常时，断电期间RTC继续走时，重新上电后FPGA读取并显示；用户说电池可能没电，当前没有电压测量和掉电保持结果，不能承诺已经实现可靠掉电保持。VL仅表示曾出现使时间不可靠的低电情况，不是电池剩余电量百分比。

### 20.3 用现有HC-06校时，不依赖电脑COM连接成功

手机蓝牙助手选**文本/ASCII发送**，一条完整发送：

```text
TYYMMDDwHHMMSS;
```

YY=年后两位（本版支持2000～2099），MM/DD=月/日，w=星期（0周日、1周一、2周二……6周六），后面为24小时制的时分秒。必须带结尾英文分号，不要分开手动敲每个字符（帧内间隔超过0.5秒会取消）。CR/LF可以跟在分号后面。日期范围和闰年会检查，格式不符/RTC正忙时忽略，不修改时间。星期由发送者提供，程序不自动推算星期。

例如下面**只是格式例子，不是当前时间**：

```text
T2610062123456;
```

表示2026-10-06、周二、12:34:56。先把电脑时钟核对正确，可在Windows PowerShell生成当前本地时间帧，再立即复制到手机发送：

```powershell
$rtcNow = Get-Date
'T{0}{1}{2};' -f $rtcNow.ToString('yyMMdd'), ([int]$rtcNow.DayOfWeek), $rtcNow.ToString('HHmmss')
```

复制和发送的延时会造成秒级偏差，验收看时间时可核对后微调；这里不是网络自动授时。电脑串口能连上时，`tools/watch_sensor_demo.ps1 -Port COM实际编号`的T键会直接发送电脑当前时间。T帧独立解析，不增加原P/F/S/N的CMD计数，LAST不变是正常现象；校时以数码管实际读回时间为准。

### 22.2 BQ4050“四个电压”是什么

VC1～VC4是同一串联电池组各节点，不是四块独立电池输入。3S应取四个节点：电芯串负端B0、第一节正端B1、第二节正端B2、第三节正端B3。满电例子分别为0/4.2/8.4/12.6V；相邻差值才是每节4.2V。实际电芯类型、满充和截止值不能只看总电压猜。

| BQ4050引脚 | 3S连接（经参考输入滤波） |
| --- | --- |
| VSS，9脚 | 电芯串B0，低电流地在电芯负端/SRP侧Kelvin取点 |
| VC1，5脚 | B1 |
| VC2，4脚 | B2 |
| VC3，3脚 | B3 |
| VC4，2脚 | 3S时在芯片侧短接VC3，不悬空、不接地；软件也配置3S |

只有包正负两个输出时，无法测到B1/B2，尤其包内可能还有保护开关，不能把输出负端自动当内部电芯B0。两块独立电池不能拼成“六节”接一个最多4S的BQ4050，也不能把两块包当VC1/VC2两个普通ADC输入。

若未来更换为可提供逐节抽头的电池，每包一颗BQ4050，共两颗；每颗有自己电流采样和SOC历史。工作时FPGA只需SMBC/SCL（19脚）与SMBD/SDA（18脚）两根GPIO，不需要FPGA模拟采样或主动驱动CHG/DSG。两颗分开总线共4根GPIO；若处理地址与电气参考，可共用两根线。

BQ4050默认**7位0x0B**，手册的0x16/0x17是带读写位的地址字节；不同于BQ34Z100-G1固定0x55。SLUUAQ3A第12章说明可修改Data Flash的Address和Address Check，并在POR后检查；未经分别配置/验证的两颗默认地址不能同时挂一条总线。首次配置应逐颗接入，不能让两颗同址同时响应。独立总线和MUX不自动提供地隔离。

最小运行先100kHz主机轮询、关闭不需要的广播，按SMBus Read Word读取两字节低字节在前，PEC是否启用必须匹配配置；不能只凭电气接口相似沿用任意I²C寄存器协议。0x09为总电压mV，0x0A为有符号电流mA，0x0D为相对SOC%，0x0F为剩余容量（单位取决于CAPM）。中断/SHUTDN按需另外预留和适配，不能把这些引脚一律当3.3V开漏输出。

### 23.1 本节接法与网络命名

以下统一采用官方多节参考图的**VSS在BAT−侧**方案，以免混用不同接法。`BAT_NEG_A/B`是现有电池包的外部负输出，不拆包接内部电芯；`PACK_NEG_A/B`是分流电阻后的负载回流。两路PACK_NEG在电源分配处与SYS_GND连接，两路BAT_NEG不互接、不接SYS_GND。各自BQ的去耦、分压下端和NTC接口使用本路BQ_GND=BAT_NEG的Kelvin点。

```text
本路电池+ ── 保险/反接保护 ── 负载正供电
本路电池−(BAT_NEG) ── R_SENSE ── PACK_NEG/SYS_GND ── 负载负回流
                      ↑两端独立Kelvin采样细线↑
BAT_NEG侧 → 100Ω → SRP(9)
PACK_NEG侧 → 100Ω → SRN(10)
VSS(8) → BAT_NEG側的安静Kelvin点
```

充电回流若经过PACK_NEG端，才能被该分流记录；外部充电绕过分流的次数不能被视为已累计。电池侧常供电小信号支路的自耗也有计量边界，不把断电/未测电流自动当0。

### 23.3 BAT分压、REGIN供电及电流采样

固定分压的基础网络：`电池正端 → R_TOP → BAT → R_BOTTOM → BQ_GND`，BAT至BQ_GND加参考小电容。R_BOTTOM建议15～25kΩ，候选16.5kΩ；R_TOP按实际最高包电压和约0.9V目标计算，参考公式`R_TOP=R_BOTTOM*(V_MAX/0.9-1)`。候选240kΩ/16.5kΩ在12.6V得到约0.811V，0.9V对应约13.99V，用于说明分压裕量，**不是已冻结值/电机过压保护电压**。优先0.1%、低温漂/匹配电阻，并按实测校准Voltage Divider；选外部分压模式VOLTSEL=1、串数3，初始设置与实际比值和校准流程一致。固定分压在12.6V约49µA持续消耗；VEN开关分压可降低该自耗但增加MOS网络和时序评审，两个方案不可拼错。

REGIN本图使用从本路电池供电、以本路BQ_GND参考的常供电前级。优先评估低静态电流、能承受满电和实际尖峰的3.3V LDO；具体型号、输入输出电容依其手册，不以一个普通分压替代稳压。不能将系统电源连同SYS_GND接到BAT_NEG旁路分流；系统3.3V单独供电并非电压上绝对不可行，但须核对跨分流参考偏移、两包供电回流及关机计量，不是本图默认接法。不能只在整车开机时给BQ供电后声称持续记录了断电期间充放电。REG25按引脚表和推荐条件选1µF，不将布局概述中泛化的电容值替代本脚要求。

两根电流输入各100Ω、SRP与SRN之间100nF差分电容；可按图8-3另预留各输入100nF至BQ_GND，保持对称及近端布局。R_SENSE按实际峰值、压降、分辨率、功率选择，正常采样压差控制在±125mV内，不把瞬态绝对极限作为连续设计目标。例5mΩ、5A为25mV/0.125W，10A为50mV/0.5W，只是计算示例；额定功率/峰值/温升及驱动允许电流未冻结。低温漂分流，采样线从焊盘内侧独立引出，不沿大电流铜线远端取点。

### 23.4 通信、接地的适用条件与此前表述修正

每包一颗，两颗固定7位0x55。按现有方案保留A/B两组SDA/SCL，共4根FPGA GPIO，或另评估I²C多路器；两个同址不可直接并联。NTC、CE、VEN、REG25不需要逐一接FPGA GPIO。

### 23.5 配置与PCB状态

选用专用电量计不自动保证百分比准确：逐包配置3S、2800mAh标称容量、分压模式/增益、分流增益、TEMPS及ChemID，完成电压/零电流/已知电流/温度校准，按TI流程完成学习及独立容量验证后才能评价SOC误差。BQ不是充电器或BMS，继续保留现有电池保护，不依据包总电压承诺逐节安全。

### 24.2 供电和I²C直连条件

U13为TPS70933而非A/B变体：1 IN→BAT_A_POS，2 GND→BQ_A_GND，3 EN明确NC（内部上拉使能），4 NC，5 OUT→BQ_A_3V3。**EN允许范围与IN不同，EN不得接12.6V。**BAT_A_POS来自已在整板设计中安排的保险/反接保护后的本路正供电，本参考图不代选主回路保护。U13只是电量计小信号供电，绝不拿它给香橙派、电机或FPGA板供电。

**删除原图U14 ISO1640及它的C69/C70，不保留两侧重复上拉。**U12-14 SDA→R68（0Ω候选）→FPGA A路SDA GPIO；U12-13 SCL→R69（0Ω候选）→FPGA A路SCL GPIO。R66/R67分别将两根信号上拉到P7-29的SYS_3V3；P7-30是SYS_GND，不能额外接到BQ_A_GND。两端本来通过R63低阻相连，不是完全浮地的两套系统；只需核算这条路径的压降，不以一根地线绕过它。

门限预算：BQ VIL最大0.6V、VIH最小1.2V、VOL最大0.4V（3mA）；GW5AT-60 LVCMOS33的VIL最大0.8V、VIH最小2.0V、VOL最大0.4V。候选目标为两参考地间`|ΔGND|≤50mV`，含充放电方向、铜箔/接线和瞬态预算：对端低电平最坏约0.45V，小于0.6/0.8V；BQ看到高电平约3.3±0.05V，符合接口要求；负摆幅亦需在允许范围内。5mΩ在10A为50mV只是分流本身的计算，**不是已测最大电流或已留完噪声余量**。真实峰值与干扰须测量；超过该目标不能据此宣称直连已通过，也不能把±125mV采样量程当总线抗扰设计目标。

每条总线只装一套4.7k上拉，先100kHz、短板内走线；按实际总电容验证上升时间（手册表6.14要求≤300ns）。不沿用旧ISO1640两侧80pF等限制，直接按BQ时序与拉低能力预算。FPGA两根GPIO只输出0或高阻释放，使用3.3V IO设置并读回管脚，SCL需支持BQ时钟拉伸，不能当固定推挽时钟。TRM描述FLASH活动可有2～20ms拉伸，未来驱动需等待余量、超时恢复，不能用极短超时；STOP后总线空闲等时序按BQ而非只套普通I²C默认值。

上拉仅接可掉电SYS_3V3，不接本路常供电BQ_A_3V3，保持LED_Comm=0、ALERT关闭，避免将通信脚改为显示输出；FPGA关机时BQ不会通过常供电上拉持续抬高FPGA引脚。若某电池拔掉、BQ未供电但FPGA仍开机，BQ的SDA/SCL独立绝对额定−0.3～5.5V不等于保证Ioff或零反供电：该状态尚待验证。本期候选不承诺任意热插拔；需要严格掉电隔离时，再针对该要求审查总线开关，不能用0Ω/串阻冒充隔离。

- P7-29/30提供SYS_3V3/SYS_GND；当前图不再使用ISO1640，SYS_3V3仅供总线一套上拉，两路可共用。

- 不能把本地3.3V换成P7-29并顺手把BQ地接P7-30，否则会改变参考地；若保留其他BAT_NEG连接，还可能形成绕过分流的回流。只取P7正供电并非电压上完全不可，但须审查两包供电/回流和参考压降，不作为现图默认接法。
- 两包各有独立BAT_NEG参考，本图各用一颗LDO，输出/本地地不并联；系统侧上拉3.3V则可以共用。额外LDO的理由是常供电和保持每包参考，不是认为FPGA板供电能力不足。

芯片本身并非强制BAT_NEG参考或强制隔离；当前第24节已在保持BAT_NEG参考的同时取消隔离器。若要整个BQ电路复用板上3.3V，PACK_NEG共地是一条可选路线，但供电、分压下端、SRP/SRN参考、GNDSEL、温度接口及误差预算须成套核对。板上3.3V随FPGA断电，无法依靠这条掉电电源持续记录关机期间充放电，因此图中常供电LDO保留。现有BAT_NEG侧小信号自耗未经过分流的计量限制继续适用，见24.4；常供电也不自动保证待机SOC准确。

### 25.4 为什么旧STM32板需要额外LDO，不代表FPGA天然供电更强

开发板外设供电能力由稳压器、输入电源、散热和走线决定，不由MCU/FPGA名称决定。LDO把压差变成热，近似损耗`(VIN−VOUT)×I`；例如5V降3.3V、负载500mA会在LDO上产生约0.85W热，小封装可能先遇到温升限制。DC/DC通过开关、电感和电容降压，通常更适合较大电流，但仍有损耗、纹波和瞬态/布局要求。不能将新增LDO输出直接并到板上3.3V来“补电流”。

本板主3.3V已经是3A等级DC/DC，暂不因BQ电流需求增设系统侧5V→3.3V LDO；保留现有候选图的本路电池侧LDO。U12芯片输入最高28V不等于整板允许28V或已确认3S满电12.6V直供，板卡6～12V约束不变。

## 26. 为什么取消隔离器，以及两种原生I²C接法（2026-10-07修正）

用户在录入原理图时质疑ISO1640是否必要。重新核对后，**此前由BAT−/PACK−参考地不同直接推导出首版需要隔离，判断过于保守，增加了不必要器件和自耗。**BQ自带I²C从机，FPGA可以用逻辑实现I²C主机；ISO1640只是接口隔离器，不是实现I²C协议的必需芯片。当前同名PNG/SVG已原位取消ISO1640，第13/23/24/25节及P7/接头说明同步修正；不另外生成版本文件夹。

数据手册第3页13/14脚就是SCL/SDA，配上拉使用；第4～5页给出接口电平。除[BQ官方数据手册](https://www.ti.com/lit/ds/symlink/bq34z100-g1.pdf)，还核对[TI工程师Terry明确讨论BQ34Z100-G1直接通信的回复](https://e2e.ti.com/support/power-management-group/power-management/f/power-management-forum/868857/bq76920-how-much-max-ah-does-bq76920-supports)：处理器参考PACK−、BQ参考BAT−，差异仅来自分流压降，应保持足够小而不影响通信。两端并非浮地隔开的系统，已经通过低阻分流联系；不能因为名字不同就必加隔离，更不能为了直连加地线短接分流。

| 接法 | 是否可原生I²C直连 | 取舍 |
| --- | --- | --- |
| 当前图：VSS在BAT−侧，主机地PACK− | 是，须满足地差/电平/掉电条件 | 保持电池端电压参考，用户已画供电/分压/温度部分可继续使用；仅去隔离器、改总线上拉与连接 |

第二条依据[TI关于VSS可接BAT−或PACK−的答复](https://e2e.ti.com/support/power-management-group/power-management/f/power-management-forum/1264244/bq34z100-g1-pack--connection-to-pcb-ground-also-ce-pin-to-control-leds-in-larger-system)及[TI对SRP/SRN和系统参考的说明](https://e2e.ti.com/support/power-management-group/power-management/f/power-management-forum/618374/bq34z100-g1-srn-and-srp-pins)。注意后者早期回复后经TEC更正，不单引最早答复。PACK侧仍SRP取BAT−、SRN取PACK−；不能交换两脚。`GNDSEL=0`选择VSS，`=1`选择10脚SRN；若两者都PACK侧，不存在设1就自动消除分流压降的效果。分压采用PACK侧时，放电测得电压约为电池外部端电压减`I×R_SENSE`，5mΩ/5A为25mV，静态校准不能消除随电流变化的该项；须纳入学习/误差验证。

当前保留本路TPS70933，是为了关机后BQ继续工作并保持每包电池侧参考，**不是因为原生I²C需要LDO或FPGA板3.3V带不动BQ**。两颗同址0x55仍分别用两组SDA/SCL，共4根GPIO；I²C直连不等于两个同址芯片可以并到一条总线。外围分压、分流、去耦、温度及SOC配置/校准/学习仍需保留。
