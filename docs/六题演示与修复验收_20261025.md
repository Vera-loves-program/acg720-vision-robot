## 六个入口

| 首页 | 操作 | 本轮行为 |
|---|---|---|
|1 CAMERA + IMU|直接进入|FPGA 摄像头画面与 IMU 显示保留；与 Pi USB 相机独立。|
|2 MOTOR CONTROL|FORWARD / REVERSE / TURN LEFT / TURN RIGHT / TURN 180 / STOP|点击方向直接执行，不需要 ARM。SPEED 调速度。|
|3 LIDAR AVOID|START / STOP / VIEW MAP / RADAR +90|沿车头低速走，前方近障减速/停车。地图可见。**此页演示减速/停车；路线绕行在题4/6。**|
|4 XY NAVIGATION|HERE IS ZERO → SET GOAL → GO TO GOAL|一键当前位置为原点、当前车头为 +X、左侧为 +Y；X/Y 单位 mm。LEFT/RIGHT 90 独立陀螺仪转向。|
|5 VISION TARGET|TRACK DOG / CHOOSE OBJECT / STOP TRACK|自动选择连续稳定的小狗，或按实时稳定 ID 选择其他候选，云台居中，车轮不走。|
|6 FIND DOG|FIND DOG / FACE DOG / GO NEAR DOG / SIDE FOLLOW / CAMERA FRONT / STOP|搜索、雷达定位、转向目标及带避障的接近；原左侧前后跟随放在 SIDE FOLLOW。|

SETTINGS 是统一调试入口。ALL STOP 随时停止动作；无需另点 ARM。保留真实电机故障、传感器断流、近障停车及已确认舵机限位。导航错误后不会自动倒车，也不会在解除故障后自行续跑。

### 题4：坐标、90°和指定点

静止等陀螺仪校准完成。将车头朝你希望的 +X，按 **HERE IS ZERO**。实现先停止控制链，随后同时清 X/Y/航向和旧地图，不会只改屏幕数字。默认目标为 `(300,0)`。SET GOAL 只有 X−/X+/Y−/Y+/STEP/DONE；先验证 `(300,0)`，再 `(300,300)` 等点。

LEFT 90 应原地左转约90°，RIGHT 90 相反；使用实测 Z 轴角速度积分后的航向与零偏修正。固定角度转向不经过旧自动后退恢复，也不依赖轮子位置环。陀螺仪不是绝对罗盘，长时间漂移仍需静止重置；不能声称是完整 SLAM。

GOTO 在车体坐标控制前进、用航向外环旋转；遇阻时在**已知空闲**栅格内做车体膨胀后的路径规划，未扫描区不能冒充可通行。`START UNKNOWN` 表示起点周围没有足够扫描覆盖，`GOAL UNKNOWN` 表示目标附近覆盖不足；`START/GOAL BLOCKED` 才表示已有障碍证据。不要靠取消全部避障来掩盖朝向映射错误。

### 题6：小狗搜索和雷达接近

物品升到雷达扫描平面，物品附近空旷，途中允许有障碍。只靠相机方向与激光几何，无法识别“完全共线且遮住小狗的同尺寸物体”，所以不作这种保证。

1. 首次建立**相机车头方向参考**：先在题5 TRACK DOG，使车轮静止，把小狗放在车头正前方约1–2m，等云台居中。进入题6后如切页已清目标，按 FIND DOG 重新锁定；小狗仍在正前方时按 **CAMERA FRONT**。显示 `CAMERA FRONT SET`。它保存到独立 `config/visual_task.json`，不改 PWM/角度表或原图像运动采样。以后重新烧录、更改原点无需重教这个车身安装参考；改变相机安装、PAN方向或角度表后要重新教。
2. 按 **FIND DOG**：只在实测 PAN 角度/限位内扫描，等三帧稳定目标；一个方向找不到时请求 FPGA 原地左转90°再扫。最多四个朝向/三次转车、总180秒；转车无法在12秒内完成则结束，显示 `DOG NOT FOUND`。这也可能表示转向受阻，查看雷达页面。不会无限转圈。发现目标时停止搜索转车，再居中定位。
3. 等 **DOG POSITION SET**。FPGA 使用激光返回点估计目标位置；不会用框大小、PAN角或假定玩偶大小估距离。题6左侧 X/Y 是该扫描下相对轮轴原点的激光簇中心，单位 mm。云台 PWM 仍是命令估计，没有新增机械编码器。
4. **FACE DOG**：由 FPGA 对实际雷达簇 `atan2(Y,X)`，结合扫描时陀螺仪航向，原地面向目标后停下。
5. **GO NEAR DOG**：一次点击锁存目标世界坐标及接近点，用题4同一导航/栅格规划绕路。默认轮轴原点距目标的雷达表面 **512mm** 停车；不是车头边缘512mm，车头还向前伸出约231mm。这个距离兼容当前320mm量级的规划膨胀，避免目标本身把停车点封死。不会追撞物品。可在独立配置中调整 `standoff_mm`（350..1500），须结合地图分辨率和车体确认实际可达。
6. STOP/离开视觉页/断网会撤销运行授权；恢复网络后重新点击动作。已经开始的接近任务固定原目标，途中新出现的近障不会被改叫“小狗”。目标定位有歧义时不允许开始新的接近。

雷达关联：以车体坐标连续点间距100mm分簇；完整簇至少3点、X/Y跨度均不超过400mm；用相机方向筛选，唯一且连续两扫描稳定才确认。先分完整物理簇再筛方向，避免把大墙在方向锥内的片段假装成小狗。`LASER AMBIGUOUS` 时移开目标旁同方向物品；`WAIT LASER MATCH` 时检查小狗高度、雷达安装角及相机车头参考。

没有完整相机内参时，系统只在玩偶靠近画面中心时使用已标定云台的中心光轴，水平容差约7°，属于近似方向。PWM到实际机械位置的滞后、相机平移未知都会影响关联，不能宣称毫米级视觉外参。默认将相机原点不确定度设为261mm（车体范围），有实测时可在 `visual_task.json` 增加 `"camera_origin_mm":[X,Y]`，按轮轴原点 +X前/+Y左测量，降低误配。`pan_sign` 未指定时，CAMERA FRONT会优先从已经应用且角度表一致的原图像运动采样中提取PAN方向符号（要求水平响应占主导）；这只辨别方向，不把Jacobian当绝对姿态。无合格采样时默认 +1，沿用既有几何模型正角向左；实际正角相反时在独立配置明确设 −1 并重做 CAMERA FRONT。没有测量的外参不伪造为已标定值。

### 原左侧前后跟随

题6→SIDE FOLLOW：TRACK DOG；让小狗停在车左、云台居中，系统自动记录静止 PAN 参考；把小狗沿实际车头方向挪一点，等居中后 FRONT SAMPLE（PAN差至少3°）；START FOLLOW 直接开始。车只前后运动并保持航向，不改为追到车前方。默认视觉增益0.20、限速5 COUNT/10ms，FOLLOW SETUP可调。此模式根据教过方向的 PAN 偏差跟随，没有用 PAN 假算物距；雷达负责近障停车，**侧随本身不自动绕障**。

## 几何和上电参数

- O 是两驱动轮中心的中点；O 到前/后/左/右边缘为231.27/117.39/119/119mm。雷达 R 相对 O 为 `(32.56,-77.35)`mm。
- 从 R 到前/后/左/右边缘分别198.71/149.95/196.35/41.65mm。代码先把激光点转换到 O 再比较 O 的边缘，**不能把 R 的距离再次当车体边界扣除偏移**。整数实现保守取尺寸232/118/119/119、偏移33/−77。
- 行驶余量20mm、转向余量30mm、接触余量10mm；不是以雷达为圆心一律500mm禁止运动。转向仍考虑车头角扫过的范围。
- 当前雷达方向预置90°来自装配照片中三角标记朝车左的推断，**未实测确认**。如果正前方单一物品在地图显示成左/后/右，题3 RADAR +90 可循环修正；每次改角停止动作并清图。一键原点与雷达安装角是两个不同问题。
- 轮周204mm、编码器1469COUNT/圈、轮距213mm；速度 PID 上电30/1/0、最大PWM600‰，不用每次经 VOFA 恢复。位置环 P=0.125、I=D=0 是保守初值，尚未实车调定。

## 位置环到底做什么、怎么调

轮子位置环用于 **VOFA 的轮子“目标编码器位置”模式**：例如从0转到200COUNT，它以20Hz将剩余编码器误差换成速度目标，再由100Hz速度环执行；目标速度的绝对值同时是位置模式的速度上限。NAV 的世界 X/Y、90°转向、视觉跟随都通过现有速度环运行，不使用这两个轮子位置 PID，因此不是“位置P=0导致90°只倒车”。

两轮分别调，先 I=D=0、位置P=0.125、速度上限约3–5COUNT/10ms，发100–200COUNT的小阶跃。停得太慢且不超调时逐步增 P（如0.1875、0.25）；来回摆就减 P。先确认编码器正方向与电机正方向一致。只有确定存在持续静差且不是死区/摩擦问题再加很小 I；不要同时改速度环。实际 VOFA 命令沿用原协议，本轮没有改蓝牙串口。
