# 点锡机界面参考审查

审查日期：2026 年 10 月 3 日。这里记录实际找到的源码，以及它能怎样帮助我们改进机器人界面。

## 1. 真正的 Python 界面在另一个仓库

你给的 [EDispense_Embedded](https://github.com/ZexinLiang/EDispense_Embedded) 是 STM32F407 底层工程，主要负责电机、FreeRTOS、通信和 TJC 串口屏。当前 `master` 中没有 Python 界面文件，也没有串口屏的 `.HMI` / `.TFT` 工程；`User/TJC.c` 是向串口屏发送命令的代码，不能还原完整界面外观。参见它的 [README](https://github.com/ZexinLiang/EDispense_Embedded/blob/master/README.md) 和 [TJC.c](https://github.com/ZexinLiang/EDispense_Embedded/blob/master/User/TJC.c)。

继续查看同一作者的公开仓库后，找到了 [EDispense_Vision](https://github.com/ZexinLiang/EDispense_Vision)。它公开了你说的 RK3588 上位机界面，主要入口是 [ui/solder_ui.py](https://github.com/ZexinLiang/EDispense_Vision/blob/master/ui/solder_ui.py)。这是 PyQt5 程序，设计基准正好也是 **1024×600**。它的说明写的是飞凌 ELF2（RK3588）、HDMI 触摸屏和 USB 摄像头，因此移植到香橙派时仍要调整设备和启动配置。参见 [Vision README](https://github.com/ZexinLiang/EDispense_Vision/blob/master/README.md)。

已找到的相关文件：

| 文件 | 作用 |
|---|---|
| `ui/solder_ui.py` | 主窗口、视频显示、控制面板、调试界面、手势和点锡流程 |
| `ui/voice_input.py` | 语音输入界面及服务连接 |
| `ui/wifi_config.py` | Wi-Fi 配置 |
| `ui/cmd_bridge.py` | 外部命令桥接 |
| `run_ui.sh` | 设置显示和触摸映射，再启动主界面 |
| `models/pad.rknn`、`models/qs.rknn` | 点锡和 AOI 的模型，当前仓库中也已公开 |
| `config/` | 点锡机的相机及运动标定数据 |

这意味着可以认真参考它的界面实现。不过，点锡机的模型、标定值和运动命令对应的是原设备；我们需要接入自己的 FPGA 图像和机器人状态，不能把这些配置直接套用。

## 2. 可以参考的外观和分区

从 [主界面源码](https://github.com/ZexinLiang/EDispense_Vision/blob/master/ui/solder_ui.py) 能确认，它采用左侧图像、底部状态栏、右侧控制与参数面板的布局。控件由 `QHBoxLayout` / `QVBoxLayout` 排列，设置了留白和间距；调试面板与普通面板切换显示。

它的主要风格比较简洁：

| 用途 | 配色 / 做法 |
|---|---|
| 整体背景 | 浅灰 `#F2F2F7` |
| 信息卡片 | 白色、细灰边框、约 10 px 圆角 |
| 正文 | 深灰 `#1C1C1E` |
| 次要信息 | 灰色 `#8E8E93` |
| 主要操作、选中状态 | 蓝色 `#007AFF` |
| 正常、运行状态 | 绿色 `#34C759` |
| 停止、异常 | 红色 `#FF3B30` |

我们可以采用同样的浅灰背景、白卡片和蓝色主要操作，减少粗黑边框、黄色大面积底色和装饰点阵。这样摄像头画面会更突出，状态和按钮也更容易区分。

**布局不能照搬宽度。**原 Python 界面的右面板约为 280 px，并允许视频区域自适应；我们的 FPGA 屏需要保留 800×480 画面，因此侧栏只能使用约 176 px 的内容宽度。较长说明要放到底栏或独立调试页，不能全部挤进侧栏。

## 3. 为什么它的双指缩放不能直接复制到 FPGA

原程序的 `PinchZoomLabel` 调用 `Qt.PinchGesture`，读取两指缩放和中心移动，并对保存的图像做显示变换。源码中的缩放范围为 1×～5×，还包含平移处理。它运行在 Linux / PyQt5 上，触摸由系统驱动提供。参见 [PinchZoomLabel 所在源码](https://github.com/ZexinLiang/EDispense_Vision/blob/master/ui/solder_ui.py)。

我们的 LCD 由 FPGA 直接输出 RGB，GT911 由 FPGA 通过 I²C 读取。实现可见的缩放，需要把下面几步接起来：

1. GT911 可靠读出至少两指坐标及触点 ID。
2. 根据两指距离的变化识别放大或缩小，并过滤抖动。
3. 更新显示缩放状态。
4. 显示通路实际裁剪、重采样图像，再送给 LCD。

旧 R3 代码只把缩放状态作为请求发送给主机；LCD 仍显示原始 1× 画面。侧栏里的 `HOST REQ 2X` 和 `LCD 1X` 也体现了这个区别。所以能识别手势或改变标签，并不代表 LCD 已完成缩放。

对于本项目，先实现清晰可验证的 **1× / 2× 本地缩放**更合适。之后如需要连续缩放、平移、动画和丰富中文控件，可以在香橙派界面继续扩展。显示缩放应与训练照片保存分开，保存的数据仍使用未经 UI 叠加的完整图像。

## 4. 这次本地界面的具体问题

审查的是改版前的 `src/lcd1024_interaction_ui.v` 和 `docs/ui_preview.svg`：

- `TOUCH OK / WAIT / ERROR` 文本占用 y=182～198，而分隔线在 y=190，线会穿过文字。
- 拍照按钮占用 y=440～488，原分隔线在 y=478，也进入了按钮区域。
- 侧栏文字允许绘制 256 px，没有按卡片宽度裁剪；侧栏实际可用宽度更小，后续换长文字容易越界。
- 旧 SVG 预览仍是早期的 SYSTEM / PIPELINE / CONTROLS，与 R3 的视觉调试、ROI 和缩放请求界面不同，需要同步更新。
- `net_ready` 只表示网络 PLL 和 PHY 初始化完成，不能据此认定网线已连通或香橙派正在接收。网络状态标签需要准确说明这个含义。
- 选中点只是 ROI 请求，尚未接入人物识别、跟踪和电机，界面应区分这些状态。

改版时建议使用一套统一坐标定义，使背景、文字、按钮命中范围和手势区域对应一致；分隔线只放在板块之间的留白中。侧栏短标签按内容宽度限制绘制，长说明移至底栏。

## 5. 后续香橙派界面怎样扩展

现在先修复 FPGA 上的布局和缩放。当前香橙派收图程序使用 OpenCV 窗口；如果后续要做到原点锡机那种多页面、中文按钮、日志、参数输入和触摸操作，可以另外改为 PyQt5 主窗口，并复用已有 UDP 图像接收代码。

建议的页面为：实时画面、视觉调试、数据采集、传感器状态。界面显示 FPGA 实际上报的滤波状态、触摸状态和选中区域；尚未完成的 AI 或运动功能明确标为未接入。FPGA 继续承担相机采集、图像处理、显示和实时控制，香橙派承担识别与较复杂的交互。

这份审查只完成了源码阅读，没有运行学长的点锡机程序，也没有验证它在本机或香橙派上的运行效果。
