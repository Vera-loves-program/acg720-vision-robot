## 3. 两种真实舵机接法不要混用

- **当前计划/新固件：信号改接FPGA** PAN=P7-24、TILT=P7-27，按联调指南`--fpga --standalone --initial-pan 1200 --initial-tilt 2100`启动。必须保留实测标定；没有用户确认已经换线时不能假定已完成。

FPGA后端目前接受1～4095μs，Pi sysfs后端的20ms数值边界为1～19999μs；两者都不等于机械安全行程，已存实测限位仍优先。
- **旧接法，仅仍接Pi物理16/15时**：PAN PWM0(fd8b0000)、TILT PWM3(fd8b0030)。此前本机编号chip0/chip2，但编号会变，需按硬件地址确认。旧命令如下，不能用于已经改接FPGA的信号：

```bash
cd /home/orangepi/acg720_vision
/home/orangepi/.venvs/acg720-detection/bin/python client.py gimbal --camera /dev/video0 --width 640 --height 480 --fps 15 --hardware --pwm-pan /sys/class/pwm/pwmchip0/pwm0 --pwm-tilt /sys/class/pwm/pwmchip2/pwm0
```

Pi设备树此前已启用pwm0-m1/pwm3-m0，无须反复重配。没有棋盘格也能用已完成的图像响应采样进行云台居中；镜头内参标定和舵机限位/角度标定是不同事情。TILT0倒像、90朝天、180正立；PAN机械约300°，不要按无限360°环绕。

## 6. 手动限位、角度与图像采样（保留已有有效流程）

以下来自已成功的v17操作流程；v18沿用这些网页控件。真实PWM必须与上面实际接线/backend一致。正常网页模式仍有5秒浏览器失联关闭；只有显式FPGA standalone才不依赖浏览器。已经调好的角度/图像样本不用重做。

#### 先让舵机动起来



1. 看顶端后端标志。`MOCK模拟 · 舵机不会转`只改软件数值；真实舵机必须用下述与实际信号接线一致的启动命令，顶端显示`真实PWM · 0/2开启`。

2. **服务启动默认PWM关闭；打开或刷新网页不会自动开启PWM。** 每轴的“待输出”显示下一次请求脉宽，“输出”在PWM关闭时为横线。默认1500µs只是待发请求，不代表当前机械位置或已经标定的安全中点。

3. PWM关闭时先点粗/细加减，可以看到“待输出”变化，**此时舵机不动是正常行为**。默认细调5µs、粗调50µs，以按钮显示和已存步长为准。也可直接改待输出数字，修改后失去输入焦点即提交草稿。

4. 点这一轴的“**开启PWM**”，该轴才输出当前待发值。之后点粗/细加减会实时改变位置请求；看本轴旁的成功/错误提示和“输出”数字。另一轴不需要重启或重新设置。

5. 点“**关闭PWM**”只关闭本轴；之后加减继续只改草稿，不会自动恢复PWM。顶部“全部PWM关闭”关闭两轴。网页失联5秒也会关闭两轴，连接恢复后仍要手动开启。



`µs`是每20ms周期内高电平的微秒数，不是同样数值的角度。`+`表示增加脉宽，安装后是否向左/向上以实测为准。**“输出”是程序最近成功写入的PWM命令，不是编码器反馈，也不是实测舵机角度。** 首次开启会直接输出待发脉宽，软件不能读取断电后的舵机实际位置；先小步观察。



若按钮提示“请求已限制到…µs”，说明已命中本轴已存限位或当前探索范围。500～2500µs现为每轴探索范围的初始值，已经不再固定写死；可按下面的范围按钮继续扩展。已存机构限位仍然优先生效。



#### 可选：记录本轴限位、调整步长



1. 展开正在调的那一轴的“记录限位”。移动到保守确认的较小脉宽端点，等输出赶上请求、机构稳定，点“**记当前为下限**”；第一个端点只暂存。

2. 移到较大脉宽端点，点“**记当前为上限**”。**两端齐后自动保存，仅修改本轴**；不会关闭另一轴，也不会把位置跳回1500µs。下限必须小于上限，指脉宽大小，不一定对应机械左/右。

3. 已存和待存的两组数都显示在此处。若新限位排除了旧角度点，程序会提示原数据未删除；在“重试应用/清除记录”中选择“清除旧角度并应用”可明确重做这一轴角度表。

4. “**清除本轴限位**”清除这一轴的限位、暂存端点和角度标定，**保留本轴当前PWM开关与脉宽，另一轴不变**。随后可继续手动探索；自动跟踪需重新实测该轴角度。

5. “调整粗细步长”可直接保存本轴的细调和粗调步长；不关闭PWM，不改变另一轴。正常手动调节不需要展开JSON。



两只位置舵机都按机构实测行程处理。PAN用户实测约300°，TILT也受机构限制；程序不把任何一轴默认为完整360°。探索范围是当前允许手动发送的脉宽范围，**不是已验证的机构行程**；扩大它不会证明舵机能继续转动。



#### 底座到2500µs仍未测到边界：只扩大PAN探索范围



用户已测好TILT上层645～2420µs，更新包不含现场`config/gimbal.json`，因此保留该范围。不要清除上层记录。



1. 更新到v18并重启服务，浏览器Ctrl+F5确认v18。默认PWM仍关闭，按需开启PAN；TILT无需为此开启或重新标定。

2. 展开PAN卡片里的“扩大本轴探索范围”。点一次“**向上扩100µs**”，初始上限2500变成2600；仅保存探索范围，不改变当前输出、不自动开启PWM、不删除角度或限位。若原本在自动跟踪，保存成功后会暂停跟踪并保持当前输出，方便继续手动测量。

3. 回到PAN的“**细＋5**”，即可从2500继续到2505、2510。需要时再小段扩大范围。向较小脉宽继续测量时用“向下扩100µs”。也可在折叠区直接填写探索下限/上限并保存本轴范围。

4. 截图里PAN暂存的2500尚不是确认的真实上限。可在PAN“重试应用/清除记录”中先清除本轴记录，再重新测两端；这不会删除TILT的645～2420。若仅保留暂存端点，最终到达真实上端时重新点“记当前为上限”覆盖2500，再记另一端。

5. 若PAN以前已存机构限位，仅扩探索范围仍会被已存限位夹住；明确要重测时才清PAN本轴限位。两端重新记录后，后续手动/跟踪继续受新实测限位约束。



若脉宽继续变化而机构已不再转动，或开始顶住、持续嗡响，就停止增加并退回，记录有余量的端点；不需要靠堵转寻找边界。两轴探索范围、实测限位均独立保存。



#### 数字、位置看起来对不上时



“当前生效的探索范围”以服务已保存的值为准。例如这里仍显示1～2800µs，而“自定义探索范围”的输入框已填340和2600，说明输入框还只是未保存的草稿。点“保存本轴范围”，成功后确认当前范围也变为340～2600µs。若当前输出或请求还在新范围外，先将本轴移回新范围内再保存；不要为此清除TILT已测好的645～2420µs。



PWM关闭时，“待输出1500”只是一条准备发送的脉宽，不能据此判断当前位置。PWM开启后，请求会渐变到目标：默认150µs/s，从2800回到1500约需8.7秒。先等“输出”与“待输出”相同，再等机构停稳，才比较两个位置。



用户已经确认：保持PWM开启，执行1500→1600→1500，可以回到相同位置。这验证了这次连续通电测试的重复性，**不表示1500µs就是镜头水平位置**。当前TILT角度定义为0°倒像、90°朝正上方、180°正立；PAN仍以车身约定的水平朝向记录。保留已经测好的连续角度表，不因更新软件重新把当前位置叫作0°。



用户还报告：PWM关闭后手动转过转盘，重新开启时实际朝向会相差约180°。程序只知道最近发送的PWM命令，**不知道关闭PWM后被手动转到了哪里**。先固定车身和安装方向，用同一个参考脉宽、等待输出与机构稳定，比较连续通电和重新开启后的实际朝向。若同一命令仍对应不同朝向，应检查舵盘/传动连接与舵机内部位置反馈的重复性，再决定是否重新测角度表；不能把这种机械或反馈不确定性直接归结为软件偏了180°。



**本程序没有加入自动补180°、自动重设零位或掉电后的姿态恢复。** 不能用软件硬补180°掩盖同一PWM命令不重复的问题。v17保存单轴角度不再中断PWM，便于保持连续通电完成当前静止追玩偶演示；真实机械重复性仍需现场确认。

#### “角度标定”页：记录脉宽对应角度



手动移动只需要脉宽，不必先完成这一页。需要指定角度或自动跟踪时再做：



1. 在手动页将一轴转到一个位置，保持PWM开启，等输出稳定。

2. 切换“角度标定”，选择轴，填写**实际测量**的角度，点“记录当前位置”。PAN以车头为0°，沿用已测水平朝向；本车TILT用0°倒像、90°朝天、180°正立的连续定义，不在90°或180°处重设零位。

3. 每轴至少记录两点，推荐含零位三点。列表可删除记录；角度严格递增、脉宽单调，均须在已存限位内。约300°行程用连续角度记录，不绕回0°。

4. 点“**保存所选轴角度**”，确认“角度已保存；PWM状态保持不变”。只保存所选轴，另一轴的表不变；两轴原来开启就继续开启，原来关闭就仍关闭，不会为了保存而跳到1500µs。依次保存PAN、TILT即可，基本操作无需编辑JSON。

5. 保存成功会暂停原跟踪并清除旧目标选择。转到“目标跟踪”，等一张新画面，再点选玩偶或人脸，最后点“开始跟踪”。角度映射仍是命令与实测位置的关系，不是舵机角度反馈。



当前用户实测的PAN点为`380µs→45°、1882µs→180°、2550µs→240°`，TILT点为`2420µs→10°、2043µs→45°、645µs→175°`；两轴脉宽随角度的方向可以相反。它们是这台机构的实测记录，不是其他舵机可照抄的通用行程。单轴保存校验失败或写盘失败时，旧文件、旧角度表、PWM输出及正在运行的跟踪请求都保留，先处理页面错误再保存。



“高级”页的“**保存并关闭PWM**”仍用于整份配置替换，按钮明确会关闭输出；日常记录角度使用本页的单轴保存，不需要绕到高级页。



#### “跟踪校准”页：人和车不动，手动学习两轴画面响应



先保留当前能看见同一人物、图像正立的手动姿态。用户这次录像中，`PAN 1987µs／TILT 878µs`、TILT约153°时人物正立可见；这只是**该次现场位置记录**，不会被写成默认起点，也不会启动时自动跳转。1500µs按现表约95.49°，接近天顶；2043µs仍对应已测45°，但不是本车的正立起步建议。无需因此重做角度表。



1. 固定小车，让人物站定、脸部朝相机；也可用固定不动的玩偶。两轴开启PWM，手动调到目标完整可见，等待“输出”赶上请求。全程人物、玩偶和车身都不要移动，只让云台转轴移动。

2. 点顶部“**跟踪校准**”。进入本页会暂停旧跟踪并保持PWM输出。画面中央的**蓝框是期望的目标中心区域**，不是检测框；人物框来自识别结果。

3. 先做PAN第一组：点击同一人物的“**记起点**”。然后只用本页PAN粗／细`＋/−`改PWM，使人物框中心在**左右方向**靠近蓝框中心；TILT不要动，高度此时不要求同时对齐。

4. 等PWM输出稳定、人物仍站定、画面已更新，再点击**同一人物**的“**记终点**”。一组包含起点和终点；页面显示两轴脉宽和目标像素变化，每完成一组就保存记录。

5. PAN再做反方向第二组。若人物已经在蓝框中央，可先手动移开少量，等稳定后重新“记起点”，再只动PAN往相反方向对齐。每组小幅移动，不要顶到机构限位；一次任一轴不超过30°。

6. TILT也做上下两个相反方向的组：先记起点，**只调TILT**让人物中心在上下方向靠近蓝框，再等稳定记终点；PAN不要动。不需要每组都同时把左右和上下全部对齐。

7. 至少有**4组有效记录，PAN和TILT分别独立采样**后，看“拟合状态”。可以多记几组，最多保留最近64组。只有样本方向足以区分两轴（rank=2）、位移有效且残差等检查通过，才显示可以应用。只有一轴的数据、总按相同比例同时动两轴、目标自己移动或分辨率变化，可能无法通过。

8. 点“**应用采样模型**”，确认当前跟踪模型为“图像采样模型”。它会保持两轴PWM，不自动开始跟踪。回“目标跟踪”，等新画面、重新点同一人物，再开始。



如果一组点错人、人物动了或位移不合适，先“取消当前组”重来；已经存下的不一致样本可“清除全部采样”后重新采集。单靠软件不能证明人和车是否静止，残差检查也不能替代这个操作要求。暂时看不到同一目标时，不用旧框猜终点。



采样记录及是否应用保存在现场`config/gimbal.json`，更新ZIP不覆盖它。修改脉宽—角度表后，旧采样的角度签名不再匹配，**先清除旧图像采样再重测**；图像尺寸变化时恢复原尺寸或清除后重新采样。新增采样后需重新点应用。模型无效、尺寸不符或角度签名变化时，控制回退到本车安装定义的几何模型，页面显示当前模型来源。



#### “目标跟踪”页：先验收当前正立姿态



1. 固定小车和起始目标，沿用手动调好的、人物或玩偶完整可见的正立姿态。保持双轴PWM开启，不自动归零、转180°或回1500µs。

2. 核对两轴角度已标定、PWM开启、当前命令在角度表内。看当前模型来源；没有应用有效采样模型时，使用默认“180°正立”的几何模型。等待新画面，点选玩偶或人脸，再点“开始跟踪”。

3. 先小幅左右移动玩偶，看PAN是否减小横向误差，再上下移动验证TILT。若误差持续扩大，先暂停，核对模型来源及采样中人和车是否移动，不用加大增益掩盖方向错误。



先验收当前正立方向，再单独验证接近天顶和倒像。模型能否识别倒置的人脸或玩偶仍须实测；控制方向补偿与手动采样模型都不会自动旋转检测图像或补上漏检，不能把正立跟踪成功等同于倒像识别也可靠。



v17在跟踪页逐轴显示三个不同状态：**角度是否已标定、PWM是否开启、当前输出是否落在角度表覆盖范围内**。顶端`真实PWM · 0/2开启`仅表示两轴当前都关闭，**不是角度记录丢失**。看到“角度已标定 · PWM关闭”时，点“返回手动开启PWM”，按需开启两轴；原记录会保留。开启后等输出稳定、再点选当前目标即可开始。



若显示“当前命令超出角度表”，先在手动页调回提示的覆盖脉宽区间。比如PAN机构限位是340～2600µs，而已测角度点只覆盖380～2550µs，则340µs虽能手动输出，仍不能据表换算角度进行跟踪；这也不是“未保存”。跟踪页会用中文列出尚缺的条件，包括未开启PWM、未保存角度、没有重新选择目标、画面过期或控制错误，按提示处理，不需要反复清除标定。



没有棋盘格也能按归一化画面中心偏差追踪；此时不宣称准确方位角、距离或三维位置，不驱动车轮。目标暂离后先完成一次最后观测的有限预测移动，再等待重现；帧过期或故障立即保持。到实测角度端点时不会积累越界角度，也不把约300°绕回0°。



#### 安装定义、采样模型分别解决什么问题



相机正立在TILT 180°端，而不是0°端，等效于参考安装的画面上下和左右都相反。因此v17的**几何回退模型相对此前两轴都改正方向**，而不是改写原角度表或让舵机补转180°。高级页“相机安装定义”默认选“**180°正立／0°倒像**”，本车不需要更改；只有实际是相反安装时才选“0°正立／180°倒像”。保存安装定义保持PWM，随后重新选择目标。



几何模型用拍摄时TILT命令角估计和安装方向符号`s`转换纠偏：PAN因子为`s·cos(θ)/(cos²(θ)+0.01)`，TILT局部纠偏也乘`s`；本车`s=-1`。PAN跨过天顶时按余弦变号，TILT不因跨90°再翻一次；转换后仍限制两根轴的最高请求速度。[相机运动学与图像伺服参考§4.4、§5.4](https://vislab.isr.tecnico.ulisboa.pt/thesis/SjoerdMScThesis.pdf)提供的是原理依据，本工程采用有阻尼、有限速的实现，并非照搬论文公式。



“图像采样模型”则用手动起终点拟合包含TILT几何项的**2×2局部画面响应J**，学习两轴小角度移动如何让目标中心在画面里移动；应用且有效时优先用它纠偏。它无需棋盘格，也不能代替脉宽—角度表、证明人车静止，或推算目标距离和精确三维位置。局部模型也不保证任意大转角或不同镜头条件下都适用；现场不一致时应重新采样。



跟踪页显示正立／倒像一侧和接近正上方的提示。**接近天顶不是禁止整段角度运动的开关。** 精确90°时PAN水平纠偏能力仍会退化，采样模型也不能创造机构本来没有的控制能力；若停在这个姿态，暂停跟踪、手动调离90°后重新选目标，不自动扫动，也不保证任意姿态都能自动脱离。



安装补偿和采样控制都不能恢复PWM关闭后被手动扳动的真实位置。控制仍以已发出的PWM命令及实测角度表估计姿态；没有镜头内参或机械位置反馈时，不能声称已得到精确车身方位、距离或真实舵机角度。



“画面过期”与“目标暂离”不同：没有可用的新画面时立即保持当前输出并取消旧预测移动，等待相机恢复；仍有新画面但没有匹配目标时，完成最后一次预测移动后等待自动重获。v17取消旧`lost`永久锁定和超时后强制重选流程，不清除原目标类别，也不会在空画面中盲扫。



展开“调跟踪灵敏度”可直接调参数，不用JSON。点“填入演示起点”只是填写下表草稿，仍需点击保存；它不是实机已调定参数：



| 参数 | 参考起点 | 作用 |

| --- | --- | --- |

| 中心死区 `deadband` | 0.04 | 按图像半幅归一化，接近中心时不继续追赶 |

| 跟随增益 `normalized_gain_dps` | 50 | 无相机内参时把中心偏差换为转速；太慢时先小幅增加 |

| 最高转速 `max_rate_dps` | 20°/s | 限制请求转速 |

| 低通时间 `filter_time_constant_s` | 0.06s | 抑制框跳动，增加会更稳也更迟缓 |

| 死区迟滞 `deadband_hysteresis` | 0.015 | 避免在中心死区边缘反复启停 |

| 最小转速 `min_rate_dps` | 2°/s | 离开中心死区后克服过小请求 |

| 单帧积分上限 `max_control_dt_s` | 0.20s | 兼顾本次约176ms推理周期，并限制长卡顿后的追赶 |



保存跟踪参数会暂停并保持位置，不自动重开PWM或开始运动。重新选择当前目标再点开始。程序保留小数角度请求，避免低灵敏度变化一直被整数µs舍入吃掉；目标暂离时切换到一次固定预测位置，手动暂停或旧帧时取消未执行的追赶量。



#### “高级”页：以后再做镜头标定



棋盘格用于相机焦距参数、主点和畸变标定，**不是舵机限位标定**。当前没有棋盘格可跳过，不妨碍上述普通识别、拍照、手动移动或归一化画面居中。高级页另有JSON和运行诊断，日常不用展开。



等有棋盘格后，在高级页用“棋盘格 · 连拍10张”收集15～25张清晰、位置和姿态不同的照片，覆盖中央和四角、倾斜与不同距离。固定分辨率、焦距和对焦；停止预览后运行内参标定。至少12张需完整检出角点；下列9×6内部角点与20mm边长只是例子，必须替换为实际标定板：



```bash

/home/orangepi/.venvs/acg720-detection/bin/python client.py camera-calibrate --images 'dataset/usb_captures/calibration/*.jpg' --columns 9 --rows 6 --square-mm 20 --output config/usb_camera.json

```



输出为fx/fy/cx/cy、畸变系数和逐张重投影误差。镜头、焦距或采集分辨率变动后应重新核对，不能把另一摄像头内参直接套用。原理见[OpenCV官方标定教程](https://docs.opencv.org/4.x/dc/dbb/tutorial_py_calibration.html)。以后确实已生成`config/usb_camera.json`，才给启动命令额外加`--camera-config config/usb_camera.json`。现场舵机配置保存在`config/gimbal.json`；更新ZIP不会覆盖两份现场配置或照片。
