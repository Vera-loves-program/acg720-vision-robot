# 香橙派使用说明：R4 配套客户端

更新：2026-10-04。以后香橙派端只使用这份说明和 `acg720-orangepi.zip`。固定运行目录是 `/home/orangepi/acg720_vision`，入口是 `client.py`，不用再区分 V2、R4 等客户端文件夹。

FPGA 使用你已经烧录的 R4。本文直接配置和运行当前版本，不要求回退或做版本对照。

## 1. 当前 SSH 连接与之前的超时原因

当前热点配置：香橙派地址是 `192.168.137.80/24`，电脑热点接口是 `192.168.137.1/24`，电脑仍通过校园 Wi-Fi 上网。你已经成功登录 SSH，FPGA 收图也通过；随后出现热点 SSH 卡顿/断线，目前在排查，见第 15 节。不要把之前端口可达当成现在仍稳定的证明。

现在直接在 **Windows PowerShell** 中运行：

```powershell
$opiAddress = "192.168.137.80"
ssh "orangepi@$opiAddress"
```

首次连接会询问是否信任服务器的主机密钥；确认是自己的香橙派后输入 `yes`，然后输入香橙派用户的密码。输入密码时没有字符或星号显示，这是正常现象。以后若重新连接热点，DHCP 可能分配不同地址，以香橙派的实际输出为准。

下面保留之前校园网直接连接失败的排查过程，**当前已能连接时无需重复执行**。

之前两台设备连接同一校园 Wi-Fi，香橙派 SSH 服务为 active，但电脑无法访问它的 22 端口。当时的地址如下：

| 设备 | 当时地址 | 所在网络 |
| --- | --- | --- |
| 电脑 Wi-Fi | 10.9.76.199/21 | 校园网 |
| 香橙派 Wi-Fi | 10.9.136.188/21 | 同一校园 Wi-Fi |

同一 SSID 也可能有多个子网，校园网络策略可能限制设备互通。Windows 已有 SSH 客户端，不需要安装 Windows Python，也不需要进入 WSL。下面第 1.1、1.2 节保留为校园认证设置参考，已经连上的设备不用重复配置。

### 1.1 澳门大学 SECURED 的对应设置

澳门大学的 [官方无线网络教程（2025 年手册）](https://fah.um.edu.mo/wp-content/uploads/2025/05/Booklet-DPORT-Summer-Programme-2025_EN.pdf) 给出 `UM_SECURED_WLAN` 的认证为 **PEAP + MSCHAPv2**，Identity/Password 使用 UMPASS。

在香橙派的桌面终端运行：

```bash
nm-connection-editor
```

打开 Network Connections 后，选中 `UM_SECURED_WLAN` 的连接配置，点编辑。在 Wi-Fi Security（无线安全）页核对下表；不要修改 `eth0` 的 FPGA 连接。

| 字段 | 设置 |
| --- | --- |
| SSID | UM_SECURED_WLAN |
| Security / 安全 | WPA/WPA2 Enterprise（企业） |
| Authentication / 认证 | Protected EAP（PEAP），不是 TLS 或 TTLS |
| Anonymous identity / 匿名身份 | 先留空 |
| PEAP version | Automatic（自动） |
| Inner authentication / 内部认证 | MSCHAPv2 |
| Username / Identity | 与电脑成功登录时相同的 UMPASS 用户名 |
| Password | UMPASS 密码 |

证书设置也要匹配：上面的校方 2025 年简化教程写的是 `CA certificate: Do not Validate`，对应 Linux 的“不需要 CA 证书”选项。如果 ICTO 已给你 CA 证书和服务器域名，应优先使用学校提供的配置。这里是对校方特定教程的转述，不是让所有校园网都关闭证书验证；不校验会失去认证服务器身份核验。

UMPASS 用户名不是任意一串完整学号。校方 [Wi-Fi FAQ](https://faq.icto.um.edu.mo/category/network/) 提示学生 UMPASS 是学号对应的前七字符形式；最直接的方式是与电脑已经成功登录的用户名保持一致，不自行换成完整邮箱或 eduroam 的账号格式。

IPv4 页保持 Automatic（DHCP），保存后再点网络图标连接 `UM_SECURED_WLAN`。若找不到编辑器或字段与上面不同，把窗口截图发我，遮住账号和密码。

账号密码正确却重复弹窗，仍需区分认证配置、证书、系统时间或服务端拒绝。连接失败后立即运行下面的只读命令，提供错误行即可：

```bash
nmcli -f GENERAL.STATE,GENERAL.REASON device show wlan0
sudo journalctl -b -u NetworkManager -n 60 --no-pager
date
```

### 1.2 PORTAL 能上网不等于 SSH 能用

`UM_WLAN_PORTAL` 是网页认证入口：连接 Wi-Fi 后，还需要在香橙派浏览器完成登录。校方 [PORTAL 说明](https://faq.icto.um.edu.mo/how-to-connect-captive-portal-of-um-wireless-network-service/) 列出的允许服务不包含 SSH，因此 **22 端口可能被网络策略拦截**；这是根据服务列表作出的判断，不是已经测到你的具体连接被拦截。

如果香橙派已在任一校园网络获得地址，在香橙派运行 `ip -4 -br addr`，记录 `wlan0` 的当前地址。在电脑 PowerShell 用这个实际地址测试：

```powershell
$opiAddress = "替换为香橙派当前的IPv4"
Test-NetConnection $opiAddress -Port 22
```

通过就直接用第 3 节继续 SSH。若服务器为 active 而校园网络仍不允许互通，再用下一节的电脑共享校园网方式。

### 1.3 已连接同一 Wi-Fi，SSH 仍然超时

你最新截图确认：香橙派 `wlan0` 为 `10.9.136.188/21`，`eth0` 为 `192.168.10.3/24`，SSH 服务为 `active`。电脑访问它时使用地址 `10.9.76.199`。

`/21` 对应掩码 `255.255.248.0`，香橙派所在网段是 `10.9.136.0～10.9.143.255`。本机读取确认电脑也是 `/21`，其网段为 `10.9.72.0～10.9.79.255`，到香橙派的流量经过校园网网关 `10.9.79.254`。两台设备需要校园网路由转发。**同一个 Wi-Fi 名称不保证设备能直接互访。**分段本身不一定有问题；路由、防火墙或无线隔离规则都可能导致超时，现在还不能直接认定某一种。

先在香橙派运行：

```bash
sudo ss -lntp | grep ':22'
sudo ufw status
ip route get 10.9.76.199
```

判断方法：

- 监听输出应有 `0.0.0.0:22` 或接受 IPv4 的全接口监听。只监听 `127.0.0.1:22`，外部无法访问；只监听 `192.168.10.3:22`，也不能通过校园 Wi-Fi 访问。若仅显示 `[::]:22`，需要再检查 IPv4 是否也可接受，不能仅凭这一行断言可用。
- UFW 若 `inactive`，不用改它。若 active 且没有适用的放行规则，可针对本次电脑地址执行 `sudo ufw allow from 10.9.76.199 to any port 22 proto tcp`。不关闭整个防火墙。若找不到 ufw，先保留这个输出，不需为了诊断安装它。
- 路由输出应使用 `dev wlan0`、源地址 `src 10.9.136.188`，通常经无线网关。如果走 `eth0` 或源地址为 `192.168.10.3`，回程路由有问题；FPGA 有线连接不应设置默认网关。

确认这些结果后，在电脑 PowerShell 依次运行：

```powershell
$opiAddress = "10.9.136.188"
Test-NetConnection $opiAddress -Port 22
ssh "orangepi@$opiAddress"
```

地址发生变化时以实际地址为准。你最早那条错误没有显示主机地址，是因为当时还没给 `$opiAddress` 赋值；它不能说明香橙派拒绝连接。必须先赋值，再执行 SSH。

21 是 FTP 端口，不是 SSH 端口；不需继续测试 21。Ping 超时也不能单独证明主机不在线，因为校园网或主机可以过滤 ICMP。

如果监听、主机防火墙和回程路由看起来正常，但校园网依然不允许两台设备通信，用下一节的电脑共享校园网建立本地连接。不要通过随意把 Wi-Fi IP 改成同一网段来处理校园网隔离，那不会改变校园网的实际分段，还可能与已分配地址冲突。

### 1.4 备选：电脑共享校园网，不用手机流量

在电脑操作：

1. 电脑继续连接校园网，先确认浏览器能上网。
2. 按 Win+I，打开“设置 → 网络和 Internet → 移动热点”。这里是 **Windows 电脑热点**，不是手机热点。
3. “共享我的 Internet 连接”选择正在连接校园网的 **Wi-Fi/WLAN**，不要选 FPGA 测试用的以太网。
4. “共享方式”选 Wi-Fi。
5. 在属性里点“编辑”，把热点名设为 `Vera-OrangePi`，自己设置一个至少 8 位的密码。如果有频段选项，先选 2.4 GHz，点保存。
6. 开启“移动热点”。电脑继续连接校园网，不要断开校园 Wi-Fi。
7. 在香橙派点网络图标，选择 `Vera-OrangePi`，输入刚设的 **电脑热点密码**。此处不填校园账号。
8. 香橙派无线 IPv4 保持自动/DHCP；有线 `eth0` 的 FPGA 地址不改。

这是 Windows 自带的网络共享功能，设置位置见 [微软移动热点说明](https://support.microsoft.com/en-us/windows/experience/connectivity-networking/use-your-windows-device-as-a-mobile-hotspot)。网络来源是校园网，电脑热点本身不使用手机套餐流量。

香橙派连接成功后，运行：

```bash
ip -4 -br addr
```

找 `wlan0` 行，记录它的 IPv4。Windows 共享网络常见为 `192.168.137.x`，但必须以实际输出为准。以下用 `192.168.137.123` 举例，**不是要求把香橙派设置成这个地址**。

在电脑 PowerShell 先把这个变量换成实际查到的香橙派地址：

```powershell
$opiAddress = "192.168.137.123"
```

之后本文的 PowerShell 命令都使用 `$opiAddress`。关闭 PowerShell 后重新打开，需要重新设置这个变量。不要继续使用已经脱离的手机热点地址 `192.168.43.142`。

如果 Windows 提示无法开启热点，把错误提示发我；如果香橙派能连电脑热点但网页打不开，先确认共享来源选的是校园 Wi-Fi，电脑本身也仍能上网。不要反复重装 Python。

## 2. 两条连接分别负责什么

```text
校园网 ── 电脑 Wi-Fi ── Windows 电脑热点 ── 香橙派 wlan0
                      远程编辑、传文件、共享校园网

FPGA 网口 ─── 网线 ─── 香橙派 eth0：图像和控制数据
192.168.10.2          192.168.10.3/24
```

电脑热点连接不影响 FPGA 的有线连接。香橙派 `eth0` 保留 `192.168.10.3/24`，不填写有线网关或 DNS。电脑有线网口若也接入这个测试网段，使用 `192.168.10.4`；本次电脑不必接测试网线。电脑校园网地址与共享网络地址不同是正常的，Windows 会建立共享接口，不需要把电脑 Wi-Fi 改成香橙派的 IP。

如果直接用校园网络的 SSH 已能通，继续保留它即可；第 1.4 节共享路径用于校园网限制设备互通时。两种方式都使用校园网流量，不需要手机套餐。直接校园网和电脑热点的地址可能变化，后续命令均使用实际的 `$opiAddress`，不是固定某个无线 IP。

## 3. 香橙派启用 SSH

以下在 **香橙派终端**运行，提示符一般是 `orangepi@orangepi5`：

```bash
sudo systemctl enable --now ssh
systemctl is-active ssh
```

看到 `active` 就继续。如果提示 `Unit ssh.service could not be found`，需要安装服务器：

```bash
sudo apt update
sudo apt install openssh-server
sudo systemctl enable --now ssh
```

如果 apt 又出现之前的 `Hash Sum mismatch`，先按第 5 节处理软件源；可以先通过 U 盘把本次唯一的 ZIP 放到香橙派。

接着在 **电脑 PowerShell**运行：

```powershell
Test-NetConnection $opiAddress -Port 22
ssh "orangepi@$opiAddress"
```

`TcpTestSucceeded: True` 表示 SSH 端口已通。第一次连接会显示主机指纹；可在香橙派执行 `sudo ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` 核对。确认是你的设备后输入 `yes`，再输入香橙派账户密码。密码输入时不显示字符。

成功后电脑终端会变成 `orangepi@orangepi5`。输入 `exit` 返回 PowerShell。

如果电脑已接热点且 SSH 为 active，仍然超时：

1. 再核对 `wlan0` 的当前 IP，不沿用已变化的地址。
2. 在香橙派运行 `ss -lnt | grep ':22'`，确认服务在监听。
3. 在香橙派运行 `sudo ufw status`。若防火墙 active 且禁止 SSH，可运行 `sudo ufw allow OpenSSH`；若 inactive，则不需要改它。
4. 确认香橙派连的是电脑的 `Vera-OrangePi`，不是仍连接手机或尝试校园 Wi-Fi。电脑移动热点必须保持开启。不要为此修改 FPGA 的 IP。

## 4. 安装这一个客户端包

### 4.1 把 ZIP 传到香橙派

电脑上的固定文件是：

```text
D:\GOWIN_PROJECTS\deliverables\acg720-orangepi.zip
```

先看终端左侧的提示符，判断命令实际在哪台设备执行：

| 提示符 | 当前操作的设备 | 可以使用的路径 |
| --- | --- | --- |
| `PS C:\...>` | Windows 电脑 | `D:\GOWIN_PROJECTS\...` |
| `orangepi@orangepi5:~$` | 香橙派，即使窗口在电脑上 | `/home/orangepi/...` |

SSH 登录成功后，当前终端已经切换到香橙派。香橙派不能直接读取电脑的 `D:` 盘；在那里执行 Windows 的 `scp` 命令，会把 `D:` 当作远端主机名，报 `Could not resolve hostname d`。Windows PowerShell 的 `$opiAddress` 变量也不会自动传到香橙派的 shell。

**第一步，在当前香橙派 SSH 终端输入：**

```bash
exit
```

这只退出 SSH，不会关闭香橙派。看到 `PS C:\...>` 就回到了 Windows。也可以保留 SSH 窗口，另开一个新的 PowerShell 标签页传文件。

**第二步，确认当前是电脑 PowerShell，执行：**

```powershell
scp "D:\GOWIN_PROJECTS\deliverables\acg720-orangepi.zip" orangepi@192.168.137.80:/home/orangepi/
```

输入香橙派用户密码，等待传输完成。这条命令把电脑的 ZIP 复制到香橙派主目录，电脑原文件仍保留。`scp` 通过 SSH 传文件，见 [微软 OpenSSH 工具说明](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh-overview)。当前地址是 `.80`；若以后 DHCP 分配了新地址，替换成实际地址。

**第三步，仍在电脑 PowerShell，重新登录：**

```powershell
ssh orangepi@192.168.137.80
```

看到 `orangepi@orangepi5:~$` 后，执行下面第 4.2 节的 Linux 解压命令。

如果 SSH 还未安装，这次先用 U 盘把 ZIP 复制到香橙派主目录 `/home/orangepi`。使用文件管理器的 Home，不是打开压缩包后就算解压了。

### 4.2 解压，只在香橙派执行

先确认主目录没有已经被你修改过的 `acg720_vision` 目录。第一次安装时执行：

```bash
cd ~
python3 -m zipfile -e ~/acg720-orangepi.zip ~/
cd ~/acg720_vision
ls
```

应看到 `client.py`、`pc`、`tools`、`README.md` 和 `manifest.json`。`pc` 内的几个 Python 文件是配套模块，都要保留，但日常不需要分别启动它们。

旧 V2 目录先不动。新目录确认能运行并保留照片后，再按第 8 节清理。

`apt update` 成功后再运行安装命令。若仍失败，把实际错误发我；不要关闭软件包校验。先确认香橙派通过电脑共享的校园网能正常打开网页，不使用手机流量下载依赖。

安装完成后再次执行上面的依赖检查。

### 5.1 所有软件源都报 `Could not resolve` 时

2026-10-04 的实际日志已显示 ZIP 传输成功、解压成功；`No module named 'cv2'` 表示当前系统 Python 缺少 OpenCV。随后所有 APT 域名都报 `Could not resolve`，说明域名解析失败，索引没有成功更新。后续已经确认默认路由正确、DNS 为空，直接按第 5.2 节修复；下面保留只读诊断方法。

已在电脑侧核对：可以连接阿里源 HTTPS，热点地址仍为 `192.168.137.1/24`，网络共享服务正在运行。不要重复解压、换软件源或删除 Python 环境；先确认香橙派能通过热点上网。

在 **香橙派 SSH 终端**逐行执行，把输出交给我判断：

```bash
ip -4 -br addr
ip route
nmcli -f GENERAL.CONNECTION,IP4.GATEWAY,IP4.DNS device show wlan0
cat /etc/resolv.conf
```

`nmcli` 可显示当前接口的连接、网关和 DNS，参见 [NetworkManager 1.36 官方手册](https://networkmanager.dev/docs/api/1.36/nmcli.html)。正常热点上网应有经 `192.168.137.1`、从 `wlan0` 出去的默认路由。`resolv.conf` 指向 `127.0.0.53` 时可能正在使用本地 DNS 服务，不应仅凭这个地址判定错误。先读实际配置，不直接覆盖该文件，不在 SSH 会话里随意关闭 Wi-Fi。

修复后先确认域名能解析：

```bash
getent ahostsv4 mirrors.aliyun.com
```

然后执行 `sudo apt update`。只有日志没有本次域名解析/索引下载失败，才继续：

```bash
sudo apt install python3-opencv python3-numpy
python3 -c "import cv2, numpy; print('Dependencies OK')"
```

SSH 当前已正常运行，不需要为这个错误重新安装 SSH。APT 在网络失败后仍可能显示 `Done` 并使用旧索引，这不等于更新成功；判断要看 `Err`、`Failed to fetch` 和具体报错。

不依赖 OpenCV 的收图检查可以先做：接好 FPGA 与香橙派网线，确认 `eth0` 已有 `192.168.10.3/24`，关闭其他接收程序，在 SSH 中运行：


## 10. 用这次连接复习 IP、子网、路由和 NAT

### 10.1 `ip -4 -br addr` 只是查看地址

在香橙派终端执行，不会更改网络配置：

```bash
ip -4 -br addr
```

| 部分 | 含义 |
| --- | --- |
| `ip` | Linux 的网络管理命令，可以查看或配置接口、地址、路由等 |
| `-4` | 本次只显示 IPv4，不显示 IPv6 |
| `-br` | `--brief` 的缩写，使用简洁的表格输出 |
| `addr` | `address` 的缩写，查看接口上的 IP 地址；这里省略了 `show` |

因此可以理解成“简洁地查看各个网络接口的 IPv4 地址”。参数说明见 [ip 命令手册](https://man7.org/linux/man-pages/man8/ip.8.html)。

按照目前的配置，主要输出类似这样：

```text
lo      UNKNOWN   127.0.0.1/8
eth0    UP        192.168.10.3/24
wlan0   UP        192.168.137.80/24
```

第一列是接口名，第二列是状态，第三列是地址和前缀长度。`lo` 是本机回环接口，`127.0.0.1` 指自己，`UNKNOWN` 在这里通常正常。`eth0` 是接 FPGA 的有线网口，`wlan0` 是接电脑热点的无线网口。`UP` 不能单独证明可以上网或可以 SSH 登录。

IP 地址配置在接口上，所以一台香橙派可以同时拥有有线地址 `.10.3` 和无线地址 `.137.80`，它们并不冲突。

### 10.2 `192.168.137.80/24` 怎么读

`192.168.137.80` 是这个接口的 IPv4 地址。IPv4 总共 32 位，`/24` 表示前 24 位是网络部分，剩下 8 位是主机部分，对应子网掩码 `255.255.255.0`。

| 项目 | 本例的值 |
| --- | --- |
| 网络地址 | `192.168.137.0/24` |
| 电脑热点接口地址 | `192.168.137.1` |
| 香橙派无线接口地址 | `192.168.137.80` |
| 通常可分配的主机地址 | `192.168.137.1` 至 `192.168.137.254` |
| 广播地址 | `192.168.137.255` |

这里的 `/24` 既不是端口号，也不是“24 台设备”。因为恰好按整字节分界，本例可以看前三段判断子网；遇到 `/21` 等其他前缀，必须按掩码计算，不能套用“前三段相同”的判断。

### 10.3 当前的完整连接

```text
校园网 / 互联网
       │
电脑 WLAN：10.9.76.199/21
电脑热点：192.168.137.1/24
       │ Wi-Fi：电脑分享校园网
香橙派 wlan0：192.168.137.80/24
香橙派 eth0：192.168.10.3/24
       │ 网线
FPGA：192.168.10.2/24
```

电脑和香橙派的热点接口属于 `192.168.137.0/24`，香橙派与 FPGA 的网口属于 `192.168.10.0/24`。这两个子网承担不同用途，不需要把它们改成同一个子网。

**电脑访问香橙派：** 执行 `ssh orangepi@192.168.137.80` 后，电脑查询路由表，发现目标位于自己的热点子网，于是从热点接口发送；通过 ARP 获得目标的 MAC 地址，再建立 TCP 22 端口连接。这段通信不需要绕行校园网关。电脑上的路由查询已确认目标使用热点接口，`NextHop=0.0.0.0` 表示目标直接在链路上，不是让你把网关填写为 `0.0.0.0`。

**香橙派访问互联网：** 外部目标不属于上述两个直接连接的子网时，通常交给默认网关，即电脑的热点接口 `192.168.137.1`。电脑共享网络时执行 NAT，将香橙派的私有源地址和端口映射为电脑校园网接口的地址和端口，再发给校园网上游；回包按映射返回香橙派。电脑在这里兼任无线接入点和网关。热点通常通过 DHCP 自动给香橙派分配地址、网关和 DNS，所以不要手动把香橙派无线地址改成电脑的 `.1`。这次上游是校园网，**不会使用手机流量**；电脑和热点需要保持开启。

**香橙派接收 FPGA 图像：** FPGA 发往 `192.168.10.3` 的 UDP 6102 数据通过网线进入香橙派 `eth0`；香橙派发往 `192.168.10.2` 的数据也从 `eth0` 走，不经过电脑热点。SSH 和图像接收可以同时进行。

之前电脑与香橙派虽然连接相同校园 Wi-Fi 名称，但分别在不同子网，必须经过校园网络路由才能互通。校园网络可能限制这类访问；仅凭超时不能确定具体是哪条网络策略。现在使用电脑热点，SSH 走本地链路，已经测得 22 端口可达。

### 10.4 地址决定去哪里，端口决定交给哪个程序

| 用途 | 目标地址 | 传输协议与端口 |
| --- | --- | --- |
| 电脑远程登录香橙派 | `192.168.137.80` | TCP 22，SSH 服务 |
| FPGA 发送图像给香橙派 | `192.168.10.3` | UDP 6102，图像接收程序 |

可以把 IP 理解成目的地地址，端口理解成这个目的地上负责某种服务的入口。两台设备处在同一子网时，地址必须不同；TCP 和 UDP 的端口空间也分别独立。

在香橙派终端可以做三个只读练习：

```bash
ip route
ip route get 192.168.10.2
ip route get 1.1.1.1
```

第一个显示路由表，第二个应选择 `eth0`，第三个正常应经 `wlan0` 的默认网关。`ip route get` 只是询问内核“如果发往这个地址会怎么走”，本身不证明目标在线，也不是在向它发送 ping。若默认路由错误地选了 FPGA 网口，应检查有线连接是否误填了网关；FPGA 直连网口不承担上网用途。

## 12. 通信测好后做什么，怎样计划转接 PCB

### 12.1 先把图像和控制链路验收清楚

1. `probe --seconds 30` 有完整帧；在香橙派桌面 `view` 连续运行，观察画面、帧率和错误统计，先以连续 10 分钟不退出为目标，记录实际结果。

3. 分别记录高斯滤波开/关时的实际画面和收图表现。训练数据使用实际发送的 400×240 图像；不要把界面文字截图当作训练图。先做两组小样本比较，再决定是否固定滤波，不能预先保证高斯滤波会提高识别率。
4. 保存一次测试日志、LCD 照片、香橙派画面，作为阶段验收资料。之后可继续三类数据采集和预训练模型试运行，同时推进传感器接线规划。

### 12.2 冻结已有接口，再分配扩展接口

已有摄像头、LCD/GT911、DDR3、网口、按键和 LED 映射以 `src/lcd_interaction.cst` 为准，暂不改动。CST 没使用的脚不一定是空闲脚，还可能连着板载外设。

规划时核对以下原始硬件资料，它们没有被这次清理删除：

- `D:\GOWINNN\06_硬件图纸\ACG720-138&60K通用原理图.pdf`
- `D:\GOWINNN\04_引脚功能信息\高云 ACG720-138&60K通用管脚分配表.xlsx`

**纠正：本版官方原理图与引脚表中，P7 GPIO0 在 BANK2、HDMI 在 BANK7，球位没有重叠。**此前“GPIO0 与 HDMI 共用”说法没有依据，已撤回。P7 的 40 针包含 36 个数字 GPIO 和电源/地；P3 的 4 针是 DAC 模拟输出，P5 的 16 针是 ADC 模拟输入，P8 的 8 针只有三个 USER 信号及电源/地/未标功能脚，不能合计为 68 个数字 IO。GPIO0 的 VCCIO 由跳帽选择，使用 3.3V 数字接口前需确认实物。

已核对 TOF200C 和 LSM6DSV16X 资料，按下面方案分配 FPGA 信号；模块实际针序、供电和默认电平仍需确认，尚不是可直接上电的接线表：

| 模块 | 接口假设 | 信号数量 |
| --- | --- | ---: |
| 六轴 IMU | I²C + 中断 | 3 |
| 四个 TOF200C/VL53L0X | 共用 I²C＋四路独立 XSHUT | 6 |
| 超声波 | Trig/Echo | 2 |
| TB6612 双电机控制 | 两组方向/PWM + STBY | 7 |
| 两台电机霍尔编码器 | 每台 A/B 两路 | 4 |
| 硬件急停状态 | 独立输入 | 1 |
| 调试串口预留 | TX/RX | 2 |
| 两块电池监测 | 独立 I²C，共用两线 | 2 |
| 合计 | 电源、地另算；暂不接电池 ALERT | 27 |

若为两个步进驱动器预留 STEP/DIR/EN，共再占 6 根，本期共 33 根，P7 剩 3 根；两路普通舵机控制通常只加 2 根。若再接两路电池 ALERT，共 35 根、剩 1 根。四个 TOF 必须通过 XSHUT 依次分配不同地址，不能默认同址并联；若没有可用 XSHUT，就改为四组独立 I²C，并把电池总线移到备用脚，重新映射。最终每个接口都形成一行：**模块脚 → 电平转换/供电 → ACG720 连接器脚 → 60K FPGA 封装脚 → Bank 电压 → 输入/输出 → 上电默认值 → 复用冲突**。已核对的 P7 全表、4Pin/6Pin 分组、初始化与电机抗干扰说明见工程 `docs/扩展板规划.md`，公开仓库也保留同名文件。

### 12.3 下一次先提供这些资料，再画 PCB

已收到 TOF200C、CS100A、LSM6DSV16X、TB6612 和 MG513 电机资料。还需要 TOF/IMU 的模块针序和供电说明、编码器六线定义与实际减速比、手边电源规格，以及板卡跳帽和安装尺寸。只有芯片手册仍可能缺少模块板上的上拉、稳压和电平转换信息。TB6612 继续沿用你们电赛组合；布线方案按 3.3V 逻辑、电机独立支路、可靠共地、默认禁能设计。

图示电池为标称 11.1V、满充 12.6V。当前建议两块电池：A 经稳压支路供 FPGA（拟 9V，官方整板输入 6～12V）及香橙派（必须稳定 5V），B 供电机。扩展板预留两路 INA226 电压/电流监测和低电通知；BQ25504 是能量采集芯片，不用于这块电池。正常关机通知、确认及香橙派后台服务仍待编写，当前 R4 不具备这项功能，详见扩展板规划第 12～13 节。

然后按这个顺序推进：核对接口和电平 → 给最容易安全接入的传感器画临时接线表 → 单模块上板验证 → 逐个验证剩余传感器 → 冻结完整引脚表和电源方案 → 画转接 PCB → 悬空低速测试电机/编码器 → 速度闭环和避障。

没有万用表时先完成资料和原理图规划；实际接线前借用或准备一个，用来检查供电和短路。短杜邦线可用于核对过电平的低电流传感器台架测试；电机电源不能经 FPGA 电源插针或细杜邦线承载。PCB 应提供合适接插件、去耦、电平转换、测试点、默认禁能和硬件急停路径。

例如 [TB6612FNG 原厂手册](https://toshiba.semicon-storage.com/info/docget.jsp?did=10660) 中输入高电平门限是 `0.7×VCC`，逻辑 VCC=5 V 时最低为 3.5 V，不能保证 FPGA 3.3 V 输出被识别。模块是否支持逻辑 VCC=3.3 V、编码器是否输出 5 V、超声波 Echo 电平和 I²C 上拉电压，都必须逐项确认。

## 13. HDMI 会让 UI 更好看吗，是否需要买屏

**HDMI 是连接接口，LCD 是面板类型；很多 HDMI 屏本身就是 LCD。**这里实际比较的是“当前 40P 并行 RGB 屏”和“带 HDMI 接收/驱动板的显示器”。

UI 的字体、布局、按钮、中文和手势主要由绘制界面的程序决定。点锡机的 Python/PyQt5 界面采用的基准同样是 1024×600；它的效果不能归功于 HDMI。Qt 提供控件、布局、样式表和缩放能力，见 [Qt Widgets 官方文档](https://doc.qt.io/archives/qt-5.15/qtwidgets-index.html)。

| 方案 | 谁绘制 UI | 优点 | 代价 |
| --- | --- | --- | --- |
| FPGA → 当前 RGB LCD | FPGA | 已正常工作，GT911 已有驱动，能展示 FPGA 直接显示与交互 | 丰富字库、动画和复杂控件需要自己实现；排线安装需固定 |
| FPGA → HDMI 显示器 | FPGA | 标准显示线，便于接通用显示器；可另选尺寸/面板 | 仍需写 UI，并新增扫描、编码、时钟和约束适配；触摸需另处理 |
| 香橙派 → HDMI 显示器 | 香橙派 | Linux/Python/Qt 更容易做中文和复杂交互 | 这部分 UI 由香橙派完成，要在分工说明中写清 |

高云官方 HDMI 示例采用 DVI/TMDS 视频输出，需要像素时钟和串行时钟，不能把当前 RGB 输出直接换几个引脚就完成，参考 [高云 DVI TX/RX IP 指南](https://cdn.gowinsemi.com.cn/IPUG938.pdf)。实际需要核对 60K 器件与该口的兼容模式。HDMI 视频线通常不传递这种显示器的触点数据；例如 [微雪的 1024×600 HDMI LCD](https://www.waveshare.com/wiki/7inch_HDMI_LCD_%28C%29) 另用 USB 传触摸。香橙派处理 USB 触摸和 FPGA 实现 USB 主机/HID，是两种不同工作量。

更高分辨率、IPS 面板、亮度和视角可能改善观感，但这些取决于具体屏幕规格。当前网络画面为 400×240，LCD 摄像头窗口为 800×480，换 1080p 屏首先是放大已有图像，不能自动增加摄像头细节。

**当前建议：先不买新屏。**继续用 FPGA LCD 展示摄像头、滤波、触摸和后续传感器状态，用手边香橙派 HDMI 显示器显示桌面及后续 Python 界面。这样可以同时突出 FPGA 的采集、预处理和实时控制，也能获得更丰富的交互。若要试 FPGA HDMI，先借用现有显示器验证官方兼容模式；触摸和 PCB 引脚另行确认后再决定采购。

## 14. 当前 R4 如何写入 Flash，开机自动运行

SRAM Program 断电丢失配置；写入外部 Flash 才能上电自动装载。普通用户逻辑复位不等于重新配置按键。

先确认当前 `impl\pnr\vision_robot_ui.fs` 的摄像头、UI 和通信符合预期，再在 Gowin Programmer 操作：

1. 器件保持 `GW5AT-60B`，双击 Operation 打开 Device Configuration。
2. 本机 V1.9.11.03 中 Access Mode 选 `External Flash Mode 5A`。
3. Operation 选 `exFlash Erase,Program,Verify thru GAO-Bridge 5A`。
4. File name 选当前 `vision_robot_ui.fs`，Flash Type 先保持 `Generic Flash`，起始地址保持 `0x000000`。
5. Save 后下载，等待擦除、写入、校验完成；这会替换原来保存在 Flash 的开机程序。
6. 断电再上电，不再点 SRAM 下载；核对 LCD 和香橙派收图，确认自动启动。

新版工具将 5A 称为 Arora V，参考 [Gowin Programmer 官方指南](https://cdn.gowinsemi.com.cn/SUG502.pdf)。若选项不一致，先核对工具版本，不随意改成 Internal Flash 或 Slave SPI。后续 SRAM 下载可临时试新代码，断电后仍回到 Flash 保存的版本。
