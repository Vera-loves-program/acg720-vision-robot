# 香橙派客户端：公开说明

当前 FPGA 工程只使用 R4：`vision_robot_ui.gprj`，客户端只使用 `client.py`。旧项目入口及重复操作文档已整理，Git 保留历史。

这是不包含实际校园网、主机地址和个人部署配置的公开简版。完整逐步操作指南保留在使用者电脑的 `deliverables/香橙派使用说明.md`，客户端 ZIP 中的 README 与该本地指南一致。请按自己的接口和地址配置运行环境。

客户端提供四个入口：`view` 显示视频，`probe` 检查协议和完整帧，`capture` 交互式采集，`burst` 无窗口连拍。图形入口应从香橙派桌面启动，普通 SSH 不会自动转发窗口。传文件的命令应在源文件所在电脑运行；SSH 登录后的终端操作远端设备。

`probe` 只依赖 Python 标准库，可在尚未安装 OpenCV 时检查协议。软件源都出现域名解析失败时，先检查网络路由和 DNS；APT 使用旧索引并显示完成，不代表更新成功。OpenCV 安装后才能运行图形预览。

客户端包版本 5 修复了 GTK 窗口误退出：某些 OpenCV 后端不支持 `WND_PROP_VISIBLE`，不能把负值直接认定为窗口关闭。查看器和拍照入口都使用兼容检查，启动日志显示 GUI 后端，退出日志显示原因。更新客户端即可，FPGA 仍使用 R4；照片和现有 Python 环境保留。桌面已登录且 X11 套接字为 `X0` 时，可从 SSH 用 `DISPLAY=:0 python3 client.py view` 在设备本地屏幕显示窗口；这不是把窗口转发到电脑。SSH 终端可用 Ctrl+C 退出。

若已确认路由正确而 DNS 服务器为空，应先按当前网络环境补充 DNS 并验证解析，再保存连接配置和安装依赖。本地完整指南包含对应步骤；公开说明不提供实际网络服务器地址。

SSH 卡顿或断线时先核对重启后的地址、无线状态和日志；已知的主动断电不能当成设备供电故障证据。可用临时有线直连区分无线链路与系统问题；移开 FPGA 网线期间停止收图是预期现象。SSH 心跳不替代链路故障排查。

照片保留在固定客户端目录的 `dataset` 内，不上传公开仓库。旧目录必须检查个人代码和照片后才能清理，建议先移入回收站。客户端依赖为 Python、NumPy、OpenCV；ARM Linux 环境与电脑虚拟环境不能直接互拷。

通信测稳后，先查各传感器模块的供电、逻辑电平和协议，再验证模块和冻结接线表，最后设计转接 PCB。既有 LCD、摄像头、DDR3、网口等映射保留。本版官方原理图和引脚表中，P7 GPIO0 与 HDMI 球位不重叠，撤回此前共享说法。P7 的 40 针提供 36 个数字 GPIO，VCCIO 可选；4 针 DAC 和 16 针 ADC 接口是模拟信号，不计作普通数字 IO。具体核对表、分组和模块待确认事项见 [扩展板规划](扩展板规划.md)。

已核对 TOF200C 为 VL53L0X I²C 模块、超声波为 CS100A 新版、IMU 为 LSM6DSV16X。四路 TOF 拟共用总线并用独立 XSHUT 分配地址，轮询不接中断；另预留两块电池的独立 I²C 监测，本期数字信号共 27 根，加两个步进驱动预留共 33 根；实物没有 XSHUT 时需另用四路总线、重新映射。MG513＋TB6612 沿用已有台架方案，模块针序、电源、3.3V 逻辑和默认禁能仍要逐项落实。电源建议逻辑和动力分两块电池，板卡支路稳压；INA226 监测和低电正常关机仍为方案，不是当前 R4 已有功能。队友的两份资料分别为小狗标注与 YuNet 离线检测结果，没有训练权重，具体见 [视觉模型与数据检查](视觉模型与数据检查.md)。

HDMI 是接口，LCD 是面板类型。换 HDMI 不会自动改善 UI；复杂控件和字体能力主要来自渲染程序。建议先保留正常工作的 FPGA RGB LCD，用现有香橙派显示器开展软件界面开发；如需测试 FPGA HDMI，先用现有显示器验证适配，再确定触摸与转接板方案。

公开仓库仅包含自编维护文件，厂商依赖、个人照片和位流保留在本地。不是完整厂商工程备份。
