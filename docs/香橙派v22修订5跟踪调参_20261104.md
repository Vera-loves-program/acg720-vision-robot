# Pi v22修订5：先核对限位，再调跟踪

本轮只更新Pi应用代码，FPGA位流与协议不变，不重刷系统，不覆盖现场`config/gimbal.json`、`config/visual_task.json`和模型。代理没有连接Pi或操作舵机。本机和队友包都没有Pi现场标定，因此不能凭示例断言你的当前限位变了。

## 本次改了什么

1. 修复真实可复现的居中后乱动：上一有效帧的脸中心只偏6.4像素，已在12.8像素死区内，旧App仍保存RAW误差对应的居中目标；随后一次丢框会把PAN从1500发到1509微秒。新版居中立即取消该轴待执行移动，丢框/歧义保持位置，明确重现后自动确认恢复，不再执行旧预测。
2. 原来按每帧不断累加角度请求，同方向最多可积累15度命令超前。现在每个新帧替换一个有界绝对目标，补偿拍摄后已发送的命令位移，由50Hz控制环按限速/加速度逼近。200ms没有新的跟踪观测就保持；较慢图像会限制等效增益。这里仍用PWM标定角估计，不是舵机真实角反馈，不能声称已辨识机械响应。
3. FOL由50ms改20ms发送，与FPGA PWM帧周期相配；VEC/GOL仍50ms，TGT仍200ms。发送成功不等于FPGA已经应用，网页分开显示Pi请求/输出及最近FPGA回报。
4. 区分探索边界、机械限位、角度表覆盖、TILT>=90度运行边界。原网页会把90度裁剪误写成机械限位并引导清表；已修正。保存前纯预检查，避免写盘成功、应用失败造成两套配置；TILT旧表先保留，允许用合法新实测点替换。
5. 页面增加实际控制依据、像素误差、观测年龄、加速度参数与配置SHA。相机预览画出真正控制中心和死区；存在相机内参时，十字使用主点，与控制算法一致。

有图像内参时控制使用角度增益`gain`；没有内参时使用图像增益`normalized_gain_dps`。旧网页只展示后者，可能调了不生效的参数。两者现在明确标注。图像采样Jacobian仍可使用，不覆盖旧采样。

## 2. 先读出现有限位，不先清空

Pi SSH只读命令：

```bash
python3 -c "import json; c=json.load(open('config/gimbal.json')); print(json.dumps({k:c.get(k) for k in ('axes','mount','tracking')},ensure_ascii=False,indent=2))"
```

网页“手动调节”中每轴的范围说明分四层：

| 范围 | 意义 |
|---|---|
| 探索边界 | 软件允许录入的脉宽范围，不是已测机械端点 |
| 机械限位 | 你保存的safe_min_us / safe_max_us |
| 角度表 | 实测脉宽与连续角度对应关系 |
| 运行窗口 | 机械/角度表与TILT>=90度要求共同得到的可用范围 |

记录或截图两轴这四组值和当前输出。不能把340、380、645、2420等历史测试值直接填到你的车上；更不能把90度的软件下限记成机械端点。暂时不点击“清除本轴记录”。更新包保留原标定，限位本身不会自动重新测量。

按原先能安全开启的脉宽开启PWM，先每次只调一轴、细步5微秒；每次等输出停止变化并观察机构。可由现场表只读换算TILT135度对应的脉宽：

```bash
python3 -c "import json,sys; sys.path.insert(0,'pc'); from gimbal_control import AxisConfig; c=json.load(open('config/gimbal.json')); print('TILT135 PWM=',AxisConfig.parse(c['axes']['tilt']).angle_to_pulse(135),'us')"
```

用换算出的TILT脉宽作为手动待输出，不照抄旧1076/2100；已经开启时也可在“角度标定→到指定角度”输入135。用量角器核对你原来采用的连续舵机角定义。若实际角明显错误，保留旧表，在90度以上选三个可达姿态重新实测、替换所选轴表，再保存；不要把整张表统一加180度。TILT始终不要求转到90度以下。

PAN同样先核对原表中间位置和小步运动，再核对两端。发现机械卡住、线缆拉紧或继续加脉宽不再转时退回，不靠扩大探索范围让它继续顶住。只保存真正测出的端点；新限位若排除旧角度点，应整理成覆盖新范围的有效实测表再保存，不能清TILT表后盲开。

## 3. 先用人脸和标准档测试

底盘停止，从网页操作，暂时不同时从LCD选择目标。先点“目标跟踪→标准→应用速度”，这会暂停跟踪。重新选择人脸，再开始跟踪。

标准档保存的初值：

| 参数 | 初值 | 怎样使用 |
|---|---:|---|
| 两轴PWM变化率 | 600us/s | 不是实际转速，仍受机械响应限制 |
| 图像增益 | 60 | 无相机内参时使用 |
| 角度增益 | 3.0/s | 有相机内参时使用；看页面控制依据 |
| 最高角速度 | 45deg/s | 小误差时不会一直按此速度转 |
| 加速度上限 | 180deg/s² | 抑制突然大幅跳变 |
| 中心死区 | 0.04 | 640×480时中心左右各12.8px、上下各9.6px |
| 低通时间 | 0.06s | 平滑框抖动，过大会增加延迟 |
| 死区迟滞 | 0.015 | 避免在停止边界来回启停 |
| 最小转速 | 0 | 居中附近不强行维持最低转速 |
| 单帧积分上限 | 0.10s | 保留原目标跟踪配置的时间界限；实际输出由短时目标控制器推进 |

速度档保留你原来的死区/滤波设置；上述后三项如果旧值不同，请在“跟踪参数”填入并应用。每次应用会暂停，重新选人脸、开始。只调整正在生效的增益，不要同时改两轴机械表、安装方向和增益。

测试顺序：

1. 人脸在十字中心静止20秒：包括轻微检测框抖动/一次短暂丢框，观察PWM是否停止。先确定不会自行跑偏。
2. 人脸缓慢向左/右移动各两次，再上下移动：确认它把脸往中心带回。若方向反了，立即暂停，检查安装方向/角度表或重新做图像采样，增加增益不会修正反向。
3. 中速左右移动，然后突然停下：比较是否跟上、过冲和停稳时间。不要一开始用快速档大幅摆动。
4. 暂时遮住脸再出现：丢失时保持；明确同类目标连续三帧确认后恢复。它不会识别人物身份，多人交叉不能保证一直是同一个人。

## 4. 一次只改一个参数

- 中心附近反复动：先看实际像素误差是否也跳变。确认最小转速为0；仍抖时，生效增益降20%（60→48或3→2.4），每次重新测20秒。不要先扩大限位。
- 方向正确、无抖动但追不上：先看观测年龄/人脸推理耗时、Pi输出是否落后于请求、FPGA回报是否更新。网络未应用或图像过期要先处理对应链路；不是增加P就能解决。
- 图像新、命令都应用且仍跟得慢：生效增益每次加20%，先不动45度/s上限。达到上限仍慢，再比较更高PWM变化率/角速度，保留同场录像与日志；没有实测轴角不能把命令速度当成真实速度。
- 追上后冲过中心：先降增益；加速度可180→120，低通若过大可0.06→0.04。低通越大不一定越丝滑，它也会让反馈变迟。
- 固定一方向到限位：检查目标位置、运行窗口、安装和标定，不能用更大速度去顶限位。

## 验证与限制

本轮执行真实Python控制/关联/配置代码的离线测试，包含独立相机投影、一阶机械滞后、执行/推理延迟、目标移动、抖动/丢框、限位与停止；不是舵机实测。初步同场模拟的移动误差没有显著改善，因此不宣称已解决所有跟踪滞后。已证实的是居中后丢框不会再执行旧偏移、命令超前更小、配置诊断更准确。252项Python回归、62个实际HTTP响应及网页回调和只读采集器模拟检查通过；测试期间输入哈希未变。详细哈希和同场旧/新模拟对比见源码仓库`docs/validation/pi-tracking-r5-20261104.json`。

控制设计参考图像误差到相机速度的视觉伺服思路：[Chaumette/Hutchinson原论文](https://web.mit.edu/amcp/OldFiles/drg/Chaumette_Part_I.pdf)、[ViSP原项目例程](https://github.com/lagadic/visp/blob/master/example/servo-afma6/servoAfma6Points2DCamVelocityEyeToHand.cpp)。本项目的延迟预算和参数仍需这台机构实测，不能由论文证明硬件稳定。
