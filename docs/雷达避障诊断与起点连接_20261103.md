## 二、观测与障碍的语义

1. `lidar_ready`是驱动节点链状态；`avoid_lidar_ready`额外检查完整扫描年龄；`body_guard_ready`包括配置、完整投影处理和过期/overrun。它们都不表示区域空闲。
2. 原`coverage`及F/R/L/Back计数只表示非SELF有效外部命中。质量0、距离无效、无回波、SELF均不提供FREE证据。无回波推断策略未启用。
3. `free_coverage`在此表示**采样可见性支持**：每90°32个bin、全圈128bin；bin内需要相邻且角距连续的两条有效非SELF远射线，且都超出行驶矩形和转向圆。该bin任意更近外部返回对本圈作否决。
4. 这不是连续空间无障碍的数学证明，更不是将整扇区刷FREE。地图逐束射线和规划器对实际几何的FREE检查仍独立执行；地图中的UNKNOWN/暂态占据/稳定占据都阻挡。因遮挡或稀疏采样缺证据时，仍可能正确拒行。
5. 普通确认容差为角差≤3°、距离差≤60mm的相邻有效点。这是可审阅的工程参数，不是C1通用质量阈值或精度保证。原始quality保留，并从guard真正传入`u_map`，不再硬连1。
6. 未确认单点仍进入地图，因此可能暂时形成占据并使规划保守；没有为了消噪把真实点删除。后续有效FREE射线仍按11→10→01清除旧占据。

实时body链不依赖地图冻结、显示ROI或LCD缩放。世界模式规划仍需要新鲜gyro/pose和合格积分，完整扫描不保证所有必需空间已知。人工DRIVE调试不是自动避障任务，不用它证明NAV保护。

## 三、单UNKNOWN反例的几何证明

底层细格不变：128×128，64mm/格，原点(-4096,-4096)。细格(58,64)为X[-384,-320]、Y[0,64]。

旧根粗格以0为中心，可能位置为[-64,64]²，再膨胀R291圆。该细格到粗格的最短距离为256mm，小于291，所以属于132格mask，UNKNOWN触发错误8。它到真实起点O=(0,0)的最短距离却为320mm，大于291；并不阻挡当前位姿的转向圆。

新规划先检查真实O的完整R291圆。若原粗格全位置检查不通过，以O为虚拟根，逐个验证到相邻完整安全粗格中心的连接。它检查“实际O与终点±60mm接受方形的AABB，再膨胀同一R291圆”的所有相交细格，UNKNOWN/占据/图外均失败。该AABB是所有模型直线连接及接受位置的保守包围盒。

例如到(+128,0)时，连接AABB为X[0,188]、Y[-60,60]，其R291膨胀不碰X≤-320的反例格；相邻粗格的全位置包络也不碰它。接受方形±60包含在粗格±64内，可以安全衔接后续粗规划模型。特殊连接不会被路径压缩跳过，也不会直接替换为用户终点。

这证明的是给定几何模型下的规划连接，不保证真实车辆无打滑或跟踪误差。仍使用旋转圆和连接AABB，未实现任意姿态矩形的最小扫掠体；狭窄斜向出口仍可能被保守拒绝。没有强制起点FREE、没有缩小车体、没有将周围UNKNOWN整体seed。原8格body seed及其零位姿限制保留并可诊断。

## 四、SELF、量化与快速停车

外参仍为R=(33,-77)mm，O到前/后/左/右232/118/119/119mm，行驶/转向/接触余量20/30/10mm；R291来自真实外廓最远角点再加转向余量。默认ZERO90°仍是未实测预置。

前向200mm正确投影约(233,-77)，处于前沿外约1mm，不能靠扩大SELF把它吞掉。真实外物和车身边缘测量误差仅凭这一点不可区分；保留保守的虚拟接触并记录raw角度、距离、quality和XY。也不清除被SELF挡住的后方射线。

Q2转整数mm量化低于1mm，Q6角度单位1/64°；12级整数CORDIC仍有角度/取整误差。934个外部坐标比较使用独立sin/cos参考：≤1m夹具每轴容差3mm，远距夹具容差20mm，这不是全输入最大误差证明，更不包含传感器测距误差、安装公差或振动。不能把这些数值直接当成允许扩大的SELF边界。

最快点处理171个50MHz时钟约3.42µs，普通双点确认再等一个有效点。20/30/10mm是几何余量，**不是实测制动距离**；扫描刷新、100Hz控制、PWM/机械响应仍需现场低速测量。

## 五、读取诊断（电脑执行）

诊断是新增VOFA操作10，wheel=0：

```text
#10000,10,0,1,0
#10001,10,0,0,0
```

第一条请求锁存记录，ACK等48字串行RAM写完；第二条读取索引0。读取索引0..47不改变运动控制权，原四条速度曲线和原命令保留。手工逐条末尾换行、等ACK。

也可先关闭占用同一COM口的VOFA，在电脑执行：

```powershell
python tools/read_robot_diagnostics.py --port COM8 --count 5 --interval 1 --output dataset/lidar_diag_20261103.jsonl
```

需要现有Python的`pyserial`。工具由现场用户执行才打开串口，本轮代理没有运行该采集命令。每条JSON包含原始48字及解码字段：

| 字组 | 记录内容 |
| --- | --- |
| 0..3 | 协议标记、nav_status/nav_fault/mission_error/planner_error、gyro有效/校准/新鲜度、三层雷达ready、扫描周期/年龄/work_bad |
| 4..8 | 采集与积分scan id、raw/usable/invalid点、解析错误/overrun、命中coverage及四方向计数、采样可见性和当前所需方向、近障/转向/接触/未确认标志 |
| 9..12 | 最近触发raw角度/距离/quality/XY及scan id；kind bit5表示400mm导航前瞻确认，其余位为前/后/慢速/转向/接触 |
| 13..20 | pose/heading、SELF数量、地图模式/ready/busy/frozen、seed_valid/seed_done、首拒绝细格带符号坐标、原状态/原因/阶段 |
| 21..25、40..43 | 半径/外廓/外参/ZERO、四向距离和余量 |
| 26..39、44..45 | 节点/串口/地图计数、用户目标/当前段、任务状态、拒行原因与修正计数 |
| 46..47 | 从未完成扫描/前瞻记录选择标志、记录epoch与混合采样标志 |

首拒绝reason：1/2/3为真实起点UNKNOWN/占据/图外；4/5/6为连接段；7/8/9为目标粗格。phase区分真实起点、连接、粗格/BFS。计数饱和值为10bit1023、方向/错误计数8bit255。年龄/周期单位10ms。

快照约96个时钟采集，不是所有模块的全局原子锁存。word47的mixed标记监控扫描/pose/gyro/积分/点确认等事件；mixed=0不能证明所有UART计数和任务状态严格同时发生。记录内部逐字冻结，直到下次显式捕获。触发记录是最近历史证据，不等于当前障碍仍在；同时看标志和scan id。

## 七、简短实车采集与验收

1. 人工确认本轮位流及完整时序边界后再决定是否烧录，记录位流SHA。先保持停车，记录场地、ZERO、几何和5条JSON；确认完整scan id增长、gyro已校准且新鲜、无overrun。不可把“完整扫描”当作“走廊已知”。
2. 靶标放在雷达高度，量取相对轮轴O的XY。若沿激光原点的车身+X方向校ZERO，可放在O前600mm、右77mm处，预期从R距离约567mm，车体系约(600,-77)。默认90°不能替代这次实测。改变ZERO后重新建图，不擅改尺寸。
3. 空旷处人工执行短直线/90°，记录拒行时LCD原因、JSON及全局/局部图；若是UNKNOWN，定位首拒绝格并补实际观测，不能通过改FREE或扩SELF放行。
4. 人工放真实障碍于路径，确认快速停车，雷达仍扫描；移开后确认旧占据清除、新积分ID推动同一目标重规划。手动STOP后再移开障碍，旧任务不得恢复。扫描断开/慢扫描及gyro异常先在停车状态采集，不拿行驶中断线当首次测试。
5. 按[地图视口验收](地图视口坐标与验收_20261103.md)拍FIELD/CAR两张图并量尺。显示切换不应改变同位置的guard/规划物理结果。交回JSON、两张图、靶标实测XY/尺寸及位流SHA，才能判断是否仍有安装、自身回波或未观测空间问题。
