# 本轮直线导航、实时避障与人脸联调

本页优先于此前v20/v21说明。Pi更新按[香橙派v22人脸与小狗测试](香橙派v22人脸与小狗测试.md)；对应新FPGA位流须看本轮发布记录，17:41和19:12旧位流不含这里的全部修改。

R7已于21:36完成布线并生成位流；文件、资源与未完成的跨时钟/复位时序审核见[R7编译结果与更新](R7编译结果与更新_20261025.md)。现成R7候选位于发布目录；用户21:49另行启动的原工程编译以该轮最新日志为准。

## 已找到并修改的原因

1. 原航向误差使用有符号右移，负微小误差会向负无穷取整，正微小误差却为零，存在左右不对称与约3.28°纠偏死区。现在使用对称的符号/幅值计算，导航纠偏分辨率提高。
2. 原导航持续追逐终点剩余向量，临近终点时几毫米横向残差可能变成很大的方位变化。现在先对准，再沿固定路径方向行驶；横向修正限幅±5°。最终双轴进入5mm范围后，车身还需对齐路径方向至1°内才完成。若真实偏离或越过终点，允许重新接近，不伪造坐标。
3. 原128mm规划格以原点为边界，Y从0变−1mm会使检查范围跳动128mm。已改为以原点为中心。仍检查同样的车体转向圆，未知和占用格仍阻挡。
4. 原任务层把等待超时、传感器未就绪等情况一起显示NO ROUTE。现在分别显示START/GOAL BLOCKED、START/GOAL UNKNOWN、WAIT MAP SCANS、CHECK SENSORS等原因。
5. 用户提供的Pi实际运行v20和2100参数，未部署此前135°修改。v22统一升级服务，旧2100命令也明确迁移为实测角度表换算的135°；禁止低于90°。独立跟踪新增TRACK FACE，寻找默认FIND FACE。

速度环仍P30/I1/D0，位置环初值P0.125/I0/D0；XY导航不调用轮位置PID。基础速度30 COUNT/10ms，临近终点减速至最低1。转向上限12，按剩余角度减速并使用120ms陀螺仪速率预测制动。固定90°转向保留2°接受范围；导航入线0.5°、最终对齐1°。这里都是软件判定值，尚不等于已测得5mm绝对定位精度。

## 实时任务规则

- 收到GO后，优先复用近期有效地图，规划完成即执行，不增加ARM或固定等待。
- 先转向，再沿直线段前进；路径压缩到转折点，避免每128mm停车一次。
- 路程相近时按车体当前朝向优先右绕；右侧被占用或未知时选择其他已知可行路线。
- 雷达有效点可触发停车，不等待整圈地图或BFS完成；实际首次感知仍受雷达扫描周期影响。
- 受阻后保持雷达扫描、目标和任务。用采集编号追踪一圈完整的新扫描，确认它已写入地图后再重规划，不再无条件等待两圈加两次积分。
- 暂时无路时显示等待/原因；每次新的合格地图积分完成后再尝试，不靠定时器盲目起步。
- 障碍移开且新图确认可行后自动续走；手动STOP/接管/重设原点取消旧任务，旧规划结果不能重新启动。
- 硬件故障不会被算法自动清除；无效目标或运算故障保持停车，需人工处理。完整任务与原始电机故障门控分别验证，不用自动恢复去清除硬件故障。

C1典型10Hz，一圈约100ms；规划独立模型的保守上限约37ms（按50MHz计算）。这些是采样/计算预算，不是实车测得的障碍离开到恢复延时，也不能代替真实时序报告。

## VOFA与测量方法

保持原115200/8N1。逐条发，末尾换行，等ACK再发下一条：

```text
#401,9,0,0,0
#402,9,0,1,300
#403,9,0,2,0
#404,9,0,3,0
```

依次设原点/车头+X、X=300mm、Y=0mm、开始导航。1000mm测试只需改目标X，再发GO；目标始终是当前原点坐标，不是当前位置再前进1000mm。

```text
#405,9,0,7,0
#406,9,0,8,0
#407,9,0,4,0
```

依次为取消任务、独立人脸云台跟踪、寻找人脸。题5仍保留TRACK DOG；侧随仍是小狗在车左、车只前后移动。

量取位置时以两驱动轮中心的中点O比较地面标记。LCD的XY表示O；车头离O约232mm，偏转5°时车头本身就会横移约20mm，不能直接用车头位置代替O的Y。原编码器1469COUNT/圈来自10圈实测，当前没有依据把它改成其他猜测值。

先测300/1000mm空旷直线，记录O的位置、最终Y和YAW；再测试路线中段出现障碍、移开后自动续走、移动过程中手动STOP后保持停止。地面打滑、轮胎有效周长、陀螺仪偏置仍需真实测量，不能靠屏幕估计宣称高精度。

## 本轮开源参考

- [WPILib编码器与陀螺仪里程计](https://github.com/wpilibsuite/allwpilib/blob/v2026.2.2/wpimath/src/main/java/edu/wpi/first/math/kinematics/DifferentialDriveOdometry.java)：核对累计轮距、陀螺仪航向及重设位姿的关系。
- [ROS2差速里程计](https://github.com/ros-controls/ros2_controllers/blob/master/diff_drive_controller/src/odometry.cpp)：核对左右位移平均、采样时间和中点/圆弧积分。
- [Nav2规划错误分类](https://github.com/ros-navigation/navigation2/blob/main/nav2_navfn_planner/src/navfn_planner.cpp)、[射线清空与轮廓处理](https://github.com/ros-navigation/navigation2/blob/main/nav2_costmap_2d/plugins/obstacle_layer.cpp)：核对未知、占用、起终点与清空语义。
- [OpenCV官方YuNet](https://github.com/opencv/opencv_zoo/blob/main/models/face_detection_yunet/README.md)：核对人脸推理输入与解码，保留已在Pi上工作的现有模型和环境。

FPGA仍使用整数运算，没有把ROS或浮点EKF搬进芯片；不混入未经测量的轮距/编码器/陀螺仪权重。离线检查包含带轮差、编码器量化、60Hz陀螺仪与响应滞后的独立模型，尚未实际驱动车辆验证。
